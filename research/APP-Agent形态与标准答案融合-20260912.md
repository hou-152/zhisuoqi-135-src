> ## 结论：**B 档：可半自动化**
> Agent 生成材料、判据、判定；**人提供选择、裁决、复述**。

**这个判定的三个后果：**

1. **它排除了 A 档**——所以不需要一个"能自己决定下一步"的自主 agent。这与已拍板的 workflow 口径一致，属于**独立验证，不是复述**。
2. **它也排除了 C/D 档**——所以不需要"人来决定一切"的纯工具形态。管线里大部分是机器活。
3. **它给出了运行时的第一条硬需求**：必须存在一个**人能介入的门**，而且这个门的位置是固定的（在"看案例之前"）。这直接决定 §3 里"先自己选，再看案例"这条设计不是风格选择，是档位要求的。

### 1.5 三拆：可自动 / 人必须判断 / 需反馈回流

| 类别 | 具体是什么 |
|---|---|
| **可自动化** | 取真实材料（知乎搜索 / 问题回答 / 热榜）；生成 3 概念 + L1/L2/L3 梯度 + 费曼要点；生成决策场骨架；判费曼要点命中；算漏点；落盘；图上色 |
| **人必须判断** | ① 选哪条判据（尤其判级为"尚无统一答案"时）；② 复述本身（不可代劳）；③ **接受或推翻机器给的"已掌握"判定**；④ 在决策场里先自己选 |
| **需要反馈回流** | 漏点 → 倒回哪一站。**只做站内回流**（同一会话内可见）；跨会话那层已裁决不做，本轮不得复活 |

**第③条是三条里最便宜的、也是最值钱的**：`docs/交接-agent版-知所栖135.md` 已核实一个真实缺陷——`state.feyn='pass'` 加 `remediation='none'` **同一点同时驱动**绿点、结算条、待补清单、倒回按钮、下一轮起点，**没有第二来源**；而且只有 `hit:false` 才渲染倒回按钮 → **判过 pass 的概念永不回头，永无新证据推翻**。这不是 UI 问题，是"人的判断权"被机器单方面吃掉了。补一个「机器认为你已掌握 ·[不对]」按钮就能还回去。

核心机制：把数据的权威副本放在用户设备上，把"能否带走、能否离线、能否被别的工具读"

作者与机构：Martin Kleppmann（University of Cambridge）
            Adam Wiggins / Peter van Hardenberg / Mark McGranaghan（Ink & Switch）
原始出处：Onward! 2019（SPLASH 2019 track），2019-10-23，pp. 154–178
          DOI 10.1145/3359591.3359737 · 官方全文 https://www.inkandswitch.com/essay/local-first/
核实状态：已核实（Crossref 书目 + SPLASH 2019 程序页 + 作者官方全文页三方交叉；
          ACM DL 页返回 403 未打开，DOI 元数据以 Crossref 为准）
```

**七个理想（论文原文逐条，直接可用）**：

1. **No spinners: your work at your fingertips** —— 主副本在本地，读写本地磁盘，永不出现加载转圈
2. **Your work is not trapped on one device**
3. **The network is optional** —— 离线可读写；原文：「it is desirable for the software to run as a **locally installed executable** on your device, rather than a tab in a web browser」
4. **Seamless collaboration with your colleagues** —— 目标是「on par with the best cloud apps today, or better」，论文自承这是「one of the biggest challenges」
5. **The Long Now** —— 原文：「even after the company that produced the software is gone」
6. **Security and privacy by default**
7. **You retain ultimate ownership and control** —— 这里的 ownership 指「user agency, autonomy, and control over data」，不是知识产权，也不要求开源

> **理想 3 是本项目"要做 APP"的第一手依据。** 论文原句直接点出"本地安装的可执行程序，优于浏览器里的一个标签页"——这比项目里现有的说法（"学习的材料必须掌握在自己手里"）更精确，也更可引用。

**论文自承的局限（同样是一手原文，用来划边界）**：

- 「CRDTs accumulate a large change history, which creates performance problems.」—— 同步层的性能问题未解
- 「Network communication remains an unsolved problem.」……「nowhere near production-ready: NAT traversal, in particular, is unreliable」
- 「it is not yet advisable to replace a proven product like Firebase with an experimental project like Automerge in a production setting today.」
- 「Access permissions for documents beyond secret URLs remain an open research question.」
- 「But more work is needed to realize the local-first approach in practice.」

⇒ **这段直接支持"不自己写同步"这条既有的项目决策**：论文自己说同步网络层离生产可用还远。**但也要注意它同时削弱了"本地优先"的完美叙事**——路演时不能说"本地优先解决了所有问题"，只能说"它在单人、单机、无协作的场景下已经成立"。

**主理论的评分**：机制匹配 3 / 来源可靠 2 / 人物辨识度 2（Kleppmann 是《Designing Data-Intensive Applications》作者，剑桥副教授，均已在官网核实）/ 可用于表达 2 / 边界清楚 1 → **10 分**。

**辅助理论**：Anthropic 复杂度匹配（解释编排层，不解释壳体）；VanLehn 效果上限（解释为什么人必须在环）。
**纠偏方向**：local-first 论文自承的同步未解 + 本地优先**不是**成功的必要条件（见 §2.5 反例 Notion）。

### 2.3 理论如何解释当前问题

| 当前问题 | 理论解释 | 得出的判断 |
|---|---|---|
| 「不能只做网页」这个理由成立吗 | 本地优先要求数据的权威副本在用户设备上、可离线、可被别的工具读。浏览器 `localStorage` 三条全不满足（出不来、清缓存即失、只有本页能读） | **成立，但理由要换**——不是"网页做不到"，是"`localStorage` 不是文件系统" |
| 那 PWA 呢 | **文件这一关其实能过，进程和密钥这两关过不去。** ① 文件：`showOpenFilePicker` / `showDirectoryPicker` 在 Chrome/Edge 可用，但 **Firefox 与 Safari 全版本 `false`**（MDN BCD `version_added: false`；caniuse 显示 Safari 26.6/27/TP 与 Firefox 157 全为 n，全球可用率 26.55%）——即"浏览器能写用户磁盘"只在 Chromium 成立；替代品 OPFS 是 **origin 私有**、清站点数据即删，不是"用户自己的文件"。② 进程：知乎 CLI 是 `spawn` 出去的，浏览器不能起进程。③ 密钥：key 进页面就是公开的 | **PWA 不解决本项目的问题，而且挡住它的不是"文件"。** 路演时如果被问"为什么不做网页版"，正确答案是"**浏览器起不了子进程、也守不住 key**"，不是"网页存不了文件" |
| Tauri 到底行不行 | 官方前置页原文：**「Tauri is built with Rust and requires it for development.」** 当前稳定版 `tauri` crate **2.11.5**（2026-07-01）；官方唯一的体积数字是「a minimal Tauri app can be less than 600KB in size」 | 本机 `cargo`/`rustc` 均不存在 → **48h 内不成立**。600KB 的体积优势在这个项目里没有对应的收益 |
| 要不要引入 agent 框架 | Anthropic 原文：**"We suggest that developers start by using LLM APIs directly: many patterns can be implemented in a few lines of code."** 框架"create extra layers of abstraction that can obscure the underlying prompts and responses" | **不引入。** `serve-135.mjs` 用 95 行覆盖了整条管线，这条判断已被独立验证 |

### 2.4 运行时分层：三个候选各自站在哪一层

**这是本次研究最实质的产出。** 把"APP 的 Agent"拆开后，你列的候选**不在同一层**：

```
①  壳（打包层）            怎么变成一个"打开就能用"的东西
                          候选：浏览器标签页 / PWA / Electron / Tauri / DSH Desktop
②  本地服务层              谁调知乎、谁守 key、谁写文件
                          现在是 scripts/serve-135.mjs（95 行，3 个接口）
③  编排层（管线）          谁决定下一步
                          已定：135 固定顺序 workflow
④  执行引擎（可选）        谁来跑"一次 LLM 调用 + 一次工具调用"的循环
                          候选：自建 fetch / pi-agent-core / Claude Agent SDK / DSH SDK
⑤  协议层（可选）          宿主 ↔ 引擎怎么说话
                          候选：ACP（stdio JSON-RPC）/ MCP
```

**把候选放进去（全部一手核实，2026-09-12 当日 GitHub API 快照）：**

| 候选 | 实际是什么 | 属于哪一层 | star | 许可 | 关键限制 |
|---|---|---|---:|---|---|
| **Claude Code**（CLI 本体） | 开发时的编码 agent | **不在产品里** | — | — | — |
| **Claude Agent SDK** | "A library that runs the agent loop in your own process, in Python or TypeScript" | ④ 引擎 | Py 8,082 / TS 1,748 | Py MIT | 官方原文：「Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK.」→ **商业分发要自己带 key** |
| **PI**（`earendil-works/pi`） | "a minimal agent harness"；`pi-coding-agent` 是 CLI，**`pi-agent-core` 是可不带 bin 被 import 的库**，`pi-ai` 是统一 LLM API 库 | ④ 引擎（也可只当 CLI 用） | **104,144** | MIT | 0.85.1；官网原文 "Four modes: interactive, print/JSON, RPC, and SDK" |
| **DeepSeek Harness**（DSH） | DeepSeek 官方 agent harness，"everything-is-a-plugin"，基于 Cordis，**"There is no privileged core to patch"** | ① 壳 + ② 服务 + ④ 引擎（三层通吃） | **220,497** | MIT | **developer preview**，README 原文「**THERE WILL BE COMPATIBILITY-BREAKING CHANGES**」；SAFETY.md 原文「has not undergone a security audit and must not be treated as secure or production-ready」；插件以用户权限跑在宿主进程内、**不受插件级沙箱约束** |
| **Electron**（Tauri 的替代） | 桌面壳 | ① 壳 | — | **MIT** | 当前稳定 **v44.3.0**（2026-09-08）；只需 Node + npm，自带自己的 Node 运行时；官方**没有**应用体积数字，官方发布包实测 win32-x64 150.8MB / darwin-arm64 123.8MB |
| **Tauri v2** | 桌面壳 | ① 壳 | — | MIT/Apache-2.0 | 官方前置页原文「**Tauri is built with Rust and requires it for development.**」稳定版 2.11.5；**本机无 Rust/cargo** → 48h 内不成立 |

**本项目的运行时硬需求（从现有代码与约束反推，7 条）**：

1. 能读写**用户指定的本地文件夹**（不是浏览器沙箱）——local-first 的第一条
2. 能**spawn 子进程**（知乎 CLI 现在是 `spawn(join(ROOT,'scripts','zhihu'), …)`）——PWA 死在这里
3. 能持有 LLM key 且**不进前端**（现在靠 `.private/llm.env` + 服务端 env）
4. **离线可启动**（无网也能看已有内容）
5. 48h 内**不需要写打包代码**（时间预算）
6. 数据是**纯文本 + 开放格式**（可被 Anki / Obsidian / git 读）
7. 图上点的**位置永不变**（只变色），否则用户的空间记忆作废

### 2.5 历史同构案例

> 说明：本项目 `research/历史案例-结构同构-10案例.md` 已有 10 个已核实案例。本节**不重复它们**，只补"运行时/形态"这一层缺的案例。引用旧案例时标注出处等级。

**案例 1（最近成功案例）· Obsidian（2020– ）**

- **原始处境**：2020 年，双链笔记赛道由云端 SaaS 主导（Roam Research 以 $200M 估值拿了 $9M 种子轮）
- **真实约束**：两个滑铁卢大学毕业生、前作 Dynalist、明确拒绝 VC 融资、团队刻意保持极小
- **实际决策**：**本地 Markdown 文件夹** + 插件生态 + 个人使用免费；**明确拒绝融资**
- **后续结果**：商业上可持续。约 100 万用户（CEO 基于 GitHub 下载量的估算，2023-10，**公司不采集使用数据，故为估算非测量**）；团队约 12 人（Fast Company 2023-10-13）
- **证据**：`research/历史案例-结构同构-10案例.md` 案例 2，条目 93（Fast Company 一手采访）
- **证据状态**：已核实事实
- **与用户相同之处**：小团队、无融资、本地文件夹、方法论先于工具
- **与用户不同之处**：Obsidian 的用户是通用知识工作者、不是学习场景；它有十年积累，你有 3 天
- **类比有效性**：**中高**
- **能提取的机制**：**"本地文件 + 免费 + 插件"这个组合本身是获客机制**，不只是产品属性
- **不能照搬的部分**：插件生态需要时间，48h 内不可能有

> ⚠️ **一处需要修正的项目内数字**：`docs/交接-人类版-知所栖135.md` 与多份文档用的「**8 人 1 猫 / 2500 万美金 ARR / 零融资**」这组数字，项目内**能追到的一手来源是 Fast Company（2023-10-13）：约 12 人、约 100 万用户，且没有 ARR 数字**；2500 万 ARR 目前只见于中文二手转载。**路演时如果要引用，只引"零融资 + 小团队 + 本地 Markdown"，不要引具体 ARR 数字**，除非找到一手出处。

**案例 2（跨域重复样本）· Anki（2006– ）**

- **实际决策**：数据的权威副本是**本地 SQLite 文件**（`collection.anki2`）；`revlog`（复习日志）与 cards（派生卡片）**两层分开存**；同步是**可选的**附加服务
- **后续结果**：十余年持续维护，是间隔重复品类的实际标准
- **证据**：`research/历史案例-结构同构-10案例.md` 案例 4；`docs/交接-agent版-知所栖135.md` 引 16 产品调研（47 条来源）
- **证据状态**：已核实事实（项目内已核）
- **与用户相同之处**：**"不可变流水 + 派生状态"这一分层**，正是 §3.4 判断二要用的结构
- **类比有效性**：**高**（域不同，结构同）
- **不能照搬**：Anki 的同步最终还是要自建（AnkiWeb），说明"不写同步"是阶段性的，不是永久的

**案例 3（失败案例）· Roam Research（2019–2022 失速）**

- **原始处境**：以双链 + 图谱视图形成狂热社区，`$15/月`、**Web-first SaaS、闭源**
- **融资结构**：$9M 种子轮 / $200M 估值（2020-09，True Ventures、Lux Capital）；2021-04 通过 WeFunder 向老用户众筹，目标 $500K，1 小时超额，募得逾 $1.6M
- **实际决策**：云端权威副本 + 闭源 + 高定价
- **后续结果**：**商业动能层面失败**。2022-02 Dan Shipper《The Fall of Roam》记录的弃用机制是「这条笔记该放哪里？」的认知摩擦回归 + 迭代慢 + 移动端差
- **证据**：`research/历史案例-结构同构-10案例.md` 案例 2，条目 88–91
- **证据状态**：已核实事实（PitchBook / Business Insider / Dan Shipper 自述**非统计证据**）
- **与用户相同之处**：都面向"个人知识 + 学习方法论"
- **与用户不同之处**：Roam 拿到 $200M 估值 → 需要增长叙事；你没有融资压力
- **类比有效性**：**中**
- **能提取的机制**：**融资结构决定产品节奏**——高估值需要增长叙事，而"本地优先"讲不出增长故事
- **不能照搬**：「图谱视图无用」不成立——项目自己的研究写明"两者之间没有实证链条"

**案例 4（失败案例·最短命的那种）· Rewind.ai → Limitless → 被 Meta 收购（2022–2025）**

- **实际决策**：Mac 后台**持续捕获屏幕与音频**，云端 + 硬件 pendant
- **后续结果**：**带日期的终止事件**。2025-12-05 Meta 宣布收购；同日公告 Rewind Mac 应用自 **2025-12-19 起关闭全部屏幕与音频捕获**；巴西、中国、欧盟、以色列、韩国、土耳其、英国七地区服务熔断，这些用户须在 2025-12-19 前导出数据，**逾期账号与全部关联信息永久删除**
- **证据**：9to5Mac（2025-12-05）原文，见 `research/历史案例-结构同构-10案例.md` 案例 7-C
- **证据状态**：已核实事实
- **与用户相同之处**：都做"学习/记忆"类工具
- **与用户不同之处**：它是云端 + 硬件 + 持续捕获；你是本地 + 无捕获
- **类比有效性**：**中低**（结构差异大，但"结果"这一栏可比）
- **能提取的机制**：**云端权威副本 = 用户的记录寿命由公司的寿命决定**。从宣布到清库只给 14 天
- **不能照搬**：它的失败主因是"默认开启的系统级捕获"引发信任崩塌，不是"云端"本身

**案例 5（反例／边界案例）· Notion（纯云端仍然成功）**

- **实际决策**：**从不做本地优先**；AI 定位是"augment their thinking"（增强而非替代结构）
- **后续结果**：官方 2026-01-26 披露「2025 年底超过 50% 的 ARR 来自 AI-enabled 客户」；CNBC（2025-09-18）年化收入突破 $500M、用户超 1 亿
- **证据**：`research/历史案例-结构同构-10案例.md` 案例 7-B，条目 421–422（官方博客 + CNBC，均已 curl 核实原文）
- **证据状态**：已核实事实
- **与用户相同之处**：都在做"帮人思考"的工具
- **与用户不同之处**：Notion 是企业协作套件，网络效应与团队协作是它的护城河；你的产品没有网络效应
- **类比有效性**：**中**（作为反例有效）
- **能提取的机制**：**本地优先不是成功的必要条件**；当产品价值来自协作与网络效应时，云端是正解
- **不能照搬**：Notion 的 AI 收入占比是企业协作场景的数字，不能迁移到个人学习工具

**案例 6（边界案例·直接同构）· DeepSeek Harness 自己的桌面端（2026）**

- **实际处境**：一个 agent harness 要在本地跑，需要"本地服务 + 浏览器 UI + 可扩展前端"
- **实际决策**：
  - 默认形态：`npx @deepseek-ai/dsh web` → 本地服务在 `127.0.0.1:3080`，UI 在浏览器
  - **官方 Electron 桌面壳写在仓库里**：`apps/desktop` 原文——「The desktop application is an Electron shell around the dsh Web UI. **It opens no listening port**」；打包命令 `pnpm run package:desktop`；规则是「Electron and `@deepseek-ai/dsh` always have the same exact version」
  - **但官方没有分发安装包**：最新 release `dsh-v0.1.5-rc.2` 的 assets 只有 GitHub 自动源码 zip，无 `.dmg`/`.exe`；官网只给 `npx` 与源码两条路径
  - 第三方补上了这一格：`anywhere-labs/dsh-desktop`（25,702★，MIT，Windows/macOS 一键安装包），README 自述「独立的社区开源项目，与深度求索不存在隶属、合作、授权或背书关系」
- **证据状态**：已核实事实（仓库原文 + GitHub API + releases assets 实测）
- **与用户相同之处**：**结构完全相同**——本地服务 + 浏览器 UI + 想变桌面
- **与用户不同之处**：它有 220k star 和一个插件生态，你有一个 47KB 的单文件 HTML
- **类比有效性**：**高（形态层）**
- **能提取的机制（本节最重要的一条）**：**"本地服务 + 浏览器 UI"不是过渡形态，它是这类产品的稳态；桌面壳是可选的外层，且通常由社区而不是核心团队补上**
- **不能照搬**：DSH 处在 developer preview、无兼容承诺、插件不受沙箱约束；**不能把产品押在它上面**

### 2.7 反复出现的机制

| 重复机制 | 出现在哪些案例 | 可能的因果解释 | 成立条件 | 失败边界 | 证据强度 |

| **本地服务 + 浏览器 UI 是稳态，不是过渡** | **六个独立样本**：① DSH（官方默认形态 `dsh web` → `127.0.0.1:3080`；官方 Electron 壳与之严格同版本）② Logseq（官方文档 Local Http server：`http://127.0.0.1:12315/`，`POST /api`，**支持 CORS 供另一个网页调用**）③ Anki（**官方自带**同步服务器，2.1.57+ 的 `--syncserver`）④ Obsidian（社区插件 Local REST API，`https://127.0.0.1:27124/`）⑤ Jupyter（本地后端 + REST，浏览器前端；后端是 Python）⑥ 本项目自己的 `serve-135.mjs` | 壳只解决"怎么启动"；一旦启动方式是本地服务，浏览器就是零成本的 UI 运行时，多写一层壳只增加构建面 | 单机、单人、无协作 | 需要系统集成（文件关联、分享菜单、应用商店分发）时 | **强**（六独立样本） |

### 2.8 标准答案判断

**结论等级：条件性答案**（三个高可信同构样本 + 一个反例 + 已被检验的协议与许可事实；不是实验室共识）

> 当满足以下三个条件时——
> ① 用户的产出物是**长期复用的个人资产**（不是一次性内容）；
> ② 用户对**数据主权**有明确要求，且愿意为此接受"没有跨设备同步"；
> ③ 团队小、**没有同步基建预算**，且产品价值**不来自协作或网络效应**——
>
> 历史上反复有效的做法是：
> **把数据以开放纯文本格式落在用户可访问的磁盘上；把"本地服务 + 浏览器界面"当成稳态而不是过渡；把桌面壳推迟到有真实用户提出需求之后，并且优先用 Electron（而不是需要额外工具链的方案）。**
>
> **因果解释**：这三条约束下，服务端与安装器都是纯成本，而开放格式让你可以借用别人已经写好的工具（Anki 的复习、Obsidian 的编辑、git 的版本）。壳不产生用户价值，只改变启动方式，所以它是最后一件事而不是第一件事。
>
> **失效边界**：① 产品价值来自多人协作、实时同步或网络效应时（Notion 反例）；② 分发必须走应用商店、或需要系统级集成（文件关联、分享菜单）时；③ 团队有能力承担同步基建、且同步本身是付费点时（Obsidian Sync 就是这个模式）。

**对「用什么 Agent」的直接回答**

1. **没有一个候选是"APP 的运行时"。** Claude Code 是开发工具（不在产品里）；PI 与 Claude Agent SDK 是**可嵌入的引擎库**（第 ④ 层）；DSH 是**本地宿主平台**（第 ①②④ 层通吃）；Electron/Tauri 是**壳**（第 ① 层）。它们不在同一层，不能同台比。
2. **48h 内一层都不用加。** 第 ①②③ 层已经齐了：`serve-135.mjs`（95 行）+ 单文件 HTML + 固定管线。按 Anthropic 的原文，这正是"start by using LLM APIs directly"的字面做法。**本轮的唯一动作是把 §3 的契约接上去，不是换运行时。**
3. **APP 路线写进产品说明，壳选 Electron。** 理由有三条，按强度排序：① 官方 DSH 桌面端自己就是 **Electron**（`apps/desktop` 原文）；② 本机**无 Rust/cargo**，Tauri 在 48h 内不成立；③ Electron 只需要 Node，而 Node 已经在了。
4. **如果将来真要一个 agent 引擎，首选 `pi-agent-core`**——它是**库**（无不带 bin 的 CLI 依赖）、MIT、TypeScript、与你现有 Node 代码同语言，且它的设计口号「Adapt Pi to your workflows, not the other way around」与"方法论写死编排层"是同一个判断。**Claude Agent SDK 次之**，因为它带一条商业限制（未获批准不得为第三方产品提供 claude.ai 登录或额度）。**DSH 不作为产品依赖**：developer preview + 明文会有破坏性变更 + 未过安全审计 + 插件不受沙箱约束——这四条里任何一条都足以让"把学习产品押在上面"不成立；它现在的正确定位是**你现在正在用的开发环境**。
5. **ACP 只在一种情况下才需要**：如果将来壳与引擎要分家（比如壳是 Electron、引擎是可替换的子进程）。现在不需要——因为编排层已经定成固定 workflow，没有"可替换的 agent"这个东西。

### 3.4 三个设计判断

**判断一：知乎在「生成时」调，不在「渲染时」调。**

三条理由：
- **配额**：直答实测只剩 93 次/天（`./scripts/zhihu quota` 本机实测，2026-09-12）。一次完整决策场 = 1 次直答 + ≥5 次搜索。15 个决策场就是 15 次直答 + 75 次搜索。**搜索够用，直答是稀缺品。**
- **延迟**：直答 18.4 秒。用户点开"3 决策"时等 18 秒 = 演示事故。
- **可审阅**：生成时人能看见案例是什么；渲染时人看不见，等于让一个会编作者的模型直接对着评委说话。

代价：案例是快照，不是实时。**页面上必须标日期。** 现在 `SEARCH_META.date = '2026-09-11'` 这个做法是**对的**，保留；只是它现在标的是"离线手工"，改成"本次生成于 {日期}"。

**判断二：原始检索与蒸馏产物分离落盘（`sources/` vs `wiki/`）。**

- `sources/zhihu-*.md`：**不可变**。原样保存 `zhihu_search` 的返回（Title / AuthorName / Url / VoteUpCount / AuthorityLevel / 抓取时间）。只有人能往里写。
- `wiki/decisions/*.md`：**派生**。LLM 蒸馏出来的骨架。可以随时用 `sources/` 重建。

**为什么必须分（这条有独立的历史支持，不是抄形态）**：直答会编作者名。如果只存蒸馏结果，编造的名字就永久留在库里、无法回查。两个独立产品用了同一条原则——`llm_wiki` 的 Raw Sources / Wiki 分层，和 **Anki 的 `revlog`（不可变复习日志）与 cards（派生）分层**。两处同构 → 这是重复机制，不是风格。

**判断三：人必须在「选」之前介入，机器只在「选」之后补证据。**

这条是已裁决口径「知乎不进判断层」的落地（见 `docs/知乎黑客松-赛制要求与项目差距.md`），也是 §1.4 档位判断（B 档）的直接要求。
UI 上就是决策场现在的做法：**先自己选，再看案例**。这条必须保住——它是"半自动化"和"全自动化"的分界线。

### 3.5 失败退化链（每一跳都必须报警）

```
直答失败
 └→ 用 4 类查询的搜索结果直接组案例（无骨架）
     └→ 搜索也失败
         └→ 读 sources/ 里最近一次成功的快照，页面标「快照 · {日期}」
             └→ 没有快照
                 └→ 退到 2026-09-11 硬编码 CASE_DATA，页面标「离线样张 · 2026-09-11」
                     └→ 全挂
                         └→ 决策场只出「条件 → 路线」表，不给案例，
                            明确写「本次无外部案例」
```

**每一跳都要在页面上显示当前处于哪一跳。** 依据是项目自己的一条规则（「任何降级/回退/兜底路径必须报警」），起因是实测踩过 `Data.Items` vs `data.items` 的静默降级——那次差点用解析 bug 替团队做了架构决策。

**注意**：现在 `liveEvidence()` 的失败路径是**静默**落到 `REAL_SOURCES` 快照（第 267 行）。这条要改，否则同一个坑会再踩一次。

### 3.7 跟交互式学习的三个接点

**接点一：标准答案的「判级」是交互式学习的分支器（这条已在 09-12 凌晨产出，尚未实现）**

`dbs-standard-answer` 的 SKILL.md Step 7 本来就有三档：成熟共识 / 条件性答案 / **尚无统一答案**。但现在的实现把第三档**当失败等级用**。倒推之后它应该是平级分支：

| 判级结果 | 能教什么 | 学习序列 | 终点 |
|---|---|---|---|
| 成熟共识 | 可教 | 机制 → 条件 → 边界 | 能复述机制、能说出失效条件 |
| 条件性答案 | 教判据 | 条件识别 → 判据 → 你的情形落在哪 | 能说出自己落在哪个条件里 |
| **尚无统一答案** | 教不了答案 | 判据 → 代价 → 只有你能回答的问题 | 敢选，且知道怎么反悔 |

**135 现在缺的正是这个判级步骤。** 1 阅读器默认所有问题都有东西可教——所以「我要不要去找工作」进去，出来一篇行动方案（这是实测出来的，不是推测）。**判级接上，`dbs-learning-beta` 才有位置**：它不是"处理无标准答案的补丁"，是判级的第三个出口。

**接点二：决策场的「先自己选」本身就是提取练习**

理论依据在项目里已有：Yang 等（2021）提问效应 g=0.499。但现在 `CASE_DATA` **只标了 2/3 案例的污染**，且藏在讲评里。应升级为**每条案例都标**——哪条是成功案例、哪条是失败案例、哪条是反例，这是 `dbs-standard-answer` 的四类证据角色（最近成功 / 跨域重复 / 失败 / 反例），直接显示出来比藏在文字里有用。

**接点三：费曼的漏点要能真的倒回（现在倒不回去）**

两个已核实的代码缺陷：
- `saveCheckpoint` 只存 `{at, state, labTries}` → 刷新后待补清单只剩 `pending`，**不知漏哪条**，「漏哪倒回哪」降级成「漏了哪个概念」。
- 只有 `hit:false` 才渲染倒回按钮 → 判过 pass 的概念永不回头。

⇒ **这一层不修，融合是纸面的。** 修法很便宜（约 30 行），见 §4。

## 综合结论

**理论证据与历史证据各自支持了什么**

| | 支持 | 边界 |
|---|---|---|
| 理论（local-first） | 「本地安装的可执行程序优于浏览器里一个标签页」（理想 3 原文）；「公司消失后仍能用」（理想 5）；ownership 指用户对自己数据的支配权（理想 7） | 论文自承同步层「nowhere near production-ready」；权限、schema 迁移、多版本协作均未解 |
| 理论（Anthropic） | 步骤可预知就用 workflow；「start by using LLM APIs directly」；框架抽象层遮蔽提示词 | 不涉及桌面/网页形态 |
| 理论（VanLehn） | 自动化效果有天花板 → 人必须在环 → 支持 B 档判断 | 不涉及运行时 |
| 历史（6 案例） | 本地服务 + 浏览器 UI 是**六个独立样本**的稳态；桌面壳常由社区补上；开放纯文本格式借用生态；云端副本=记录寿命绑公司寿命 | Rewind/Notion 在阶段与结构维度上相似度低，只能当边界；Obsidian 的十年积累不可复制 |

**两边共同指向的三条**（这才是有重复机制支撑的部分）

1. **数据落在用户自己的磁盘上、用开放格式。** 理论给理由（理想 3/5/7），历史给六个执行样本。
2. **本地服务 + 浏览器 UI 不做成"过渡形态"。** 六个独立样本说明它不是权宜之计，而是这类产品的稳态；壳是外层。
3. **机器只做发现，判断留给人。** 理论给边界（VanLehn 的效果上限 + 你不该替用户收敛），本轮实测给机制（生成不稳定、检索稳定）。

**仍然存在的边界**

- 明天开始（09-13 10:00）的 48h 是"一次性用户"场景，跨会话机制全是死代码——这一条不因本文件而改变。
- 本文件没有解决**同步**。它明确建议**不写同步**，依据是论文自承网络层未生产可用。
- 本文件的运行时结论**没有真实用户反馈支撑**，只由"48h 内能否演示"这一条检验标准约束。
