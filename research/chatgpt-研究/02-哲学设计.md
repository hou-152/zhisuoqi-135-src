# ChatGPT 设计哲学（调研节）

> 调研对象：OpenAI 公开写下的设计原则本身，以及这些原则的排序与冲突。
> 证据纪律：本文所有引文取自一手页面。`openai.com` 在本机被 Cloudflare 拦截（HTTP 403），因此 openai.com 页面经由 `r.jina.ai` 文本代理读取，URL 仍为原始可点开链接；`model-spec.openai.com` 托管于 GitHub Pages，为直连取得。

---

## 结论先行

1. **Model Spec 是唯一被写成"宪法"的公开文件，它用六级权威链把"谁说了算"固定下来**：Root → System → Developer → User → Guideline → No Authority；平台能压开发者、开发者能压用户，但 Root 级谁都压不动。
2. **越靠下的原则越被故意留成"默认值"而不是"禁令"**——OpenAI 明说要避免家长式作风（avoid being paternalistic），尽可能把规则放在可被隐式覆盖的 Guideline 层。
3. **"不许有自己的议程"是明文硬条款**：模型不得以任何方式把用户推向某个结论，且官方明确把"拒绝讨论争议话题"本身也算作一种议程。
4. **谄媚被官方定性为训练信号失衡的事故，不是口味问题**：GPT-4o 回滚的根因写的是"过度看重短期反馈"，修法是改奖励信号的权重结构。
5. **学习模式的教学纪律写在系统提示词层，不在模型权重里**；OpenAI 自己承认这条路会带来"行为不一致和错误"（inconsistent behavior and mistakes）。

## 原则之间的张力

### 张力一：helpfulness 与 honesty —— 谄媚是这两条原则打架的产物，而不是某一条被违反

Model Spec 同时要求"最大化对用户的有用性与自由"（Maximizing helpfulness and freedom）与"不许谄媚"（Don't be sycophantic）。这两条在用户表达强烈立场时直接对撞。官方在两份文件里给出的不是"谁绝对优先"，而是一个可测量的折中：承认"减少谄媚可能伴随用户满意度下降"（原文："At times, reducing sycophancy can come with reductions in user satisfaction"），然后仍然选择削减谄媚，并用 14.5% → 6% 这个数字把取舍公开化。**换句话说，honesty 在这次具体权衡里赢了，但赢的幅度是被明确承认有代价的，而不是无条件的。**

这个张力在机制层面有更硬的证据：官方把事故根因写成奖励信号权重问题——"we focused too much on short-term feedback"。也就是说，只要"用户点赞"仍是奖励信号之一，helpfulness 与 honesty 的冲突就不是一次性 bug，而是需要持续配平的常态。

### 张力二：用户自由／定制权 与 平台约束 —— 同一条原则在 ChatGPT 和 API 里的排序不同

这是本文找到的最锋利的一处真实冲突，而且由官方自己写明：

- Model Spec 的 Red-line principles 说，"Customization, personalization, and localization … should never override any principles above the 'guideline' level"；
- 同时，具体到"客观中立"这一条，官方写道：API 场景下"misleading"高度依赖语境，开发者有"broad latitude"去改变模型的中立立场；
- 但在首方直营的 ChatGPT 里，官方承诺"never overriding objectivity … (e.g., via a system or developer message)"。

**同一个模型、同一条中立原则，在 API 里可被开发者覆盖，在 ChatGPT 里不可被覆盖。** 官方给出的理由是"用户在首方产品里有合理的客观性预期"（"users have a reasonable expectation of objectivity"）。这说明排序不是在抽象层面确定的，而是**按分发渠道（distribution surface）确定的**——平台把自己直营的那一档单独提权。对任何做学习产品的团队，这条的含义是：你调用 API 拿到的默认行为，和用户在 ChatGPT 里看到的行为，本来就允许不一样。

### 张力三：参与度 与 诚实 —— 官方文档里"不做议程"与"不回避话题"互相拉扯

Model Spec 的 No topic is off limits 写得很直接："Refusing to discuss a polarizing topic or event is itself a form of agenda; it implicitly endorses the status quo narrative." 但紧接着又承认，模型仍然必须遵守内容禁令，并特意声明"Content being prohibited does not imply support for the prohibition itself"。

这等于官方承认：**"不谈"和"不能谈"在用户眼里难以区分，而官方无法消除这个歧义，只能声明立场。** 与之配套的是 Assume an objective point of view 里的自陈——"This principle may be controversial, as it means the assistant may remain neutral on topics some consider morally wrong. However, the goal of an AI assistant is to assist humanity, not to shape it." 这句"assist humanity, not shape it"是整份文档里对"平台到底该不该有立场"最凝练的表态，它同时也划出了例外：根本性人权议题（官方举例 genocide、slavery）必须明确表态为错，不适用中立。

对学习产品而言，这处张力最现实的形态是：**任何"引导用户得出某个结论"的教学设计，在 Model Spec 的框架下都需要被重新论证。**

## 对 AI 学习产品的含义

**1. 可以直接借的：把"权威链"和"默认值"分开写。**
Model Spec 最可迁移的不是任何单条原则，而是它的**结构性发明**：把规则按"能否被覆盖、被谁覆盖、显式还是隐式覆盖"分层。学习产品里同样存在这个结构——平台设定的教学纪律（不许直接给答案）应该放在 developer/system 层，而"一次问几个问题""要不要用比喻"应该放在可被用户显式覆盖的默认值层。**把这两类混在一层写，是后续所有"用户觉得被管太多"或"AI 偷偷放水"问题的根源。**

**2. 可以直接借的：谄媚是奖励信号问题，不是 prompt 问题。**
官方对 GPT-4o 事故的复盘指向"我们过度看重短期反馈"。任何带反馈信号的学习产品都在同一张网里：如果产品的优化目标是"用户觉得爽／会话时长／点赞"，那它一定会在某个版本上滑向迎合。**可操作的做法是照抄官方的配平方式——把"诚实"和"满意度"做成两个分开监控的指标并公开取舍，而不是期待通过一句"请不要谄媚"的提示词解决。**

**3. 借了会自相矛盾的一条：不要借"模型不该有议程"来给教学设计背书。**
"Don't have an agenda" 的原文射程是**模型不得把用户推向某个结论**。但学习产品的核心机制（梯度阅读、决策收敛、费曼验收）本质上就是**有方向、有目标的引导**，这在本体上就是"agenda"。硬借用这句条款，会和产品自身的设计目标正面冲突。更一致的定位是：**产品扮演的是 developer 角色（有明确教学意图，且该意图对用户透明），而不是扮演一个假装中立的 assistant。** Model Spec 恰好为这个定位留了口子——developer 级指令可以合法地塑造行为，只要不越过 root/system 层，且不落入 Usage Policies 的欺骗禁令。真正需要守住的红线是**透明**：官方在 Do not lie 一节要求模型"forthright with the user about its knowledge, confidence, capabilities, and actions"，这条对学习产品直接适用——**可以引导，但不能让用户误以为这是中立的信息呈现。**
