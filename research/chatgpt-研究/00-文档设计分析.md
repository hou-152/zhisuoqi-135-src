## 0. 一句话

这两份文档的价值不在结论，在于它们示范了一种**把「研究」做成可验收交付物**的文体：每问一节、四段合同、一手/二手标注、阴性结果单列、自评可信度、主动指出提问者的前提错误。它的意识形态是**反首创、反因果跳跃、把裁决权交回人**；它的系统性盲区是**只承认公开可检索的世界，且单次运行不等于穷尽**——而后者正好解释了为什么两轮给出了两个不同的「先例」。

### 1.2 功能层的缺陷（同样可核对）

1. **引用标记泄漏进正文**：A 通篇残留 `filecite`／`cite` 标记（如 A:5、10、43），说明内部引用系统和最终输出格式没有对齐，读者看到的是一份「渲染失败的 doc」。
2. **没有文档头**：两份都没有把「检索截止时间／版本／运行次数」放在页首，时间边界散在正文里（B:13、52、295）。
3. **两轮之间不互相引用**：A 与 B 是两次独立运行，同一问题给出不同答案（见 §3 盲点 1），但文档形式上不提示「还有另一次运行」。
4. **长行、无锚点**：A 只有 199 行却有 39 KB（超长行），不便引用与定位；两份都没有目录。
5. **「对我们的含义」与证据同节同权重**：结构上建议与事实并列，容易让读者把推断层当证据层读（这是本分析最在意的一条，见 §5.1）。

## 3. 意识形态：它默认了什么

> 本节的判断分两类：**文内可证**（把它的措辞当证据）与**本文推断**（对成因的解释，标「推断」）。

| 预设 | 文内证据 | 类型 |
|---|---|---|
| **服务对象是「要交东西的团队」**：一切输出都指向「改路演／改产品／48 小时内做什么」 | A:39、70、90、125、149–171；B:15–19、305–315 | 文内可证 |
| **反首创叙事**：把「我们是第一个」一律降级 | A:10、70、109–111（出处刀／新颖性刀／同构刀）；B:231（「下一题早就有人会选」） | 文内可证 |
| **免责式严谨**：宁可说「未找到」「不能报效应量」，也不给一个可被抓住的数字 | A:11、84、188；B:131、156、297 | 文内可证 |
| **裁决权交回人**：所有建议停在使用者拍板前一步，不替你做策略 | A:39（「交给主办方确认」）；B:44–48（「交 DDR 或主办方通知」） | 文内可证 |
| **风险偏好偏低**：优先「不被打穿」而不是「讲得更响」 | A:198（减少三个方向被问穿的风险）；B:233 | 文内可证 |
| **世界观：创新是渐进的、可被检索的**——没有无人的格子，只有更窄的缝 | B:213（「这是目前更窄、更可守的叙事」） | 本文推断 |
| **成因：对齐训练让它避免断言、避免贬损具体公司、避免价值判断** | 对厂商一律「其宣传与机制事实分开看」（A:115）；语气中性 | 本文推断，未核实 |

### 三个系统性盲区（对我们的使用方式有直接影响）

1. **单次运行 ≠ 穷尽**：同一个问题，A 找到的是 Inno Agent（A:60），B 找到的是 Tutor MCP（B:56）；两份都说「未找到更完整的」。**结论：任何「没有先例」都不能只凭一次运行写下。**
2. **只承认公开可检索的世界**：B 的检索协议（B:81–102）全是英文关键词 + GitHub／arXiv／产品官网；中文私有实践、线下经验、小圈子文档天生缺席。它给出的「竞争面」是一张英文世界的图。
3. **时间与语料偏差**：默认窗口是近 12–24 个月（B:77–79），较早但仍有效的证据会被自然冷落；对「人怎么想」（评委偏好、团队政治）只能推测，无法检索。

## 4. 见贤思齐：可直接搬进知所栖的 6 件

1. **每节四段合同**（结论 → 证据 → 可信度 → 对我们的含义）：`docs/` 与交接件照此改写，读者永远知道哪句能引、哪句只是建议。
2. **独立的「没找到」一节**：写清检索路径、关键词、时间窗。项目的「缺口驱动的反向提问零先例」这句话就应该改造成这种形式。
3. **阴性结果与「不存在」分开表述**：统一改成「公开可查范围内检索过，未找到」。
4. **一行来源标签 + 原文短引**：沿用项目已有的标注习惯，但补上「一手／二手／未核实」的显式字段。
5. **主动写提问者的前提错误**：知所栖自己产出的研究文档（如 `docs/AI内参-落地依据与形态收敛.md`）应加一节「本次推翻/修正了哪些旧前提」。
6. **可替换句**：审计类交付（本次外部研究吸收、理论核实）一律以「现在这么写 → 改成这么写」收尾，而不是以「建议加强」收尾。

**对产品本身**：知所栖的费曼验收判定报告，最合适的形态就是这份文档的四段合同——结论（讲到了什么）／证据（对应原文哪一段）／可信度（判定依据是否充分）／下一步（倒回哪个模块）。**文档文体即产品文体。**

## 5. 见不贤而内自省：我们自己正在犯的 5 件

1. **建议混进证据层**：`docs/135-llm_wiki-融合形态方案.md` 的「结论」与「对我们的含义」同段；对照这份文档的四段分离，我们的读者同样难以区分事实与主张。
2. **一次检索就写结论**：本项目「系统检测缺口后自动提问无任何直接研究」「零先例」正是单次本地检索的产物，而外部一次联网就找到 Inno Agent 与 Tutor MCP 两个反例。**我们把「我没找到」写成了「没有」。**
3. **未核实项容易被后续材料抬升**：主办方规则从 09-06 挂到现在（`docs/从-Demo-倒推讨论.md`、`WHERE-TO-START.md`），中间几轮文档都提到它，但没有一处像这两份文档那样把它做成独立清单。
4. **没有版本头**：项目多数文档只有内容没有「检索截止／数据快照时间」页首行，star 数、日期这类会漂移的事实容易被后来的人当现值。
5. **中文语料优势没被写成方法**：我们有知乎 CLI 与 AI 内参 API（中文一手语料），这在英文检索里是稀缺资源，但没有任何文档把它写成可复用的检索路径。
