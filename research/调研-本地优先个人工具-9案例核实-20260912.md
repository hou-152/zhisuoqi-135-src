**revlog 与 cards 的关系**
- 官方手册原文：“The most important table for statistics is the **"revlog"** table, which stores an entry for each review that you conduct.” / “**cid** — The ID of the card that was reviewed. **You can look up this value in the id field of the "cards" table**” / “**id** — The time at which the review was conducted…” / “**ease** — Which button you pressed at the end of the review (1 for Again, 4 for Easy)” / “**time** — The amount of time (in milliseconds) you spent on the question and answer sides”
  URL：https://docs.ankiweb.net/stats.html
- 建表语句（源码）：`CREATE TABLE revlog (id, cid, usn, ease, ivl, lastIvl, factor, time, type)` + `CREATE INDEX ix_revlog_cid ON revlog (cid);`
  URL：https://raw.githubusercontent.com/ankitects/anki/main/rslib/src/storage/schema11.sql
- 结构体注释：`/// Amount of milliseconds taken to answer the card.`、`RevlogReviewKind { Learning=0, Review=1, Relearning=2, Filtered=3, Manual=4, Rescheduled=5 }`
  URL：https://raw.githubusercontent.com/ankitects/anki/main/rslib/src/revlog/mod.rs
- 关系结论：`revlog.cid → cards.id`；一次复习写一行，卡片可被改（手册明说“note that the card could have changed between when the revlog entry was recorded and when you are looking it up”）。

**从 Firefox 扩展迁到独立应用：时间与原因**
- 官方博客 “A Unified Zotero Experience”，署名 **Dan Stillman，on Monday, July 10th, 2017 at 7:50 pm**（本人 2026-09-12 复核抓到原文与日期）：
  - “Since the introduction of **Zotero Standalone in 2011**, Zotero users have had two versions to choose from…”
  - “Starting with the release of **Zotero 5.0**, Zotero for Firefox and Zotero Standalone have been replaced by a **single standalone application for users of all browsers**.”
  - 原因原文：“The reason for this change is technical, and, unfortunately, out of our control: **Mozilla is discontinuing the powerful extension framework on which Zotero for Firefox is based in favor of WebExtensions**, a new framework based on the Chrome extension model.” / “The trade-off is that it's **no longer possible to create an extension like Zotero for Firefox** that affects the browser in more profound ways… or that uses low-level features of Firefox to **manage a database, access the filesystem, or run local programs**.”
  URL：https://www.zotero.org/blog/a-unified-zotero-experience/
- 同日 5.0 发布帖：“Zotero 5.0 now runs **only as a standalone application**, and a new Zotero Connector for Firefox replaces the full Firefox extension.” URL：https://www.zotero.org/blog/zotero-5-0/
- 后续 FAQ 帖（2017-11-03）原文：“**it's no longer technically possible to create a tool like Zotero for Firefox within the browser.**” / “Zotero 5.0 will automatically detect and upgrade your existing data.”
  URL：https://www.zotero.org/blog/2017/11/
- → **2017 年 7 月 10 日**（Zotero 5.0）完成从 Firefox 扩展迁移到独立应用；原因是 Mozilla 弃用旧扩展框架（XUL）转 WebExtensions，浏览器内已无法再访问数据库与文件系统。

## 三条我在多个案例里重复看到的机制（只描述，不下结论）

1. **「本地明文文件」与「能带走」被官方当成同一件事写进对外文档，而不是分成两条。** Obsidian 的 License 页写「数据在本地 + 内容归你 + 我们不要权利」；Logseq 2022 融资公告写 “local-first… Users always own their information”；Anki 的手册直接教用户 `sqlite3 collection.anki2 .dump`；Zotero 建议整目录拷贝（“the entire folder, including zotero.sqlite and storage”）。反过来，一旦真源不在用户磁盘上或不是通用格式，「带走」立刻变成一条需要单独立项、单独写文档、甚至单独承诺的功能：Logseq DB 版要新做 Markdown Mirror，且「Export DB graph to Markdown」到 2026-08 仍在 roadmap 上；flomo 只给 HTML 一条路且 API 只写不读；Evernote 只给私有 `.enex`，且官方文档明写「Web 端不能导出」，第三方（Simon Willison）指出导出的笔记**没有唯一 ID**、笔记本结构也不在文件里；Roam 的导出说明要在别人家的官方文档（Obsidian 帮助站）里才看得到，自己的需登录。**同一件事在两种架构下的成本差，就体现在「有没有一份导出文档」上。**

2. **同一批产品里，「付费点挂在哪里」高度一致：都挂在「跨设备同步 / 托管 / 协作 / 存储配额」这条云通路上，而不挂在本地功能上。** Obsidian（Sync $4 / Publish $8，商用授权官方明说不强制）、Zotero（存储配额 $20–120/年，官方原文「with or without Zotero Storage」本地都无限存）、Logseq（Open Collective $5/$15 换 Sync beta，官方 FAQ 承诺 app 本体永久开源）、Readwise（$5.59/$9.99 订每日回顾与导出）、flomo（99 元/年 PRO，免费 500M / PRO 20G 的云存储配额）、Evernote（Free 50 条 / Starter $99 年 / Advanced $249.99 年，全部按云用量分层）。抓到的唯一例外是 **Anki**：AnkiWeb 同步免费且限 100MB/250MB，官方付费点在移动端买断（价格未核实）。另一处反向证据是：一旦出现把**本地**功能划进付费档的迹象，官方论坛立刻出现公开质疑（Logseq Pro 帖，2025-04，版主随后澄清 Pro 只含托管服务）——**这个赛道的用户对「为数据通路付费」和「为本地功能付费」的容忍度明显不同。**

3. **「用户抱怨」在这个赛道里几乎从不出现在媒体报道中，只出现在官方论坛/社区帖里；而「官方承诺」则只出现在官方文档里——两边很少交叉。** Logseq 的用户不满在官方论坛（主题 54 帖 / 39,834 浏览）与 V2EX（8,695 浏览）里，官方回应是版主在同一个帖子里说「不知道什么时候能稳定」；Evernote 的「导出困难 / 锁定」批评全部在它自家论坛（2022-11、2026-06 两帖）与科技博客（Simon Willison 2020、XDA 2025）里，而官方文档只写能力与限制、不写锁定；Roam 的衰退证据全部来自 Outliner Software 论坛帖与 GitHub 元数据（`Roam-Research/issues` 归档于 2021-03-20），但同 org 在 2026-09 仍在提交官方 MCP/CLI 仓库——**没有一家出现权威第三方（TechCrunch / The Verge 级）的衰退或动荡报道**，唯一有这类报道的是 Evernote（收购、129 人裁员、迁欧），而它恰好是这一组里唯一被大公司收购的。也就是说：**小团队本地优先产品缺少外部审计层，公开可核实的事实主要由「官方自述 + 用户论坛帖」两侧拼成，中间没有第三方。**
