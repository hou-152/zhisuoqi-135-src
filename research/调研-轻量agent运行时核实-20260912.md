### 1 号对象的关键澄清：pi 到底是什么形态

pi 是**三合一**，不是单纯的 CLI：

| npm 包 | 形态 | bin | 证据 |

## 一句话总结：哪些是「能嵌进本地 app 的运行时」，哪些只是「开发时用的 CLI 工具」

**能嵌进本地 app 的运行时（库形态，可在自己进程内 import）**：Claude Agent SDK（官方明说 "a library that runs the agent loop in your own process"）、pi 的 `pi-agent-core` + `pi-ai`（有 import 示例、无 bin）、OpenAI Agents SDK（Py/JS）、LangGraph、Mastra、Google ADK、Maximooch/penguin 的 Python API、penguin-harness 的 `@prismshadow/penguin-core`；**DSH 属于"子进程型运行时"**——它提供 `sdk` profile，通过 stdio 上的 JSON-RPC（`dsh-sdk-jsonrpc-server`）被宿主程序驱动，是进程间而非进程内嵌入。

**同时提供 CLI / 桌面 app 的同一批项目**：pi 的 `pi-coding-agent`（bin `pi`）、DSH 的 `dsh web`（浏览器 UI，默认 127.0.0.1:3080）、penguin-harness 的桌面 app 与 `penguin` CLI（web 服务默认 127.0.0.1:7364）、Maximooch/penguin 的 TUI/CLI/web API。这类项目的"CLI 工具"与"可嵌入运行时"是同一套内核的两种出货形态，不是互斥分类。

**既不是运行时也不是 CLI，而是协议层**：ACP（编辑器 ↔ agent，Zed Industries + JetBrains 主导，已有大量编辑器/桌面端采用）与 MCP（AI 应用 ↔ 外部工具/数据，当前版本 2026-07-28）。二者是接线标准，需要两端各自有实现才成立。
