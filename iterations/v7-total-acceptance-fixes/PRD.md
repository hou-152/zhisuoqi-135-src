# 知所栖 135 · PRD · v7-total-acceptance-fixes

> 文件位置：`iterations/v7-total-acceptance-fixes/PRD.md`
> 本轮依据：总验收结果、用户真实走查反馈、`SOURCE_OF_TRUTH.md`、v5/v6 PRD。
> 本轮目标是修复“看不懂、点不动、入口错位、路径单一、旧流程残留”的体验问题，不扩展新的学习内容。

## 1. 项目背景

知所栖 135 已有知识体系、内参、实践空间、学习空间和桌面版。本轮总验收证明主流程技术链路大多可运行，但用户走查发现信息架构、入口语义和跨区联动仍然让普通用户困惑。

## 2. 本次目标

让普通用户能回答四件事：我正在看什么、筛选会改变什么、点主题后去哪看、下一步为什么是这条路。删除或隔离已经失去产品位置的旧入口，保留可用能力但不让历史实现主导当前体验。

## 3. 用户与关键场景

### 场景 1：浏览内参并筛选
- **用户**：第一次进入内参的普通读者。
- **旅程**：看懂右上筛选 → 选择分类或重要等级 → 看到结果数量和内容变化 → 清空筛选。
- **结果**：筛选有明确语义、结果可预测，分类和策展不是装饰。

### 场景 2：从知识体系主题进入概念
- **用户**：想沿一个主题浏览知识的学习者。
- **旅程**：点击主题 → 点击概念 → 画布平滑移动到对应概念，同时右侧详情与图谱状态同步。
- **结果**：用户知道自己选中了哪个概念，不需要猜右侧是否已更新。

### 场景 3：理解和使用“怎么算会了”
- **用户**：不熟悉费曼验收和判定术语的新手。
- **旅程**：看到概念卡说明 → 选择“先看例子／自己试讲／稍后再做”之一 → 获得明确反馈和下一步。
- **结果**：用户理解这不是考试，也不会误以为必须立即提交复述。

### 场景 4：选择学习路径
- **用户**：想从一个问题开始，而不是被迫接受唯一课程路线的学习者。
- **旅程**：看到可用路线集合 → 了解每条路线解决的问题、预计步骤和入口 → 选择一条开始。
- **结果**：单一路线被明确标为示例或主线，不能冒充全部学习路径。

### 场景 5：进入实践空间和完整主流程
- **用户**：从首页探索产品能力的访客或演示者。
- **旅程**：理解实践空间与知识体系的关系 → 进入实际可用的学习单元 → 不被“135 / 01 决策场”历史入口打断。
- **结果**：实践空间只呈现当前有效的学习入口；完整主流程和桌面版有明确去留说明。

## 4. 页面结构

- `/` 或壳首页 —— 探索、内参、知识体系、实践空间四格入口。
- `#neican` —— 多期内参集合、分类与策展筛选。
- `#graph` —— 我的树与路径；概念详情与图谱联动。
- `#practice` —— 实践空间的主线、路线集合和学习单元。
- `#learn=<id>` —— 单元学习与验收。
- `/135.html` —— 完整主流程页面；本轮明确标注其产品地位，不在实践空间重复挂载历史入口。
- Electron 壳 —— 保留桌面版能力，和网页版共享当前导航与流程口径。

## 5. 信息架构

### 内参集合 `#neican`
- **筛选说明区** —— 解释每个筛选维度会筛什么。
  - 内容槽：分类定义 / 重要等级定义 / 当前筛选条件 / 清空入口
- **结果反馈区** —— 让用户看到筛选确实生效。
  - 内容槽：结果数量 / 无结果说明 / 当前期与日期范围
- **日报卡区** —— 展示符合条件的文章。
  - 内容槽：标题 / 摘要 / 分类 / 重要等级 / 来源 / 进入单篇入口

### 知识体系 `#graph`
- **主题列表** —— 点击后定位主题列并保留选中态。
- **画布区** —— 渲染主题和概念，点击概念后镜头平滑移动到目标节点。
- **概念详情区** —— 与画布选中节点保持同步。
  - 内容槽：定义 / 为什么相关 / 前置与后续 / 来源 / “怎么算会了”说明 / 操作入口
- **验收说明区** —— 用普通语言解释三种操作：看例子、自己讲一遍、稍后继续。

### 实践空间 `#practice`
- **入口说明区** —— 解释实践空间、主线课程、路线和概念全书的关系。
- **路线集合区** —— 展示多条路线或明确标记“当前仅有一条示例路线”。
  - 内容槽：路线名称 / 要解决的问题 / 步数 / 当前进度 / 开始入口
- **主线课程区** —— 只展示当前确认保留的课程单元。
- **状态说明区** —— 用人话解释为什么能学、为什么暂时不能学。
- **历史入口隔离区** —— 旧版 135 / 01 决策场不在默认实践空间出现；若需保留，仅放到完整主流程页面或更新记录。

### 完整主流程 `/135.html` 与桌面版
- **产品定位区** —— 明确“演示／历史主流程／当前主入口”中的一种状态。
- **返回入口** —— 回到当前首页，不把用户重新送进已废弃的实践空间入口。
- **桌面版** —— 保留本地保存与学习记录能力，导航和页面语义与网页版一致。

## 6. 目标衡量

**主指标（本轮验收）：**
- 新用户完成“主题 → 概念 → 图谱定位”的成功率达到 `100%`，且不需要刷新页面。
- 新用户能正确说出内参筛选的作用、实践空间与学习空间的关系，以及“怎么算会了”的下一步。

**漏斗指标：**
- 点击筛选 → 结果数量或空结果提示发生变化。
- 点击主题 → 主题选中态、镜头移动、概念详情三者同步。
- 点击概念验收入口 → 先看到说明，再进入用户主动选择的操作。
- 进入实践空间 → 能看到路线选择或明确的单一路线说明。
- 网页版与桌面版 → 四格导航和关键入口名称一致。

## 7. 范围

**这一版会做：**

1. 重写内参分类与策展筛选的语义、状态反馈和清空行为；筛选计数必须按当前期/日期范围计算，零结果项禁用。
2. 修复主题、概念、画布、右侧详情的联动与平滑定位：点概念后节点必须可见、高亮，详情选中态同步。
3. 重做“怎么算会了”入口说明和用户操作分流：可展开完整判据，提供遮住定义的选择，区分未提交、待判定、通过、有漏；“已读”明确不等于掌握。
4. 将路径明确为“当前唯一正式策展路线”，七站路线标草案；本轮不做多路线排课，实践空间提供目录/折叠/当前定位，避免长页面迷路。
5. 重排实践空间，移除默认出现的旧版 135 / 01 决策场入口。
6. 将完整主流程 `/135.html` 保留为独立 legacy/demo 区，实践空间不重复挂载 135/01 入口；保留桌面版能力，并在重打包前校验 app/assets 与源壳同源。
7. 为以上行为补充桌面端、移动端和普通用户走查验收。

**验收要求：**

- Playwright 桌面端与 `375×812` 移动端逐按钮走查；覆盖正常流程、空结果、错误输入、返回和刷新。
- 新增筛选计数一致性、概念节点可见性、判据说明、实践空间首屏/跳站、legacy 入口隔离、网页版/桌面版同源检查。

**这一版明确不做：**

- 不新增概念地图源数据和大批量课程内容。
- 不重新设计全站视觉主题、字体系统或技术架构。
- 不删除 `/135.html`、Electron 或历史数据；只调整入口和展示位置。
- 不把单一路线扩成未经策展的自动规划系统。
- 不把费曼判定结果包装成学习效果证明。
- 不发布公网、不 push，除非另有明确授权。

## 8. 风险与待解决问题

**已知常见项（请确认或调整）：**

- 内参分类字段和重要等级字段的真实来源需要逐条核对，避免只改文案不改数据逻辑。
- 概念网络存在边标签重叠和部分 R6 层缺失，联动修复不能掩盖图谱数据问题。
- Graph 当前与概念地图规模不一致，不能把系统审计图当作完整数据镜像。
- 当前桌面版 app/assets 比源壳落后约 25 分钟，需先做 hash/mtime 同源检查，再重打包并复测。
- 完整主流程与实践空间的产品定位需要最终裁决，PRD 先保留页面与能力，不做删除。
