# v9-tab-learning-clarity 实施计划

## 背景
当前项目已有四个一级 tab，但搜索状态、知识体系路径、实践空间课程和队友 Starlink 首页之间的职责边界仍不够清楚。六章与七站分别代表深度课程和问题地图，页面目前没有把二者的关系讲明白。5 实验已从当前产品闭环移除。

## 范围
做：tab 状态隔离、探索入口合并、知识体系详情与路径表达、六章—七站交叉引用、内参分类与术语清理、统一视觉和性能回归。
不做：重建概念地图、改写六章和七站数据、自动生成路线、恢复 5 实验、发布公网或 push。

## 阶段总览
| Phase | 目标 | 状态 |
|---|---|---|
| 01 | 固定一级/二级 tab 与筛选状态边界 | pending |
| 02 | 合并 Starlink 探索入口并控制渲染性能 | pending |
| 03 | 重做知识体系的树、路径和概念详情 | pending |
| 04 | 表达六章与七站关系并收紧学习闭环 | pending |
| 05 | 清理内参分类、术语、小字和配图说明 | pending |
| 06 | 桌面、移动、静态产物和真实浏览器整体回归 | pending |

## 关键决策
- 一级 tab 固定为：探索、内参、知识体系、实践空间。
- 知识体系内部只保留：我的树｜路径。
- 六章是深度课程，七站是问题地图；两者共用单元记录，不合并编号。
- 当前产品闭环固定为：阅读 → 3 决策 → 费曼复述验收。
- 5 实验从当前产品中移除；历史演示仅作为历史产物保留。
- Starlink 作为探索层视觉和入口，不覆盖真实模块的数据与学习状态。

## Open Questions
- 六章—七站的交叉引用先采用人工锚点，不自动依据图谱边排课。
- 配图没有可确认素材时，采用简洁图形或留白，不生成复杂插画。
- 公网发布、push 和旧历史页面的去留不属于本迭代，另行确认。
