# 壳的信息层级变成三级下钻：一级导航 → 二级主题 → 三级概念

> 文件位置：`iterations/v1-shell-ia/.plan/plan.md`
> 配套 skill：first-flight-phases
> 本 plan 文档是**稳定航图**，状态跟踪在各 phase 文档（同目录 `phases/NN-*.md`）里。

## 背景

09-13 前半夜连着做了三轮减法（删四个入口与底栏 → 删左栏图例 → tab 提到顶栏），
做到最后壳只剩「知识体系 + 内参」两栏，但**层级仍然是平的**：

1. 主题（21 条，二级内容）挤在**左栏**，跟一级导航 `知识体系` / `内参` 混在一起；
2. 概念（936 条，三级内容）**常驻中间栏**，一打开就是 936 行，看不出「我在哪一层」；
3. `图谱 / 星球` 被提到三栏之上，成了全局顶栏，但它是**知识体系这个页面内的视图切换**，层级过高。

所有者 04:0x 的原话：「这些主题其实它是属于知识体系的**二级页面**，筛选也是属于知识体系的二级页面。
你这下面的这些概念其实是可以去**隐藏的三级页面**」「星球……它不应该在顶栏，而是它在知识体系下面的那个 tab」
「左侧的一级页面，应该是**先内参再知识体系**」。

不做的代价：第一次打开的人（评委 / 队友）在无人讲解时看不出这个产品有几层、下一步该点哪。

## 范围

**做：**

- 左栏一级导航顺序对调：**内参在上、知识体系在下**
- 图谱 / 星球 tab 从全局顶栏移回**知识体系页内**（主区顶部）
- 21 条主题从**左栏**搬到**中间栏**，成为中间栏的默认态（L2）
- 中间栏两级下钻：点主题 → 换成该主题下的概念列表（L3）+ 顶部「← 全部主题」返回
- 画布联动：选中某条主题时只亮这一列（复用已有的 `filter` 机制）
- 四套验收脚本更新并跑过；文档同步

**不做：**

- 不改画布渲染逻辑与费曼倒逼判定
- 不动内参阅读页的四个分页签
- **不删星球**（保留，只从顶栏降级为知识体系页内 tab）
- 不做移动端 / 窄屏专门适配（现有 `<1100px` 隐藏列表栏的权宜行为保持）
- 不动后端与 `/api/*`（`/api/health` `/api/llm` `/api/save` 等一行不改）
- 不做登录、账号、收藏、公开笔记
- 不做虚拟滚动（下钻后单条主题最多 169 条，可接受）

## 关键决策

- **2026-09-13**：拆成 01 / 02 / 03 三段而不是一个大 phase，因为**每一段都能单独打开页面看**——
  不用等全部做完才知道对不对。所有者每段都能验，改错也只回退一段。
- **2026-09-13**：01 先落 tab 位置。它是所有者这轮说得最明确的一条，且跟列表栏改动无耦合，先锁死。
- **2026-09-13**：02 与 03 分开——02 只让「主题出现在中间栏」，03 才做下钻。
  这样 02 做完如果所有者觉得「主题不该占整个中间栏」，回退成本只是一段。
- **2026-09-13**：**不删星球**。所有者原话是「我觉得应该存在……但不应该在顶栏」——
  它是降级不是删除。删它属于超出 PRD 的动作。
- **2026-09-13**：中间栏复用现有的 `renderList()` 分支结构（`currentView` 加态），
  不新写一套列表渲染——壳里已经有三栏 + 面板的既有骨架，重写会带来无谓回归风险。
