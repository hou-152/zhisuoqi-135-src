## 〇、这份 README 的写法

**这份文档是辩证写的：每一条正面说法后面，都要跟一条「它在什么条件下不成立」。**

不是为了显得谦虚。是因为这个项目真实发生过的事是：**测试数量一直在涨，而没有人真的用过它。**
只写正面，就是把这件事再掩盖一次；只写反面，就是把已经做出来的东西说没了。两种都是失真。

所以下面每个小节都按三段走：**说它行，行在哪 → 说它不行，不行在哪 → 这条边界是怎么核出来的**。
凡是我今天亲自跑过的，会写「本机实测」并给出命令；凡是只从历史回执拿来的，会写「历史回执，未复核」。

## 一、这个项目在做什么

**正：** 从用户眼前的问题出发，找到需要补的知识，沿一条可解释的路线阅读、解释、判断，并留下能继续用的学习记录。

真正想做的不是知识展示页，也不是让 LLM 围着材料自由聊天，而是这一句：

> **AI 能接住学生的回答，针对当前缺口补讲；学生讲清之后，系统接着推进原来的学习过程。**

负责人选定的交互是「**它问哪里，学生就只补哪里，系统接着往下教**」——不是每次都要重写整段解释，也不是每次短答之后模型就忘了前面讲清过什么。

**反：** 上面这段现在是**设计意图，不是已证明的效果**。
本仓库里**没有任何一条真人学习记录**。学习空间里的每一次复述、每一次作答，全部是脚本扮演的合成学习者（`walk-graph-real.mjs`
的头部注释里就写着这句话）。所以「AI 能接住学生」目前能说的是：**这条链路在脚本扮演下跑得通**，不是「学生真的被接住了」。

**这条边界怎么核出来的：** `ls evidence/` 里所有 `*-walk-*.json`、`inline-feedback-*.json`、`real-diagnosis-*.json`，
`learnerIs` 字段一律是「合成学习者（脚本扮演，不是真人，也不是学习效果实验）」。没有例外。

## 三、全链路 Graph 是什么，以及它为什么还不等于"全做完了"

**正：** `knowledge/graph-260914/graph.json` 把材料、语义、知识、课程、活动、记录编成同一套索引，**分五种边**：

| 边类 | 数量 | 能不能驱动学习跳转 |
|---|---:|---|
| `knowledge` 知识关系 | 5725 | 不能 |
| `provenance` 出处关系 | 1165 | 不能 |
| `curriculum` 课程编排 | 278 | 不能 |
| **`transition` 流程** | **395** | **能——唯一能** |
| `evidence` 证据 | 运行期创建 | 不能 |

七层：材料与出处 252 · 五类语义 538 · 公共知识与关系 1020 · 问题与课程编排 47 · 学习活动 142 · 运行与记录 0（运行期才建）· 模型与规则 3。

而且它**不是旁边画的一张示意图**：`scripts/lib/graph-runner.js` 是**一个文件两处用**——
Node 里的验收脚本 `require` 它，浏览器里的壳由 `build-shell.mjs` 内联它。
学习空间里学生每一次复述、每一次作答，走的都是图里真实注册的 `transition` 边；**章末解锁改由运行器核对正式条件后才写**。
只有 `transition` 边参与 `allowed()`；`guard` / `effect` 必须按名字查到注册表，查不到就是系统未判定，不许静默通过。

**反：** 「全部 Graph」这句话有两个完全不同的意思，混起来就会自我欺骗：

```text
结构完整：这些环节和关系全部进入统一模型，现有资产通过适配挂接     ← 做到了
内容完成：每个具体单元都有足够、可信、经过必要审核的材料           ← 没做到
```

本轮**只完成了前者**。45 条缺口全部保留节点并写清原因（不变成 `ready`），主要五类：

1. 图鉴站的 7 个 `category_id` 与概念地图 21 个主题是**两套分类，没有逐条核对过的映射**（不按名字猜）。
2. 六章判据的补讲材料只绑到**整章阅读梯度**；单篇有逐条指定的 `material[ref]`，六章没有这一层。
3. 单篇**没有已确认的正式章末通过与解锁门**，照实标待装配，不借用六章的通过标准。
4. 六章主案例**全部是「假设场景」**；每章候选 CAS 只有 1 个，没有第二个可对比候选。
5. 源数据自带重复（概念依赖 2 条、概念关系 11 条，已按稳定身份去重并登记）；**227 个语义单元源数据本身就标着「待核对」**；
   49 个原始来源本地只有标题/作者/链接，**没有正文快照**。

**这条边界怎么核出来的：** `node scripts/check-graph.mjs`（85 项）会逐条查断链、未注册的守卫/效果、
`scaffold` 有没有写清原因，并拿概念地图 `manifest.json` 的 sha256 核对**公共源数据一个字节没被改脏**；
`node scripts/test-graph.mjs`（210 项）走的是固定响应端到端。

### 3.1 知识是网，课程是线

同一个公共概念（例如 Harness）可以被多条路线引用，但**路线位置、目标、判据、通过状态都各自独立**：

```text
路线 A → 某个教学单元 ─┐
                      ├→ 同一个公共概念 Harness
路线 B → 另一个教学单元 ┘
```

在一条路线里答对一道 Harness 题，**不能**自动推导为他掌握了这个概念的所有场景。公共知识、课程位置、个人证据分别记录。

**反：** 本库当前**只有 1 条正式路线**。为了让「运行器能被复用」「共享概念真的被两个位置引用」这两条可验证，
用了一条**明确标注的开发夹具路线**（`route:fixture-shared-concept-v1`，2 个单元，页面显著标「开发夹具 · 不是正式课程」）。
**夹具不是第二条课程**，`check-graph.mjs` 里有一条断言专门盯着这件事：正式路线数量必须仍然是 1。

## 四、教学闭环：哪一半是真的，哪一半还没有

| 机制 | 正：已经做到 | 反：它还不等于 |
|---|---|---|
| 短答承接 | 新回答没重述旧判据 → **保留旧证据**、不新增 `missing`，并留一条 `kept` 记录 | 这是规则层的正确，不是「学生真的讲清了」 |
| 新矛盾 | 明确推翻旧关系 → 记 `conflictAt` ＋ 保留 `previous` ＋ 进补讲重新核对 | 冲突判定仍来自同一个模型 |
| 补讲回归点 | 三条真路径都验过：从阅读中费曼发起 → 回阅读中费曼；从某道题发起 → **回那一道题**；从章末发起 → **回章末** | 不是「永远回决策题」这条错误已被测试挡住，但**只有脚本走过** |
| 错题回补 | 答错 → 反馈 → 补讲 → 回**同一题**重答，不自动算对 | 题目来自人工撰写，覆盖的是 18 道 |
| 即时费曼 | 讲对了也**不解锁**、也没有"跳下一单元"这条边 | 无 |
| 章末门独立 | 通过必须来自**一次独立的章末验收记录**（逐条判定全 met）；补讲 `met` 之后仍然没过 | 判定等级是「本地模型」，不是人 |
| 暂停恢复 | 暂停记住原节点，跑开再恢复 → 回到**保存的那个节点**，不是从阅读重来 | 只存在本地，没有账号系统 |
| 系统异常 | 超时 / 非法 JSON / 未知 ID / 非法状态 → **系统未判定**，草稿与旧证据不动，既不通过也不算学生不会 | 无 |

**反（这一轮最该记住的一条）：模型判定会波动。** 真模型走查里，同一段复述第 2 轮判 `met`、第 3 轮又判 `partial`。
这记在证据里，**没有**通过改答案、改预期去凑成绿的。

**这条边界怎么核出来的：**

```sh
node scripts/test-graph.mjs          # 210 项：六章 ＋ 单篇四判据 ＋ 夹具 ＋ 整条路线一次走完
node scripts/test-learn-agent-loop.mjs   # 学习空间黑盒：费曼门 · 未过不解锁 · 改复述清状态 · 判定竞态作废
node scripts/walk-graph-real.mjs agent 5180   # 真模型走查一章（真调 /api/llm，3 次调用）
```

真模型那趟的实际轨迹（`evidence/agent-loop-260913/graph-walk-real-*.json`，11/0）：

```text
阅读 → 读中费曼 → 真判定①(partial/missing) → 补讲 → 学生只补那两处 → 回阅读中费曼
     → 真判定②(全 met) → 回阅读 → 三题实际作答 → 章末 → 真判定③ → 应用核对 → 进第 2 章
```

## 五、两种"五"：五类语义与真五维

**五类语义**（`QST` 问题 / `CON` 概念 / `OPI` 观点 / `CAS` 案例 / `SOL` 方案）说的是**材料在说什么**；
**真五维**（`concepts` / `reading` / `decisions` / `experiments` / `feynman`）说的是**这些材料怎样用于学习**。
两者需要连接，但**不是一套字段的两种叫法**，代码里也是分别建模再连边。

**反：** 真五维目前**只有 10 份**（内参 260912 期）；六章课程里**没有实验环节**，那 9 个 `ExperimentReference` 节点
照实标着「未启用」（本轮不新建实验台）。「每份 3 概念 / 1 阅读 / 3 决策 / 5 实验 / 1 费曼」是**那批材料的内部结构线索，
不是所有未来内容必须凑齐的数量**。

## 七、为什么会反复返工（这一节是复盘，不是待办）

负责人指出过：过去也常用「先跑 MVP，再拆成很多 issue，反复审核复审」的方式，最后仍然没推动起来。
下面是从这轮讨论里收敛出来的判断。

**7.1 管理闭环 ≠ 产品闭环。** 「实现一点 → 写回执 → 审查发现问题 → 拆新任务 → 再修复」可以永远转下去，
而另一条过程始终没发生：**一个人实际使用 → 发现具体阻碍 → 改掉阻碍 → 这一版开始被使用。**
任务、文件、测试在增长，不必然意味着出现了一个可以交出去的版本。**本仓库现在最大的缺口不是功能，是后面这条。**

**7.2 同一条规则散落在六处时，「改过」不等于「运行时生效」。**
一个要求可能同时存在于：聊天、任务书、判据 JSON、提示词、测试预期、页面逻辑。改了一处，另外几处还是旧口径。

**7.3 先完善零件、太晚连接整条链。** 局部结构可以正确，却未必支持完整的使用过程。
所以这轮的做法是：**一边保留分层测试，一边尽早让一条完整但有限的链路跑起来**（就是第三节那张图）。

**7.4 审查也可能不断扩大范围。**「值得修」不等于「必须阻止当前版本试用」。如果每个新发现都自动变成本轮阻塞，版本就没有自然结束点。
安全风险必须处理；普通改进不自动获得否决权。

**反：** 上面四条是**判断，不是已被验证的结论**。它们本身也需要被检验——检验方式只有一个：让人真的用一次。
在这一步发生之前，这一节也随时可能是错的。
