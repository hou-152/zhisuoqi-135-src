# 谷歌重磅发布WikiSkill，技能可以自己进化了！

## 一句话主旨
通过分离原始轨迹、持久知识库与可执行技能三层架构，WikiSkill 让 Agent 技能从不回滚的经验知识中自我进化。

## 作者试图回答的问题
如何摆脱对更大模型或更多训练数据的单一依赖，让 Agent 在执行任务的过程中实现技能的自适应进化与持续变强？

## 三级论证骨架

### 一、架构核心：把经验与知识彻底解耦
#### 1.1 传统技能进化方法的根本缺陷
- 过去方法（如 EvoSkill、Trace2Skill、SkillOpt）在分析完执行轨迹后直接修改技能提示词。
  - 原话：“以前的技能进化方法（EvoSkill、Trace2Skill、SkillOpt）分析完执行轨迹就直接改 Skill，经验用一次就丢。”
  - 缺乏持久层，经验未沉淀，改动丢失了背后的推理上下文。

### 二、三层知识架构设计
#### 2.1 第一层 Raw Layer：不可变的原始事实依据
- 存储每次迭代的完整执行轨迹（推理链、工具调用、输出）。
  - 原话：“Raw Layer 存储每次迭代的执行轨迹，包括 Agent 的完整推理过程、工具调用、输出结果。这一层不可变，目的是保留"到底发生了什么"的原始记录。”
  - 为后续提取失败模式和按需回溯提供不可篡改的事实。
#### 2.2 第二层 Wiki Layer：跨迭代持续积累的知识中枢
- 将轨迹编译为结构化知识：包含失败原因与修复方案的模式目录（patterns/）、进化日志（logs.md）以及技能接受/拒绝记录（skill-impact.md）。
- 关键设计一：Wiki 永不回滚。
  - 原话：“第一，Wiki 永不回滚。Skill 被拒绝时，Skills Layer 回到上一版本，但 Wiki 保留所有积累的知识。”避免后序重复踩坑。
- 关键设计二：知识与技能分离。
  - 原话：“第二，Knowledge 和 Skill 分离。知识回答"我们知道什么"，技能回答"我们该怎么做"。”
#### 2.3 第三层 Skills Layer：带溯源的可执行技能
- 包含当前生效的技能，每个技能下包含直接读取的 SKILL.md 与记录溯源依据的 PURPOSE.md。
  - 原话：“PURPOSE.md 解决的是"这个技能为什么存在"的问题。当技能需要修改时，Proposer 可以通过 PURPOSE.md 回溯到对应的知识模式，理解当初的设计意图，而不是盲目地打补丁。”

### 三、进化闭环与实验实证
#### 3.1 四步闭环协同机制
- 闭环由四步组成：Inference Agent 跑 rollout 产生轨迹（训练时禁读 Wiki）；Wiki Maintainer 进行根因分析更新 Wiki；Skill Proposer 以 ReAct 方式读 Wiki 并提出技能更新；Gating 门禁在验证集评估打分。
#### 3.2 实验表明技能进化能弥补规模差距
- Qwen-3.5-9B 结合 WikiSkill 平均达到 47.4%，超越 Qwen-3.6-27B 裸模型的 39.4%。
- 消融实验证明 Wiki 层的关键承重价值：
  - 原话：“去掉 Wiki 访问后，平均分从 63.7% 降至 48.7%，回落约 15 个百分点。Wiki Maintainer 积累的跨迭代知识是 Skill Proposer 能解决复杂失败模式的前提。”

## 作者边界、反例与不确定性
作者明确指出了训练阶段的数据访问限制：Inference Agent 在训练时不能访问 Wiki，否则 Agent 会直接查答案导致轨迹失去参考价值；同时，“发现策略”与“执行策略”属于不同能力，小模型执行大模型进化的技能效果优于自进化技能。
