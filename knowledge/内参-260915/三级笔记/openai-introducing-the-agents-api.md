# 推出 Agents API | OpenAI

## 一句话主旨
OpenAI 推出公测版 Agents API，将驱动 Codex 的云端执行框架、上下文自动压缩与多子智能体编排全面开放为托管服务。

## 作者试图回答的问题
如何摆脱开发者自行维护长程提示词链、脆弱工具调用与复杂子智能体编排的基础设施负担，让生产级智能体能够可靠连续运行数天？

## 三级论证骨架

### 一、长程智能体落地的三大基石
#### 1.1 实用智能体的系统级要求
- 真正的实用智能体不仅仅是一个模型接口调用，需要全套执行框架与基础设施。
  - 原话：“实用的智能体需要一个强大的执行框架，用于管理上下文、高效使用工具并协调子智能体。它们还需要可靠支持其连续运行数天的基础设施，以及能让它们处理文件、运行代码并保存中间结果的环境。”
- 核心理念：将执行框架交由 OpenAI 托管维护，计算沙箱可自由选配，让开发者聚焦于特有工具与业务流。

### 二、Codex 执行框架的核心机制演进
#### 2.1 长会话上下文自动压缩（Compaction）
- 支持模型连续工作数小时乃至数天，克服上下文窗口限制。
  - 原话：“当会话接近上下文上限时，Agents API 会自动压缩较早的上下文，同时保留智能体继续工作所需的信息。开发者无需自行实现压缩逻辑，即可构建跨越多个上下文窗口的工作流。”
#### 2.2 工具搜索与程序化调用（Programmatic Tool Calling）
- 动态加载工具定义：
  - 原话：“工具搜索会按需加载相关工具定义，在保留模型缓存的同时减少 Token 用量和成本。”
- 程序化调用削减数据载荷：
  - 原话：“程序化工具调用可让智能体并行执行调用、串联相关操作，并通过代码筛选或合并结果，从而处理海量数据，同时只将相关结果送回上下文。”
#### 2.3 多子智能体并行编排（Multi-Agent Subagents）
- 任务拆解与上下文隔离：
  - 原话：“借助多智能体支持，Agents API 可将复杂任务拆分为相互独立的部分，并委派给多个子智能体并行处理。每个子智能体都维护各自的上下文，以便专注于分配到的任务；主智能体则协调它们的工作并汇总结果。”

### 三、开源底座与生态解耦
#### 3.1 基于开源 Codex Harness 构建
- 核心逻辑由开源 Codex harness 驱动，保证开发者能检查核心调度逻辑。
  - 原话：“The Agents API is powered by the open-source Codex harness, giving developers visibility into the core logic that coordinates model calls, tools, and context.”
#### 3.2 沙箱计算环境的自由解耦
- 支持 OpenAI 托管沙箱，亦支持接入 E2B、Modal、Cloudflare、Daytona 等合作伙伴或部署在自有 VPC 中。
- 平台无额外包装费用，按实际使用的 Token 和工具用量付费。

## 作者边界、反例与不确定性
作者指出，Agents API 目前处于公测（Public Beta）阶段，执行框架由官方统一定义演进；虽然支持自定义沙箱与 VPC 隔离，但模型的上下文压缩与多智能体协调策略完全受托管调度逻辑约束。
