从技能验证器工具开始——它能在您花时间调试其他问题之前，先捕获结构性问题 
如果某个技能无法触发，原因几乎总是出在描述上——添加与您实际表达请求方式相匹配的触发短语 
如果某个技能无法加载，请检查 SKILL.md 是否位于一个命名目录内（而不是在技能根目录下），并且文件名是否恰好为 SKILL.md 
如果使用了错误的技能，说明您的描述过于相似——让它们更具区分度 
对于运行时错误，请检查依赖项、文件权限（chmod +x）以及路径分隔符（请在所有地方使用正斜杠） 
当技能无法正常工作时，问题通常属于以下几类之一：技能无法触发、无法加载、存在冲突，或在运行时失败。好消息是，大多数修复方法都相当直接。
首先应该尝试的是 agent skills verifier 命令。安装步骤因操作系统而异，但使用 uv 是最快捷的设置方式。
安装完成后，您可以导航到您的技能目录，或者从任意位置运行该命令。验证器会在您花时间调试其他问题之前，先捕获结构性问题。
您的技能存在且通过了验证，但 Claude 在您期望的时候却没有使用它。原因几乎总是出在描述上。
Claude 使用语义匹配，因此您的请求需要与描述的含义有所重叠。如果重叠不足，就不会匹配。以下是您应该做的：
 
用各种变体进行测试，例如"帮我分析一下这个性能"、"为什么这个这么慢？"、"让这个更快一点" 
如果任何变体未能触发，请将这些关键词添加到您的描述中 
如果您询问 Claude "有哪些可用技能"时，您的技能没有出现，请检查以下结构性要求：
 
SKILL.md 文件必须位于一个命名目录内，而不是在技能根目录下 
文件名必须恰好为 SKILL.md——"SKILL"全部大写，"md"小写 
运行 claude --debug 查看加载错误。留意提及您技能名称的消息。有时仅凭这一点就能直接指向问题所在。
如果 Claude 使用了错误的技能，或者在多个技能之间似乎感到困惑，那么您的描述很可能过于相似。让它们更具区分度。尽可能具体不仅有助于 Claude 决定何时使用您的技能——还能防止与其他听起来相似的技能发生冲突。
如果您的个人技能被忽略，可能是因为存在一个同名的企业级或更高优先级的技能。
技能优先级层级结构——企业级高亮显示于个人、项目和插件之上，旁边是 managed-settings.json 文件名
例如，如果存在一个企业级的"code-review"技能，而您也有一个个人的"code-review"技能，企业级的那个每次都会胜出。您的选择：
 
将您的技能重命名为更具区分度的名称（这通常是更简单的方法） 
安装了插件但看不到其技能？清除缓存，重启 Claude Code，然后重新安装。
如果之后技能仍未出现，可能是插件结构有问题。这正是验证器工具真正发挥作用的时候。
技能已加载，但在执行过程中失败。几个常见原因：
 
缺失依赖项： 如果您的技能使用了外部软件包，这些软件包必须已安装。在您的技能描述中添加依赖信息，以便 Claude 知道需要什么。 
权限问题： 脚本需要执行权限。对您的技能所引用的任何脚本运行 chmod +x。 
路径分隔符： 在所有地方都使用正斜杠，即使在 Windows 上也是如此。 
 
无法触发？ 改进您的描述并添加触发短语。 
无法加载？ 检查您的路径、文件名和 YAML 语法。 
使用了错误的技能？ 让各个描述之间更具区分度。 
被遮蔽了？ 检查优先级层级结构，如有需要请重命名。 
插件技能缺失？ 清除缓存并重新安装。 
运行时失败？ 检查依赖项、权限和路径。
