## ① 概念 ×3

- **流程不变，主体变了**：AI 原生开发 = 用新方式跑旧流程——可行性、方案、原型、编码、测试五关一个没少；变的是每关的执行主体从人换成 Agent。人从一线程序员升职成技术总监，只回答三件事：做不做、怎么做、做得对不对。
- **瓶颈转移到代码两侧**：编码已经不是瓶颈（模型编码能力过剩，「简单的自然语言提示词就够了」）；左边是设计与确认，右边是测试、验证、部署——两侧仍以人类速度运行，才是值得优化的地方。宝玉的反直觉推论也从这来：别装编码类 Skills，代码不需要增强，两侧才需要。
- **文档 = 记忆载体**：Agent Session 上下文有限，跨会话、跨人交接全靠文档传递——「确认后的文档，就是下一个 Agent Session 的全部起点」，一句「按 docs/remote-transcription.md 实现」就够。代价：版本不更新，文档反而喂给 Agent 错误上下文。

## ② 阅读 ×1（三层梯度）

> 一个真实功能从 GitHub Issue 走到上线，作者一行代码没 Review——因为他把时间全花在了代码两侧。

- **直觉**：AI 原生开发不是「让 AI 帮我写代码」。是「你当技术总监，Agent 当一线」：你不写每一行，但你决定做不做、怎么做、做得对不对。
- **机制**：五关拆开看——可行性分析（Agent 罗列方案、人拍板方案 A）→ 设计文档（把决策固化成下一个 Session 的起点）→ 高精度原型（需求/交互/UI 三合一，改布局只是一句话）→ 实现（Agent 自跑测试自截图，自己先验证完再交给人）→ 黑盒测试（把自己当普通用户乱点，而不是当开发者走正路）。
- **边界**：可行性分析是期望值的赌注——作者上一个「技术没问题」的功能照样翻车砍掉；跳过 Code Review 只在「Agent 自验证 + 常规功能」时安全，金融核心逻辑不行；文档过期比没有文档更危险。

## ③ 决策 ×3

- **情境**：有个新功能想法，第一反应是打开编辑器开干。
  - 做法：先过可行性两栏——产品角度（有没有价值、配不配定位）、技术角度（做不做得、成本可不可控），让 Agent 列方案，自己拍板。
  - 适用条件：预期投入好几天/一大堆 token 时才值得；几十钟能试错完的小改动，直接干反而是更优解。且记住它只是提高期望值，照样会看走眼。
- **情境**：要从设计阶段进实现阶段，或把活交给下一个人/下一个 AI 会话。
  - 做法：把决策固化成文档（需求、架构、接口），确认后用一句话交接：「按 docs/xxx 实现」，不口头复述来龙去脉。
  - 适用条件：上下文一次能说完的独狼小任务可以不写；但凡跨 Session、跨人，文档比口头精确。前提是文档保持更新——过期文档是负资产。
- **情境**：想给 Agent 装一堆开发类 Skills，让编码更强。
  - 做法：不装。编码已过剩，只装两侧的：左侧设计确认类（如 Claude Design / baoyu-design），右侧省体力的自动化类（自动部署、/goal 里程碑推进）。
  - 适用条件：常规功能开发成立；陌生技术栈、极端性能要求时编码能力仍可能吃紧，届时再补。

## ④ 实验 ×5

1. **做**：下一个想法动手前，先写可行性两栏表（纸笔即可）：产品价值/技术成本各一栏，最后一句话写「做/不做 + 理由」。
   - 观察：多少「技术没问题」其实没依据；产品理由是不是事后补的。
   - 结论：可行性分析到底帮你挡了什么，以及它挡不住什么。
2. **做**（免费）：写一份简易设计文档，新开一个全新 AI 会话，只发一句「按这份文档实现」；对照组不发文档。
   - 观察：实验组能否无背景直接开工；对照组漏掉了哪些决策。
   - 结论：文档作为 Session 间桥梁的最小有效密度是多少。
3. **做**：同一个交互改动，在原型阶段改一次、等实现后再改一次，记录各自耗时。
   - 观察：两者的成本差几个数量级。
   - 结论：「原型阶段值得死磕」是不是真的。
4. **做**：把自己当第一次用的用户，凭直觉走一遍自己刚做的功能，记下每个卡点。
   - 观察：开发者视角漏掉的提示不清、路径不通有几处。
   - 结论：黑盒测试抓住了哪些 Agent 自测试抓不住的问题。
5. **做**：盘点自己装的编码类 Skills，禁用一周；同时给设计侧、自动化侧各加一个。
   - 观察：编码质量是否真的下降；两侧的效率变化是否更明显。
   - 结论：亲自验证「瓶颈在两侧」这个判断。

## ⑤ 费曼验收

**AI 示范**：宝玉给 App 加远程转录功能，全程没写代码。他只干三件事：决定值不值得做，把要求写成文档，最后当普通用户试了一把——中间的活全归 Agent。他的核心发现：软件开发的流程一步没少，只是干活的人换了，你升职成技术总监。写代码已经便宜到不值钱，值钱的是代码前面「决定做什么」和后面「验证对不对」，你的时间该全部押在这两头。

**判定要点**（引擎用）：
- 流程不变主体变：能讲出五关一个没少；能讲出人只做确认与决策、Agent 做执行。
- 瓶颈两侧：能讲出编码为何不是瓶颈；能说出左侧（设计与确认）与右侧（测试/验证/部署）各含什么。
- 文档桥梁：能讲出文档两大职能（给人确认的载体 / 给 Session 传上下文）；能说出过期文档会喂错上下文的风险。
