# 五维拆解 · agent-skills-lesson-1

## ① 概念 ×3
- **技能（Agent Skills）**：技能是 Claude Code 可以发现和使用的指令文件夹，用于更准确地处理任务。；技能是一个 Markdown 文件，它教会 Claude 如何做某事一次，之后 Claude 会在需要时自动应用这些知识。；技能最适用于将专业知识应用于特定任务，且其独特之处在于自动化并与特定任务相关。
- **SKILL.md 与技能描述**：每个技能都存在于一个 SKILL.md 文件中，其前端包含名称和描述。；技能描述是 Claude 决定是否使用该技能的依据：Claude 把请求与所有可用技能描述比较，激活匹配的技能。；在前言下方写实际说明——审阅清单、格式偏好，或 Claude 需要知道的关于该任务的任何信息。
- **按需加载与自动激活**：技能按需加载：Claude 最初只加载名称和描述，因此不会占据整个上下文窗口，请求匹配时才加载正文。；当 Claude 识别到相应情况时，技能会自动激活，不需要像斜杠命令那样手动输入。；与 CLAUDE.md 每次对话都会加载不同，PR 审核清单在调试时无需出现在上下文中，实际请求审核时才加载。

## ② 阅读 ×1（三层梯度）
> 如果你总在向 Claude 重复同一套规范、审查结构或格式偏好，这篇文章说清了把这件重复事变成一次封装、自动生效的办法。

- **直觉**：技能就是一个指令文件夹：你把自己反复解释的做事方式写进去，Claude 在合适的时候自己找出来用，不用你每次重讲。
- **机制**：Claude 先只加载每个技能的名称和描述，把你的请求与所有技能描述比对；匹配成功才按需加载技能正文并自动激活，所以它既不常驻上下文，也不需要你像斜杠命令那样手动调用。
- **边界**：技能的适用面是把专业知识应用于特定任务，靠描述匹配触发；描述写得让请求匹配不上，自动激活就不会发生。个人技能跟随你所有项目，项目技能随仓库给克隆者共享，共享范围错了，该被团队共用的规范就传不出去。

## ③ 决策 ×3
- **情境**：你每次让 Claude 审查 PR，都要重新描述希望反馈的结构；每次提交信息都要提醒一遍格式。
  - 做法：按经验法则把反复解释的这件事写成技能：把审阅清单、格式偏好放进 SKILL.md 前言下方的说明里。
  - 适用条件：适用于同一类说明会被反复交代、且能归到特定任务的情况；如果只是偶尔提一次、或每次要求都不同，就不值得封装。
- **情境**：你希望 Claude 始终使用某种通用设定（如 TypeScript 严格模式），又想让它同时拥有只在特定任务才需要的专业知识。
  - 做法：把始终要生效的通用设定留在 CLAUDE.md，把与特定任务相关、按需才需要的知识写成技能，避免后者一直占据上下文窗口。
  - 适用条件：适用于能分清“每次都生效”与“匹配到才生效”两类需求时；原文未说明二者是完全替代还是互补，无法判断归属时就先按各自特点分开摆放。
- **情境**：你写了一套团队标准（如品牌指南、首选字体和网页设计颜色），希望同事克隆仓库后自动获得。
  - 做法：把它作为项目技能放在仓库根目录的 .claude/skills 下，并与代码一起提交到版本控制系统中共享；个人偏好则放在 ~/.claude/skills。
  - 适用条件：适用于需要团队共享的规范；如果只是个人提交信息风格、文档格式等个人偏好，放个人目录更合适。

## ④ 实验 ×5
1. **做**：用一张纸或纯文本（不依赖任何付费工具）列出你最近一次与 Claude Code 互动中重复交代过的指令，逐条标记“每次都要说”。
   - 观察：哪些说明出现了重复，重复属于编码规范、审查反馈结构还是提交信息格式这一类。
   - 结论：验证“反复向 Claude 解释同一件事”这条经验法则能否用来判断哪项技能需要写出来。
2. **做**：为其中一条重复说明写一个 SKILL.md 草稿：前端写名称和描述，前言下方写审阅清单或格式偏好等实际说明。
   - 观察：描述是否能让一个只看名称和描述的匹配过程认出“什么请求该用我”。
   - 结论：验证技能描述是 Claude 决定是否使用该技能的依据，描述不清就无法可靠匹配。
3. **做**：做一个对照：把同一句请求分别对照两份技能描述——一份写得贴合该请求，一份写成不相关的描述，观察哪一份会被匹配、终端里是否看到技能加载出来。
   - 观察：请求与技能描述比对后，加载行为是否只在描述贴合时才发生。
   - 结论：验证技能靠描述匹配、匹配到时可在终端中看到加载，触发是自动而非手动。
4. **做**：把同一份技能内容分别放到个人技能目录与项目技能目录，再用另一台机器或另一份仓库副本验证谁能拿到它。
   - 观察：个人技能是否贯穿所有项目，项目技能是否随仓库被克隆者自动获得。
   - 结论：验证个人技能与项目技能的作用域和共享边界，决定该把规范放哪一层。
5. **做**：不借助任何付费工具，写出两个简短场景：一个是把专业审核清单做成技能、只在请求审核时才加载；另一个是把同内容常驻在每次对话加载的文件里。
   - 观察：调试等无关时刻，哪种方式不需要把审核清单显示在上下文中。
   - 结论：验证按需加载与 CLAUDE.md 每次加载的差别：最初只加载名称和描述，因此技能不会占据整个上下文窗口。

## ⑤ 费曼验收
**AI 示范**：技能就是把重复交代的做事方法写成一份 SKILL.md：上面贴名称和描述，下面写审阅清单、格式偏好。你发出请求，Claude 拿它比对所有技能描述，匹配上才加载正文并自动应用。个人技能跟着你所有项目，项目技能随仓库共享给克隆者。

- 技能（Agent Skills）：说出技能是 Claude Code 可以发现和使用的指令文件夹，用于更准确地处理任务；说清技能教一次、之后在需要时自动应用，而不是每次重讲；点出技能最适用于把专业知识应用于特定任务

- 按需加载与自动激活：说出最初只加载名称和描述，因此不占据整个上下文窗口；说出请求匹配时才加载、由识别到相应情况自动激活，不需要像斜杠命令那样手动输入；能对比 CLAUDE.md 每次对话都会加载这一差异
