# 撕开 Claude Code 真相：让它好用的 98.4%，是工程不是 AI

## 一句话主旨
让 AI 编程好用靠 98.4% 工程基建，而非 AI 本身。

## 作者试图回答的问题
为什么 Claude Code 好用？让 AI 编程在生产环境真正可用的，是更强的模型或更长的提示词，还是围绕模型搭建的工程基础设施？关联子问题：1.6% vs 98.4% 从何而来、意味着什么；CLAUDE.md、skills、hooks、docs/decisions 如何组成“项目大脑”；Harness Engineering 是什么；普通开发者能做什么。

## 三级论证骨架
### 一、引子：所谓“泄露截图”并非泄露，而是官方标准范式
#### 1.1 起点是 X 推文
- @ai_rohitt 晒出“头部大厂偷偷在用的 Claude Code 项目模板外泄”。
  - 推文开头：“这已经不是写提示词了。这是 AI 工程基础设施。”
#### 1.2 截图内容不是泄露
- 它是 Anthropic 官方文档里公开推荐的 Claude Code 标准范式。
  - CLAUDE.md 是 Claude Code 每次会话开始时自动读取的项目记忆文件；.claude/skills/ 和 .claude/hooks/ 是官方支持的扩展机制。
  - 社区已经讨论了几个月，但很多资深开发者这两天才意识到原来它还能这么用。
- 作者判断：硅谷顶级团队已经把这件事跑成生产线。

### 二、核心数据：1.6% vs 98.4%，产品复杂度重心在工程
#### 2.1 数据来源与结论
- MBZUAI VILA-Lab 论文扒了 Claude Code v2.1.88 的 51.2 万行 TypeScript 源码。
  - 结论：只有 1.6% 是 AI 决策逻辑，98.4% 是确定性工程基础设施。
#### 2.2 98.4% 的构成与限定
- 98.4% 具体由四类组成：权限网关、上下文管理、工具路由、错误恢复。
- 限定：这组数字不是说模型只贡献 1.6% 的能力，而是说明 Claude Code 作为产品，大量复杂度不在模型本身，而在围绕它的工程基建上。
#### 2.3 与顶级团队同范式
- 普通开发者的 CLAUDE.md/skills/hooks 结构，和 OpenAI、Stripe 那套是同一种范式，只是规模小得多。

### 三、项目大脑：CLAUDE.md 及周边结构
#### 3.1 范式转移
- 真正在生产环境跑通 AI 编程的团队，关心的早就不是模型版本。
  - 而是：怎么让 AI 记住自己上次踩过的坑；怎么让 AI 动手前先看项目架构约束；怎么让 AI 犯错时自己被工具挡住。
#### 3.2 CLAUDE.md = 项目大脑/员工手册
- Anthropic 官方定义：一个 markdown 文件，放在项目根目录，Claude Code 在每次会话开始时自动读取。
  - 内容：架构决策、命名约定、测试要求、反复踩过的坑。
- 三条核心原则围绕它展开：每次 Claude 犯错，加一条规则；每次你重复自己，加一个工作流；每次出 bug，加一道护栏。
#### 3.3 skills = 可复用工作流/SOP
- Boris Cherny：“如果你每天做某件事超过一次，把它变成 skill 或 command。”
  - 一个 skill 就是一段可执行的方法论；code review、生成 commit message、写发布说明，都不该是每天手敲提示词的活。
#### 3.4 hooks = 自动护栏/合规部（最关键）
- 不依赖 AI 自己判断，由确定性代码在 AI 犯错之前就挡住它。
  - 这是敢让 AI“无人监督”地跑的原因：出错的边界由 hooks 卡死了。
#### 3.5 docs/decisions = 架构决策记录（最容易被忽略，但最大杠杆）
- 让 AI 不仅知道代码“是什么”，还知道代码“为什么是这样”。
#### 3.6 “AI 公司岗位编制”隐喻
- CLAUDE.md = 入职手册，skills/ = 工作 SOP，hooks/ = 合规部，docs/ = 公司章程，tools/ = 后勤组，src/ = 真正出活的业务部门。
  - 概括：“你不再是在和 AI 聊天了，而是在构建一个了解你代码仓库的 AI。”
#### 3.7 多团队收敛信号
- GitHub 代表项目：rohitg00 的 awesome-claude-code-toolkit、diet103 的 claude-code-infrastructure-showcase、affaan-m 的 everything-claude-code。
  - 都围绕 agents、skills、hooks、rules、MCP configs 等组件搭建。
- 结论：真正成熟的 AI 编程工作流 = 把模型嵌入一套可复用、可约束、可恢复、可审计的工程系统里。

### 四、Harness Engineering：给 98.4% 命名并升级为学科
#### 4.1 Harness 与中心公式
- 2026 年 2 月 11 日，OpenAI 官博文章《Harness engineering: leveraging Codex in an agent-first world》；Anthropic 围绕这个概念重新调整 Claude Code 架构思路。
  - Martin Fowler 网站凝练成公式：Agent = Model + Harness。
- Harness 来自马术，指马的整套挽具：缰绳、马嚼子、马鞍、笼头。
  - 类比：模型再强也不知道在你的代码库里该往哪儿走；Harness 是你为它造的方向盘+刹车+导航。
#### 4.2 OpenAI Frontier 的关键工程实践
- 层级架构强约束：Types → Config → Repo → Service → Runtime → UI，依赖关系单向流动，由 linter 在 CI 层强制执行；Agent 写出违反层级的代码，直接构建失败。
- linter 错误信息本身是修复指令。
  - 普通项目：“violation detected”——给人看的。
  - OpenAI Frontier：“use logger.info({event: 'name', ...data}) instead of console.log”——给 Agent 看的、可以直接读懂并修复的指令。
- 文档作为单一事实来源：所有架构图、execution plans、设计规范都在仓库内部的 docs/ 目录；Agent 不需要任何外部知识库。
#### 4.3 生产级效果与算账
- OpenAI Frontier：从空 repo 起步的内部 beta，约 5 个月内由 Codex 生成约 100 万行代码、约 1500 个 PR；团队 3 人扩到 7 人，人工不直接写代码。
  - Ryan Lopopolo 称这套工作流已接近“0 人工代码、0 人工 review”的极限形态；与其节省 token，不如用模型极高的并发能力和极低的成本，去替代人类有限且昂贵的同步注意力。
- Stripe Minions：内部自动化代码代理系统，每周生成并推动超过 1300 个 PR 合并；代码从头到尾由 AI 生成，但仍经人工 review。
- LangChain 没换模型，只调 harness（系统提示、工具、中间件、推理模式），把 Terminal Bench 2.0 分数从 52.8 提到 66.5。

### 五、对普通开发者：为 AI 造项目大脑
#### 5.1 三件事
- 在最重要的项目根目录建一个 CLAUDE.md：不需要完美，也不需要很长；写下架构规则、命名约定、测试要求、反复踩过的坑，10 分钟能写完一个能用的版本；下次 AI 犯错时先问自己 CLAUDE.md 里缺了什么。
- 把每天重复做的事改造成 skill：code review、生成 commit message、写发布说明、修一类重复的 bug。
- 在容易踩坑的地方加一个 hook：Hook 是 98.4% 里最有杠杆的那部分；把人类工程师的判断力翻译成机器可读约束。
#### 5.2 核心判断与能力曲线
- 这件事的核心不在写代码，而在写规则。
- Karpathy 今年 1 月推特金句：“我已经从 80% 手动写代码变成了 80% 交给 Agent 写。”
- 未来五年，工程师的能力曲线正在从“我能写多少行代码”转向“我能为 AI 设计多严格的工作环境”。
  - 写代码的活儿正在被 Agent 接管，但设计那个让 Agent 能写出好代码的世界，还是人的工作——而且比以前更难、更重要、也更有意思。

## 作者边界、反例与不确定性
- 1.6% vs 98.4% 不是说模型只贡献 1.6% 的能力，而是说明 Claude Code 作为产品，大量复杂度不在模型本身，而在围绕它的工程基建上。
- 截图并非“泄露”：它是 Anthropic 官方文档公开推荐的标准范式；社区已讨论数月，很多资深开发者才意识到能这么用。
- Stripe Minions 的代码从头到尾由 AI 生成，但仍经人工 review；OpenAI Frontier 是接近“0 人工代码、0 人工 review”的极限形态，两者在人工 review 上有差异。
- 普通开发者的 CLAUDE.md/skills/hooks 结构与 OpenAI、Stripe 同范式，只是规模小得多。
- 论文数据针对 Claude Code v2.1.88 的 51.2 万行 TypeScript 源码；材料未把它扩展为所有 agent 产品、所有模型能力的普遍结论。
- 原文未给出反方证据或失败案例。
