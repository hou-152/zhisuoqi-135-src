# Harness Engineering vs Agentic Engineering：两种工程范式的概念辨析

## 一句话主旨
Harness 与 Agentic Engineering 指向不同抽象层级，前者是地基，后者是地基上的工作流。

## 作者试图回答的问题
Harness Engineering 与 Agentic Engineering 这两个 2026 年初几乎同时火起来的概念，区别在哪、关系是什么？作者侧重厘清二者分属的抽象层级，并给出自己的立场。

## 三级论证骨架

### 一、核心命题：二者指向不同抽象层级
- Agentic Engineering 回答的是「人类如何与 AI Agent 协作来做软件开发？」——一种**工作方式（practice）**。
- Harness Engineering 回答的是「如何设计让 Agent 可靠运行的环境和基础设施？」——一门**系统设计学科（discipline）**。
  - 作者用骑马比喻区分：Agentic Engineering 是说「我们现在骑马出行了，不再步行」；Harness Engineering 是说「马鞍、缰绳、马蹬怎么设计，马才不会把你甩下去」。

### 二、两个概念各自的内涵

#### 2.1 Agentic Engineering（智能体工程）
- 命名者 Andrej Karpathy（2026.01），对标 Vibe Coding（随性编码）。
- Simon Willison 定义：在编码 Agent 辅助下开发软件的实践（Claude Code、OpenAI Codex、Gemini CLI 等）。
- Karpathy 认为行业已超越 Vibe Coding，走向更结构化：「Agent 编排写代码，人类开发者监督和验证输出」。
- 核心关切是**角色转换**——工程师从 creator 变为 curator。
  - 花更少时间写基础代码；花更多时间编排 Agent 组合、定义目标和护栏、验证输出。
  - 核心技能从语法变成系统思维。

#### 2.2 Harness Engineering（驾具工程）
- 命名者 Mitchell Hashimoto（2026.02），对标 Prompt/Context Engineering，抽象层级更高：从「单次调用优化」升级到「系统级运行环境设计」。
- 不关心人机协作的工作流问题，关心如何设计**约束、工具链、反馈循环、文档系统和生命周期管理**，使 Agent 在数千次迭代中始终产出正确、可审计、可恢复、可扩展的工作。
- 关键证据：LangChain 的编码 Agent 在 Terminal Bench 2.0 上从 Top 30 跃升至 Top 5——**没换模型，只改了 Harness**。
- 核心产出物（即 Harness）：Linter、AGENTS.md、CI 管道、skill 系统等基础设施。

### 三、层级关系：两种视角，作者倾向 B

#### 3.1 视角 A：Agentic Engineering 是上层大伞，Harness 是子集
- Simon Willison 把 harness 看作 agentic engineering 实践中的一部分。
  - 其说法：「LLM 不会从过去的错误中学习，但编码 Agent 可以——前提是我们刻意更新指令和工具 harness 来适应所学」。

#### 3.2 视角 B：Harness 是底层基础设施，Agentic 是上层工作流
- 编排是操作的大脑，harness 是手和基础设施；Harness 是地基，Agentic 的上层实践都建立在 Harness 提供的可靠性之上。
- 作者倾向 B 的理由：几周就能微调出有竞争力的模型，但构建生产级 Harness 需要几个月甚至几年。
  - 「Harness 是护城河，Agentic Engineering 是护城河之上的城堡。」

### 四、Bitter Lesson 的张力：质疑与反驳
- Noam Brown 的反论：人们在推理模型上构建脚手架，但这些脚手架最终可能被更强大的模型取代（经典苦涩教训）。
- 作者的反驳：Harness 不只是弥补模型缺陷，它还在做**治理（governance）**——权限控制、审计追踪、合规性验证；模型能力越强、自主性越高，这些需求反而**更加重要**。

### 五、实践映射
- 设计多 Agent 架构的角色分工与工作流 → **Agentic Engineering**。
- 配置 skill 系统、MEMORY.md、Heartbeat 机制、接口 → **Harness Engineering**。
- 最简类比：Agentic Engineering 是管理学（如何带团队），Harness Engineering 是工程学（如何造工厂）。
- 结论：两者都需要，但工厂地基没打好，管理再好也出不了合格产品。
