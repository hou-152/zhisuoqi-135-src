# OpenAI Agents SDK 下一代演进：原生沙箱 + 模型原生 harness

## 一句话主旨
Agents SDK 引入 model-native harness 与原生沙箱，以 harness–compute 分离实现安全、持久、可扩展的生产级 agent。

## 作者试图回答的问题
- **核心问题**：开发者从 prototype 走向 production 时，光有最强模型还不够，需要怎样的基础设施来支撑 agent 检查文件、运行命令、写代码并跨多步持续工作？
- **子问题**：现有三类方案（model-agnostic frameworks、model-provider SDKs、managed agent APIs）各自的短板是什么？如何用一套标准化基础设施同时解决易上手与模型能力释放的矛盾？harness 与 compute 为什么要分离？

## 三级论证骨架

### 一、问题背景：production 需要新 harness
#### 1.1 有用的 agent 需要系统性支撑
- agent 要能做四件事：检查文件（inspect files）、运行命令（run commands）、写代码（write code）、跨多步持续工作（keep working across many steps）。
- 光有 strongest model 不够，还需要支撑这些行为的系统。

#### 1.2 现有三种方案各有 tradeoffs
- **Model-agnostic frameworks**：灵活，但不能充分发挥 frontier model 的能力。
- **Model-provider SDKs**：离模型更近，但对 harness 缺乏足够可见性。
- **Managed agent APIs**：部署简单，但限制 agent 运行位置和敏感数据访问方式。
- 三者共同指向一个缺口：缺少既贴近模型、又对 harness 有掌控力的基础设施。

#### 1.3 OpenAI 的答案：标准化基础设施
- 三个设计目标：easy to get started、built correctly for OpenAI models、提供 **model-native harness + native sandbox execution**。
- 定位是 standardized infrastructure，不是模型本身，也不是完整产品。

### 二、核心能力一：更强的 agent loop harness
#### 2.1 harness 的新能力
- **configurable memory**：可配置记忆。
- **sandbox-aware orchestration**：感知沙箱的编排。
- **Codex-like filesystem tools**：类 Codex 的文件系统工具。
- **standardized integrations**：与 frontier agent 系统常见 primitives 的标准化集成。

#### 2.2 内置标准化 agentic primitives
- 五个核心构件被内置：
  - **MCP**：工具调用；
  - **skills**：progressive disclosure（渐进式披露）；
  - **AGENTS.md**：自定义指令；
  - **shell tool**：代码执行；
  - **apply patch tool**：文件编辑。
- 这些 primitives 正在成为 frontier agent 系统的通用底层；内置后开发者能“spend less time on core infrastructure, more time on domain-specific logic”。

#### 2.3 设计哲学：对齐模型的自然执行模式
- 让 execution 与模型最擅长的工作方式对齐（“aligning execution with the way those models perform best”）。
- 目的在于提升 reliability 与 performance，尤其是 long-running 或跨多工具协调的复杂任务。

#### 2.4 turnkey yet flexible
- 设计哲学：turnkey yet flexible——即开即用，但允许适配自己的 stack。
- 可自定义 tool use、memory、sandbox environment。

### 三、核心能力二：原生沙箱执行（Native Sandbox Execution）
#### 3.1 为什么需要 sandbox
- 许多有用的 agent 需要一个 workspace：读写文件、安装依赖、运行代码、安全使用工具。
- 过去开发者要自己拼凑 execution layer；现在 SDK 直接内置。

#### 3.2 支持 BYO sandbox 或内置 providers
- 可 bring your own sandbox，或直接使用内置支持：Blaxel、Cloudflare、Daytona、E2B、Modal、Runloop、Vercel。

#### 3.3 Manifest 抽象：可移植的 workspace 描述
- Manifest 用于声明工作空间：mount 本地文件、定义输出目录、从云存储拉数据（AWS S3、Google Cloud Storage、Azure Blob Storage、Cloudflare R2）。
- 给模型一个 **predictable workspace**：明确 input 在哪、output 写哪、长任务如何组织。
- Manifest 是 harness 与 sandbox 之间的声明式契约，使环境跨 provider 可移植。

### 四、关键架构决策：Harness 与 Compute 分离
#### 4.1 安全：防 prompt-injection 与 exfiltration
- 设计前提：“Agent systems should be designed assuming prompt-injection and exfiltration attempts.”——默认假设每次输入都可能被污染、每次输出都可能被窃取。
- 分离 harness 和 compute 能让 credentials 远离 model-generated code 执行的环境，抬高风险。

#### 4.2 持久：durable execution
- agent 的 state 被外部化后，“losing a sandbox container does not mean losing the run”。
- 内置 **snapshotting + rehydration**：在原环境失败或过期时，可在新容器里从上一个 checkpoint 继续。

#### 4.3 可扩展：scale-out 执行
- 一个 agent run 可以用一个或多个 sandbox；按需 invoke sandbox。
- 把 subagent 路由到隔离环境，跨容器并行化，加速执行。

### 五、定价、路线图与客户反馈
#### 5.1 定价与可用性
- 所有客户通过 API 通用可用（GA）；使用标准 API pricing，按 tokens + tool use 计费。

#### 5.2 路线图
- 首发 Python；TypeScript 即将跟进。
- 即将加入 **code mode** 与 **subagents**（Python + TypeScript 双端）。
- 更多 sandbox providers、更多集成、更多生态入口。

#### 5.3 客户反馈（Oscar Health）
- 新 SDK 使关键临床记录工作流得以 production 化，此前方案可靠性不够。
- 关键不在能否提取元数据，而在于能否正确理解每一次 encounter 的边界。
  - 引述者：Rachael Burns, Staff Engineer & AI Tech Lead, Oscar Health。

### 六、整理者解读：OpenAI 的 agent engineering 三层观（非原文明确表述）
#### 6.1 三层架构
- **Model 层**：frontier model 提供认知能力。
- **Harness 层**（重点）：model-native，承载 agent loop、memory、tool use、filesystem、primitives。
- **Compute 层**（重点）：sandbox 提供隔离、持久、可扩展的执行环境。
- 核心洞见：harness 与 compute **解耦**——既释放 frontier model 能力，又满足 security、durability、scale 硬要求。

#### 6.2 概念网络的关键关系
- harness 包含 agent loop；memory、tool use、filesystem 服务于这个 loop。
- primitives（MCP、skills、AGENTS.md、shell、apply patch）构成 harness 的“能力工具箱”。
- Manifest 桥接 harness 与 sandbox，是声明式契约。
- harness–compute 分离同时实现三个特性：security、durability、scale。
- 张力关系：model-native 对押 model-agnostic——前者的选择暴露 OpenAI 对“agent 未来是 model-native”的赌注。
- subagents 是 scale 的关键：子 agent 跨 sandbox 分发，配合分离架构形成可横向扩展的系统。
