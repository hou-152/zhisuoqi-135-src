这篇文章在回答：让 Claude 长时间自主干活时，怎么避免它越干越糊、还总觉得自己干得挺好？答案是给它套一层“脚手架”，把干活的 agent 和打分的 agent 分开，并在上下文快满时换人接力。

核心机制是：模型干久了，上下文窗口塞满会产生“焦虑”，提前草草收尾，所以用“上下文重置”——彻底清空，让新 agent 拿着交接文件继续。更关键的是，模型评价自己的作品时会自信地夸赞平庸结果，所以把生成者和评估者分离，借鉴对抗网络的思路：生成者干活，评估者用一份写清设计原则的评分表严格挑刺，再把批评反馈回去，生成者就有了具体改进目标。

好比学生写论文，自己越看越满意，于是请一位严格的编辑按清单挑毛病；每写一章前还先约定“什么叫写完”，免得白干。

作者承认的代价是：脚手架里每个零件都假设“模型自己做不到某件事”，这些假设会过时；随着模型变强，有些零件得拆掉，而且评估者只在任务超出模型可靠边界时才有价值，边界内就是多余开销。
