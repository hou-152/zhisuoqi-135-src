# 检索与推理的双任务负担

> 塞入完整聊天历史等于要求模型一次调用里同时做长文定位与推理，差值即检索代价。

**领域** context-engineering ｜ **类型** CONCEPTUAL ｜ **什么时候学** 做到这里再懂 ｜ **怎么算会了** 能判 ｜ **中心度** 0.017

## 费曼一下

这解释了为什么「把所有历史都塞进去」不是省事而是加活。你没有帮模型准备好材料，你只是把找材料的工作也外包给了它，而它并不擅长在一次前向里既当图书管理员又当分析师。RAG 的价值不在省 token，在于把两件事拆开。

## 原文 context

LongMemEval 部分的核心机制解释。把完整聊天历史塞进 prompt，等于要求模型在一次调用里同时做两件事：先在长文本中定位相关片段，再据此推理。对照实验里 focused input 平均约 300 token（只需推理），full input 约 113k token（必须先检索）。先验证模型在 focused 上完全能做对，再看到 full 上一致的下滑——差值就是那一步检索的代价。开启 thinking mode 能同时抬高两者，但落差不消失。

## 掌握证据（做到这些才算会）

- 能对比 focused 约 300 token 与 full 约 113k token 的落差
- 能说明 thinking mode 抬高两者但落差不消失
