# 上下文骨架

> Linear 的自我定位：不做厨房点单式的 issue 追踪，而做收集信号、问题与决策、引导 agent 的可依赖骨架。

**领域** context-engineering ｜ **类型** REPRESENTATIONAL ｜ **什么时候学** 做到这里再懂 ｜ **怎么算会了** 能判 ｜ **中心度** 0.017

## 费曼一下

当你能同时指挥一百万个 agent 干活，真正稀缺的不是“手”，而是“该干什么”的清晰指令和背景。骨架就是那套让所有 agent 站得住、对得齐的中轴：它不亲自砌砖，但决定了砖往哪儿砌。工单系统只管“把菜端出去”，骨架管的是“这家店为什么做这道菜、接下来该上什么”。

## 原文 context

Karri 用来概括 Linear 新使命的说法——“Linear 成为引导 agent、构建这种上下文的系统”。它和一个被推翻的旧隐喻对立：过去人们把 issue tracking 当成厨房点单系统（点了鱼，票进厨房“做鱼”），而 Linear 把自己看作“可依赖的骨架”，负责收集信号、问题和决策。

## 掌握证据（做到这些才算会）

- 能复述被推翻的「点单系统」旧隐喻与它的不足
- 能说出「骨架」定位下系统该收集和沉淀什么
