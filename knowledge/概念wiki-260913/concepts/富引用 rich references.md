# 富引用 · rich references

> spec 引用不限于简单 markdown，可用 HTML artifact、测试套件、待移植函数、rubric，且优先选代码形态。

**领域** spec-intent ｜ **类型** CONCEPTUAL ｜ **什么时候学** 做到这里再懂 ｜ **怎么算会了** 能判 ｜ **中心度** 0.035

## 费曼一下

说明书不必是一段文字。一套能跑的测试、一份能渲染的原型，都是更硬的说明书，因为它们不容易被误读。

## 原文 context

第六组 then / now 的落点。从 plan mode 里的简单 markdown 计划文件，扩展到 HTML artifact、详细的测试套件、另一个 codebase 里待移植的函数、rubric——都可以充当 spec。

## 掌握证据（做到这些才算会）

- 能说出为什么代码形态的引用保真度更高
- 能把一段文字需求改写成代码或测试形式的引用

## 验收问句

> 给我写一份 {{name}}：拿什么当 spec 比文字描述更清楚？
