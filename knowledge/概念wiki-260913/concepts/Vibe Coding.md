# Vibe Coding

> 抬高地板式编程范式：用自然语言描述需求由 agent 生成代码，适合原型与小工具，不适合严肃工程。

**领域** code-engineering ｜ **类型** CONCEPTUAL ｜ **什么时候学** 做到这里再懂 ｜ **怎么算会了** 能判 ｜ **中心度** 0.06

## 费曼一下

“跟着感觉走”式的编程——把需求抛给 AI，不统规划、不结构化、不严格审查。是 Agentic Engineering 的前一个阶段，Karpathy 以它为对标来定义 Agentic Engineering 的进化方向。

## 原文 context

<mention-page url="https://app.notion.com/p/202679b108ff8386979a01933594c9bc"/>
> Vibe coding raises the floor. It lets almost anyone create software by describing what they want.
**费曼一下**：Karpathy 2025 年初造的词，指 **"抬高地板"** 的编程范式——让几乎任何人都能用自然语言描述需求，由 agent 把代码生出来。
适合 prototype、个人小工具、玩票项目；不适合需要保住质量底线的严肃工程（那是 **Agentic Engineering** 的活）。
2026 年 Karpathy 进一步说：vibe coding 抬高地板，但不允许放弃质量。
---
来源：<mention-page url="https://app.notion.com/p/d6d679b108ff82debc5181b2c1ced4ff"/>（Sequoia AI Ascent 演讲原文）
> December was this clear point... I just trusted the system more and more, and then I was vibe coding. It was a very stark transition.
**费曼一下（2026-05-03 补充）**：Karpathy 在原文里指出 **December 2024** 是他个人进入 vibe coding 状态的 stark transition——最新模型的代码块「出来就是对的」。提醒：很多人对 AI 的认知还停在 2024 年初的 ChatGPT 时代，需要「重新看一眼」——agentic coherent workflow 真正开始 work 是在 December。**"你不能因为 vibe coding 就引入安全漏洞"**——你仍然对你的软件负责。
