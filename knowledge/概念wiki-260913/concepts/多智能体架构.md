# 多智能体架构

> 把任务拆给多个各司其职的 agent：场景生成→角色扮演→行为提取→评分，逐层可替换。

**领域** multi-agent ｜ **类型** CONCEPTUAL ｜ **什么时候学** 做到这里再懂 ｜ **怎么算会了** 能用 ｜ **中心度** 0.267

## 原文 context

源自：<mention-page url="https://app.notion.com/p/92e679b108ff82bab54201af8ed3171e"/>
- **context**：
	> Vantage 不是一个 AI 在干活，而是一群 AI 在演戏，该系统的精巧之处在于架构设计……搭了一个四层架构，每层都有 AI 各司其职，同时运转。
- **费曼一下**：不是一个 AI 包办所有事，而是把任务拆给多个 agent 各领其职：场景生成 → 角色扮演 → 行为提取 → 评分。模块化解耦让场景、角色、量表都可替换——本质上，是把「微服务架构」搬到了教育评估里。

## 掌握证据（做到这些才算会）

- 能画出四层各司其职且同时运转的架构
- 能说明模块解耦让场景、角色、量表都可替换

## 先懂这些（前置 1）

- [[单 agent 的速度天花板]] · **soft** — 不懂单 agent 慢在哪，就说不清为何要引入多 Agent

## 懂了它才能懂（解锁 9）

- [[子 Agent 分工]] — 分工是把任务拆给多个 Agent，没有多 Agent 架构就无从分工
- [[Handoffs Agents as tools]] — 委派机制只在多个 Agent 并存时才成立
- [[动态协调 dynamic coordination]] — 动态协调是多个 Agent 互相观察行为并决策，前提是多 Agent
- [[Executive LLM]] — 它是多 agent 系统里的一个角色，没有该架构就无从谈起。
- [[integrator 瓶颈]] — 瓶颈来自大量并行 worker 争抢同一合并闸口，需先懂该架构。
- [[Orchestra Interface]] — 像指挥家协调多个 Agent，前提是存在多 Agent 协作体系。
- [[共享 多人 agent 会话]] — 多人会话建立在多 agent 共同工作的架构之上。
- [[意图理解、路由与升级 understand intent, route, escalate]] — 路由与升级的前提是有多个各司其职的 agent 可供分派。
- [[Symphony]] — 它是编排多个 Agent 的持久化运行时，前提是多 Agent 架构。
