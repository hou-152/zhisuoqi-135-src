# 文件系统即持久记忆

> 把耐久状态（日志、diff、错误 trace）写进文件系统而非塞进 context，靠 bash 读写即可续跑长任务。

**领域** state-persistence ｜ **类型** CONCEPTUAL ｜ **什么时候学** 现在先懂 ｜ **怎么算会了** 能用 ｜ **中心度** 0.263

## 费曼一下

脑子记不住那么多，就把东西写在纸上放进抽屉。抽屉不占脑容量，需要时再翻出来；而且「翻抽屉」这项技能，模型本来就越练越熟。

## 原文 context

Pattern 2。harness 不该把整条工作流和全部日志扛在 context 里，而应把耐久状态放进文件；长时程 rollout 中实验日志、代码 diff、错误 trace 常远超训练时的 context 窗口。作者补充：读写编辑文件系统（常通过 bash）是 LLM 的基础技能，因此这种朴素形态能天然吃到核心模型能力提升的红利。

## 掌握证据（做到这些才算会）

- 能把一次长任务的日志与 diff 落到文件，并在新会话中读回继续
- 能说明长时程 rollout 的状态放文件为何比扛在 context 里更可靠

## 验收问句

> 不给 {{name}} 的完整历史，你能只靠文件把长任务接着跑下去吗？

## 懂了它才能懂（解锁 9）

- [[本地状态层]] — 本地状态目录把 todo 存 json、消息存 sqlite 文件，本质是文件系统持久记忆。
- [[状态子系统与进度持久化]] — 用 progress.md、feature_list 等写磁盘，需先懂文件系统即持久记忆。
- [[Git-backed state]] — 把循环状态落在 git 中，git 本身基于文件系统，不懂文件持久记忆无法理解。
- [[Shared File System]] — 多 session 共用文件夹系统记录状态，需先懂文件系统作为持久记忆。
- [[状态子系统与进度持久化]] — 进度靠 progress.md 等文件留存，不懂“文件即记忆”就不知进度存哪、下次怎么续跑。
- [[agent 模板的声明式持久化]] — 声明式配置以文件承载，懂文件系统持久记忆有帮助。
- [[Git-backed state]] — git 状态最终落地为工作区文件，先懂状态以文件持久才懂 git 提供的显式持久性。
- [[Artifact Schema]] — artifacts 以文件加 README/schema 落地为共享知识层，依赖把状态写进文件系统。
- [[agent 模板的声明式持久化]] — 模板以 YAML 存进 git 文件并由 CLI apply，先懂状态以文件持久才懂声明式持久化。
