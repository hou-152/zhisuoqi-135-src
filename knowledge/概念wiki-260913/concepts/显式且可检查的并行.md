# 显式且可检查的并行

> harness 派生多个 subagent 并行执行并监控后台作业，父 agent 需小型进程管理器负责启动、看日志、取消、合并。

**领域** multi-agent ｜ **类型** CONCEPTUAL ｜ **什么时候学** 做到这里再懂 ｜ **怎么算会了** 能判 ｜ **中心度** 0.126

## 费曼一下

几个人同时干活可以，但要有工单和交接记录。全靠口头说，一断线就全丢了。

## 原文 context

Pattern 3 的关键设计选择。harness 可派生多个 subagent 并行执行、监控后台作业，父 agent 需要一个小型进程管理器（启动、看日志、取消、合并）。如果 subagent 输出只活在临时对话 context 里，很快变得过时且不可见；存成文件、日志和状态记录，模型才能在中断后恢复并对自己的执行历史推理。

## 掌握证据（做到这些才算会）

- 能列出父 agent 进程管理器至少四项职责
- 能说明为何 subagent 输出不能只存在临时对话 context 里

## 验收问句

> 若 subagent 输出只留在临时上下文，会有哪些具体后果？请结合 {{name}} 说明。
