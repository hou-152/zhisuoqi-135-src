# 阶段压缩 · compression

> agent 吸收程序性工作后，原本分离的规划、实现、代码评审三个阶段开始合并压缩。

**领域** agent-org ｜ **类型** CONCEPTUAL ｜ **什么时候学** 做到这里再懂 ｜ **怎么算会了** 能判 ｜ **中心度** 0.017

## 费曼一下

过去写软件像接力赛：先规划、再实现、再评审，一棒一棒交。agent 能同时插手这几段活儿，于是几个阶段被挤到一起、几乎同时发生，中间的等待和交接被压扁了。整个链条从"串行"变得更像"并行"。

## 原文 context

agent 把"移除开销"推得更远的机制。随着 agent 吸收程序性工作，规划、实现、代码评审（planning, implementation, and code review）三个原本分离的阶段"开始压缩（begin to compress）"。

## 掌握证据（做到这些才算会）

- 能说出被压缩的三个阶段名称
- 能解释压缩为何发生——agent 接管了程序性工作
