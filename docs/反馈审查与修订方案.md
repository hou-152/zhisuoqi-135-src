# 知所栖 · 反馈审查与修订方案

日期为 2026-09-06。审查范围是用户提供的 README 反馈、当前 `prototype/知所栖-demo.html` 代码和已有验证记录。用户本轮选择先做审查与方案，状态规则讨论后再改 Demo；因此本文不修改原型行为。

## 审查结论

这版已经足够作为一条固定镜头课程的交互原型。反馈指出的主要风险成立。产品对外说的是“从问题找到需要补的知识”，代码当前主要实现的是“问题作为入口，进入同一组预设概念”。这属于原型范围取舍，暂时不能当作产品方向已经被证伪；下一轮要独立检查问题是否真正参与了学习过程。

当前最需要讨论的三段连接如下。

1. 用户的问题怎样变成一个可解释的学习目标。
2. 学习结果怎样回到这个问题，并说明哪些地方仍未解决。
3. 记录怎样区分发生过的事实、最近一次判断和下一次要继续的任务。

在这三点定下来以前，扩充课程数量、接入完整知识树或增加成就类型，都不是优先事项。

## 代码中已经确认的事实

### 问题确实被保存，但参与程度有限

- `state.question` 会在开始课程时写入，课程页顶部会显示它，暂停断点也会保存它，学习卡导出也会包含它。
- 选择预设问题时，3 个概念的课程顺序可以不同；输入自定义问题只通过关键词判断是否属于镜头范围，再映射到景别、运镜或提示词这套预设课程。
- 输入问题不会生成新的学习目标、解释一处具体困难，或改变题目、案例和组合练习的内容。页面会提示“按关键词进入预设镜头课程；目前没有实时 AI 回答”。
- 3 个概念完成后的结束页会给出另一道固定的组合应用，提示下一步做真实作品；它没有复述用户原问题，也没有填写“这个问题已经改善了哪一部分”和“还剩什么不确定”。

因此，当前页面能够验证“固定课程是否容易进入和完成”，只能部分验证“问题是否帮助用户找到需要补的知识”。

### 记录同时包含概念证据与任务状态

当前状态字段包括 `read`、`passed`、`attempts`、`lastAnswers`、`transfer` 和 `question`。

- `read` 表示点击过“读完了”，是一个累计动作记录。
- `attempts` 保存每个概念的作答次数，`lastAnswers` 只保留每个概念最近一次选项。
- `passed` 表示最近一次答案正确的概念集合。答错会移除该概念；同时清除组合练习结果。
- `transfer` 保存当前组合练习的最后一次结果。
- 开始另一个问题时，`START` 会保留 `read`、`passed`、`attempts`、`lastAnswers` 和 `transfer`，只更换问题和课程顺序。
- 暂停时才把完整状态写入 `localStorage`。意外刷新或关闭前的最新操作不一定进入断点；后续方向备注也不写入断点。

这意味着“同一概念的证据可以复用”已经是代码事实，但“一个任务的完成结果是否可以直接带到另一个问题”仍是产品语义问题。尤其是 `transfer` 目前会随新问题一起保留，不能仅凭“概念 ID 稳定”就推断这一定合理。

### 当前进度的准确含义

`1 / 3` 表示 3 个固定概念中，最近一次检验通过的概念数。它不表示读过多少，也不表示累计完成过多少，更不表示长期掌握。答错后下降符合“最近检验状态”的解释；如果把它讲成“已经完成的学习步骤”，下降就会产生误解。

当前页面已经写了“本题通过”与“这里不评价长期掌握程度”，但还没有把“历史上曾经答对”和“最近一次需要再检验”同时呈现出来。

## 决策表

下面这些项目分开记录，避免把实现现状误认为团队共识。

| 项目 | 当前状态 | 本轮建议 | 需要团队决定 |
|---|---|---|---|
| 围绕当前目标、固定任务分母、按需探索 | 用户已确认方向 | 保留 | 暂无 |
| 3 个概念、1 个组合练习 | 原型选择 | 暂时保留用于测试 | 是否足以验证“问题驱动学习” |
| 18 个节点、27 条候选关系、每侧最多 3 个邻居 | 原型选择，关系为 `soft` | 暂时保留 | 3 个是否是可用预算；建议关系与个人补习如何区分 |
| 问题与课程的关系 | 当前是关键词匹配到预设课程 | 先补可见的“问题依据”和结束回看 | 只做上下文，还是要产生可解释的学习目标 |
| 概念证据跨问题复用 | 当前复用 `read`、`passed`、作答次数 | 保留概念层证据的候选方案 | 哪些证据可继承，哪些必须按任务重新产生 |
| 组合练习跨问题复用 | 当前随 `START` 保留 | 暂不视为确定规则 | 每个问题是否必须重新完成应用任务 |
| `passed` 答错后下降 | 当前表示最近一次检验通过 | 文案明确“当前检验状态” | 是否另存历史达成，不覆盖发生过的答案事实 |
| 中断恢复 | 主动暂停才保存当前浏览器断点 | 优先讨论自动保存或离开前保存 | 保存哪些字段，何时提示隐私与清除 |
| 继续学习的最低标准 | 当前有问题、位置、阅读和作答记录 | 增加可检查的恢复清单 | 是否需要保存用户产出与未解决点 |
| 来源与内容性质 | 手写示例，未接知乎或模型 | 保持诚实标注 | 真实资料入场前的许可、引用和冲突规则 |

## 建议的修订顺序

这是方案，不是已经承诺的开发排期。

### 第一阶段，先把一条问题驱动过程说完整

不需要先接模型。选一个真实问题，人工写出它与 3 个概念的对应关系，并在页面上显示下面四项。

- 你刚才的问题是什么。
- 这次先检查哪一个可能相关的概念，以及依据是什么。
- 这个概念学完后，回到原问题时可以重新检查哪一部分。
- 目前仍然没有检查到什么。

结束页增加一段回看，让用户用自己的话写一句“我现在会怎样处理原问题”。这段文字先作为本地临时产出，不自动判定正确。这样可以检验问题是否一直在场，也不会把预设课程包装成动态诊断。

### 第二阶段，先确定记录语义，再改数据结构

建议先用一张规则表拍板，再决定是否增加字段。

- **发生过的事实**，某次作答选了什么、是否答对、何时发生。
- **当前状态**，最近一次检验是否通过，是否需要再检验。
- **任务产出**，某个具体问题下的镜头描述或组合练习结果。
- **概念证据**，阅读动作、解释能力、不同情境中的表现，哪些可以跨任务参考。

最小可行的候选结构是保留当前概念摘要，同时增加按任务或问题区分的作答历史与产出记录。是否保存完整事件、保存多久、如何迁移概念改版，都在团队决定之后处理。不要直接把一个新的布尔值当成永久掌握。

### 第三阶段，检验“继续”是否真的恢复上下文

先不做账号和跨设备。优先验证当前浏览器中的一次意外中断，至少检查以下内容。

1. 用户的问题仍然看得见。
2. 当前目标和已经尝试过的概念仍然看得见。
3. 用户知道哪一步还没有完成。
4. 用户能找到自己的上一份表达或练习结果。
5. 页面给出下一步，而不是只把人带回某个 URL。

如果自动保存会改变隐私提示或清除方式，应一并设计。当前“主动暂停才保存”可以继续作为原型限制，但不宜把它说成已经完成了完整的继续学习体验。

### 第四阶段，再验证教学是否真的带来变化

给同一位试用者一个学习前的新情境记录，再给一个学习后的相近但不同情境。评价先采用人工可检查的维度。

- 是否说清观众先看到什么、随后知道什么。
- 画面范围和镜头变化是否支持信息顺序。
- 是否能解释选择和目标的关系，而不只是复述术语。

这些维度是本轮评审建议，不是经过验证的量表。记录原话、帮助次数和评价理由；不能只记录最后答对没有。

## 暂时不改的部分

- 不恢复整棵知识树的全局完成百分比。
- 不默认展开全部前置关系。
- 不因为反馈提出了状态历史，就马上扩充到所有主题和永久成就。
- 不把 Marble 的课程数据、规模或许可当作本项目关系有效性的证明。
- 不把小能熊公开页面的组织方式当作用户学习成效证据。
- 不在真实资料、主办方规则和内容许可尚未确认前接入知乎或第三方语料。

## 本轮应留下的验收标准

在下次修改前，团队至少要对下面 5 句话逐条给出“同意／修改”。

1. 原问题是否必须在课程、应用和结束回看中持续显示。
2. 跨问题时，概念证据、任务产出和组合结果分别怎样处理。
3. `1 / 3` 的正式文案是否定义为“当前检验通过数”。
4. 历史作答事实是否保留，最近状态是否单独呈现。
5. “可以继续”是否至少包含原问题、当前位置、已有尝试、未解决点和下一步。

五项没有定下来以前，不改状态转换，不扩充课程，不接真实模型。定下来以后，再做最小修改，并按新标准重新验证。

## 依据与限制

本审查依据当前 HTML、README、`docs/从-Demo-倒推讨论.md`、v3 验证记录、公网发布记录，以及用户本轮粘贴的反馈。没有把反馈文档中“尚未读取线上页面”的判断当作当前 Demo 的事实；代码事实以当前文件为准。原始会议是自动转写和二次整理，人物归属、第三方资料许可和完整产品架构仍有不确定性。

## 本轮拟合落地（2026-09-06）

本轮按源文件与聊天记录的共同语义做了最小拟合：

- 产品定位改回“从问题出发，理解概念之间的关系，让自己的知识树逐步生长”。
- 首页和知识体系页补充“问题会接回知识树”“本次留下的概念”等说明，避免把任务进度说成全部学习结果。
- 左侧第三栏由“讨论清单”改名为“后续方向”，用于承载可能继续聊天、探索和验证的候选方向；它不进入学习状态，也不代表已确定规则。
- 保留当前 3 个概念、固定任务进度、局部关系和主动暂停等 Demo 状态规则；没有在未讨论前修改状态转换、课程数量或资料接入。

原型文件与部署目录中的静态文件已同步；本轮没有执行新的公网发布。
