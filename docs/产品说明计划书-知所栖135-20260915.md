## 〇、30 秒版本

**知所栖 135**：一个问题 → **3 个概念** → **1 段阅读** → **3 个决策** → **5 个实验** → **费曼验收**（讲不出来，就倒回漏掉的那一维）。

- 它不是知识展示页，也不是让 LLM 自由聊天。它把**两个自有方法论 skill（dbs-learning、dbs-standard-answer）+ 一个概念（费曼验收）**工程化成了 web 产品。

## 一、场景价值：我们解什么问题

**问题**：AI 时代知识过载，人「收藏了 ≠ 学会了」。更根本的：**你意识不到自己缺什么**——而觉察缺口恰恰是学习开始的前提（Loewenstein 1994：觉察缺口是好奇心的前提，人普遍看不见自己的缺口）。

**产品替你做的事**：把「发现缺口 → 补读 → 判断 → 动手 → 讲出来验收」变成一条机器记账、人做判断的流水线：

1. **1 阅读**（dbs-learning）：三层内容梯度 L1 直觉 / L2 机制 / L3 应用，反馈按钮实时切层。
2. **3 决策**（dbs-standard-answer）：先决策 → 与真实案例同构比较 → 带条件的标准答案表 → 修订。
3. **5 实验**（提取练习）：动手做、写自己的结论。
4. **费曼验收**（不是模块，是验收层）：复述 → 查漏 → **漏点倒回**——AI 接住学生的回答，只补漏的那一维，学生补清后系统接着推进原过程，不重讲整段、不丢上下文。未复述到底时显示「本次尚未验收」，跳过也记「未验收」，不冒充完成。

**学习科学锚点（照实说）**：
- 有效成分是**提取练习 + 反馈**（Yang 2021 元分析：提问练习 g = 0.499）与**反馈-纠正 + 掌握式过关**。
- 我们在解 **Bloom 1984 提出的 2 Sigma 问题**（群体场景下接近一对一辅导）；**不说**「已实现 2 sigma」——VanLehn 2011 把人类辅导效应下修到 d ≈ 0.79，智能辅导 0.76。
- **不说**「费曼技巧被证明有效」（无一手受控证据）；我们实现的是「复述 + 漏点倒回」这个可检验机制。

## 二、核心创作思路：skill → 产品

**先例**：nashsu/llm_wiki 把 Karpathy 的一段公开 prompt 模式做成桌面 app，README 逐条标注「继承/改造/新增」。

**我们做的是同构动作，且方法论是自有的**（skill 随源仓库公开，可装进 Claude Code 当场验证：`claude plugin marketplace add hou-152/zhisuoqi-135-src && claude plugin install dbs-135@zhisuoqi-135`）：

| | llm_wiki | 知所栖 135 |
|---|---|---|
| 抽象模式 | Karpathy 公开 gist（别人的） | dbs-learning + dbs-standard-answer（**自有 skill**）+ 费曼（验收层） |
| 形态 | 桌面 app（Tauri） | web（单文件 HTML ＋ 本地 serve workflow） |
| 方法论去向 | 骨架照抄 + 工程扩展 | 方法论写死编排层：1=三层梯度实时切层，3=同构比较+条件答案表，费曼=复述→漏点→倒回 |
| 底层哲学 | compiled once and kept current，反 RAG | **检索增强判定 workflow，反 agent 全自主** |

**为什么 workflow 而不是 agent**（Anthropic 定义：预定义代码路径编排 = workflow）：我们的步骤可预知（固定六步），不需要自主证据检索，模型只做**单轮判定调用**。对外统一话术：不说「轻量 agent」，说「检索增强的判定 workflow」。评委问为什么不用框架：Anthropic 官方建议直接用 LLM API 起步，框架抽象层遮蔽提示词与响应。

## 三、整体技术方案

### 3.1 数据层：四源融合的概念地图（唯一真源）

- **1070 概念 / 681 前置依赖 / 3410+ 关系 / 21 领域**（四源：Notion 概念库 509 条含逐页正文 ＋ 飞书 Context Engineering 28 篇 ＋ Harness Engineering 30 篇 ＋ AI 内参三期），经 AI 相关性两轮过滤（1156 → 1070，逐条带理由留档可翻案）。
- 七步确定性管线（`scripts/cm-*.mjs`）：抽取 → 合并去重 → LLM 富化（领域/类型/定义/掌握证据/验收问句，带缓存可断点重跑）→ 依赖边+环检测 → 地图/wiki 构建 → 体检（`cm-validate.mjs`）。
- **概念链接层**：1070 页概念 wiki，`[[双链]]` + 反链，丢进 Obsidian 直接可用。
- 每条依赖边带审核结论（yes / weak 降 soft / reversed-fixed）；判否的边留档可翻案。

### 3.2 运行时：全链路 Graph，由边驱动学习

- `knowledge/graph-260914/graph.json`：**4591 节点 / 14487 边**，七层（材料与出处 928 · 五类语义 538 · 公共知识与关系 1091 · 问题与课程编排 409 · 学习活动 1622 · 运行与记录 0 · 模型与规则 3），五种边。
- **只有 `transition` 边能驱动学习状态跳转**——学生每次复述、作答走的都是图里真实注册的流程边；守卫/效果必须按名字查到注册表，查不到就是「系统未判定」，不静默通过。
- 运行器 `scripts/lib/graph-runner.js` **一个文件两处用**：Node 验收脚本直接 require，浏览器壳由构建脚本内联。节点/浏览器行为同源，不是两套实现。
- 教学闭环八机制全部落进运行时并测过：短答承接（保留旧证据）、新矛盾（进补讲重核对）、补讲回归点（从哪发起回哪）、错题回补（回同一题，不自动算对）、即时费曼不解锁、章末门独立、暂停恢复、系统异常不记缺口。

### 3.3 内容层：538 个语义单元 + 内参流水线

- 五类语义单元（问题 141 · 概念 76 · 观点 169 · 案例 76 · 方案 76），76 张图鉴概念卡全部带 `source_ids` 可回溯。
- 内参流水线：原文快照 → 三级笔记 → 概念辞典 → AI 费曼 → 五维拆解，已跑 3 期。
- 六章 Agent Loop 学习空间：6 章 / 18 题 / 18 条章末判据，来源链 58 篇 → 49 个原始来源。

### 3.4 交付形态与质量证据

- **公网版**：单文件零服务端（GitHub Pages），无服务端时判定走机械兜底并如实标注 `mech`——交付稳定性优先。
- **桌面版**：Electron，学习记录落真文件（`~/Documents/知所栖-135/`）。
- **验收脚本体系（全部本机实测通过）**：`verify-135.mjs` 61 项 · `check-graph.mjs` 465 项 · `test-graph.mjs` 281 项 · `check-learning-materials.mjs` 581 项 · `test-learn-agent-loop.mjs` 113 项 · `test-path.mjs` 88 项 · `test-graph-view.mjs` 27 项 · `check-public.mjs` 34 项 等；另有真模型走查脚本（`walk-graph-real.mjs`）逐章真调 LLM 留证据 JSON。
- **诚实边界**（写进产品，不粉饰）：目前所有「学习」证据来自脚本扮演的合成学习者，**真人使用为零**；76 个案例单元是假设场景；模型判定会波动（同一段复述第 2 轮判 met、第 3 轮判 partial，记录在证据里，没有改答案凑绿）；AB 对比实验因缺 10 份真人复述样本未出正式结论。每条正面说法的边界怎么核出来的，见仓库 README「辩证写法」一节。

## 四、与知乎社区生态的契合度与场景价值（重点）

**赛道**：📚 知识炼金场。知乎是中国最大的问答社区——**「一个问题」正是知乎的基本单位，也是知所栖流水线的入口**。

### 已实现

1. **知乎真实内容作为案例与证据源**：`serve-135.mjs` 桥接知乎检索（自建 CLI，`./scripts/zhihu search`），决策场的案例卡来自**真实知乎文章**（含「软文批判」标注——教判断，也顺带做内容质量示范）。
2. **检索增强判定的产品形态与知乎内容天然同构**：概念 → 知乎讨论 → 案例对照 → 条件化标准答案，全程引用可点击回原文，尊重创作者出处。
3. 概念地图与语义单元的底料含大量源自知乎社区讨论的 AI 工程概念（Context Engineering、Harness 等），本身就是知乎内容价值的沉淀。

### 规划中（路演可讲，不冒充已实现）

4. **从知乎问题出发**：在知乎看到一个问题 → 贴进知所栖 → 生成「3 概念 → 1 阅读 → 3 决策 → 5 实验」的学习路线，概念卡反向挂回知乎相关高质量回答。
5. **学习成果回流知乎**：费曼复述通过验收后，一键整理成知乎回答草稿——「学会」的证明就是**能讲给别人听**，知乎正是讲的场所。学习闭环与内容生态在同一张网上闭合。
6. 概念卡「待你看一眼」策展队列可对接知乎收藏夹：收藏≠学会，知所栖把收藏变成带验收的学习路线。

**一句话**：知乎负责「问与答」，知所栖负责「答之前的学习」与「答得出的验收」。

## 五、为什么值得做（市场/人群）

- 目标人群：AI 从业者与重度学习者——收藏夹堆积、看了就忘、无法验证自己是否真会。
- 已有内容资产验证过需求侧：AI 内参三期（Readwise Inbox → 编辑流水线）持续生产，概念地图四源中两源来自真实学习积累。
- 差异化：市面产品要么是「知识管理」（Notion/Obsidian，不验证学会），要么是「AI 陪聊」（无编排、无验收、易幻觉）。知所栖把**方法论写进编排层**，验收不过就是不过，缺口有名字、有出处、有倒回路径。
