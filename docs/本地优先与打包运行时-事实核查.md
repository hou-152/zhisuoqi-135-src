## A. 理论来源

### 理论卡

- **理论名称**：local-first software（本地优先软件）
- **作者与机构**（Crossref 元数据 + SPLASH 2019 程序页一致）：
  - Martin Kleppmann — University of Cambridge, UK
  - Adam Wiggins — Ink & Switch, Germany
  - Peter van Hardenberg — Ink & Switch, USA
  - Mark McGranaghan — Ink & Switch, USA
- **原始出处**：
  - 会议：2019 ACM SIGPLAN International Symposium on New Ideas, New Paradigms, and Reflections on Programming and Software（**Onward! 2019**，SPLASH 2019 的一个 track）
  - 年份：2019-10-23；页码 **154–178**；DOI **10.1145/3359591.3359737**；出版方 ACM
  - 场次（SPLASH 程序页原文）：`When Wed 23 Oct 2019 16:00 - 16:45 at Templars - Onward! Essays - Session 1`，`45m`，类型 `Talk`
  - 作者官方全文页（HTML 版）：<https://www.inkandswitch.com/essay/local-first/>（`/local-first/` 会跳到这里；页面自带 `local-first.pdf`）
  - 作者页给出的引用格式原文：`Martin Kleppmann, Adam Wiggins, Peter van Hardenberg, and Mark McGranaghan. Local-first software: you own your data, in spite of the cloud. 2019 ACM SIGPLAN International Symposium ... (Onward!), October 2019, pages 154–178. doi:10.1145/3359591.3359737`
  - 注：Ink & Switch HTML 页标的写作日期是 `April 2019`，会议出版是 2019 年 10 月，两者不同。
- **七个理想（Onward! 论文原文逐条，标题为原文）**：
  1. **No spinners: your work at your fingertips** — 主副本在本地，所有操作读写本地磁盘，同步在后台悄悄进行，「never needing to show you a spinner」。
  2. **Your work is not trapped on one device** — 数据存本地，但必须跨用户所有设备同步；多数同步服务仍会在服务器留一份副本，单人编辑时工作良好，多人同时编辑同一文件会冲突。
  3. **The network is optional** — 本地优先应用的主副本在设备本地文件系统，离线也能读写，之后有网再同步；同步甚至可走蓝牙/局域网；「for good offline support it is desirable for the software to run as a locally installed executable on your device, rather than a tab in a web browser.」
  4. **Seamless collaboration with your colleagues** — 目标是「real-time collaboration that is on par with the best cloud apps today, or better」；这是实现本地优先「one of the biggest challenges」。
  5. **The Long Now** — 作品应可长期访问，「even after the company that produced the software is gone」；旧式应用只要有数据和运行手段就能一直跑（虚拟机/模拟器）。
  6. **Security and privacy by default** — 云端集中库是攻击目标；本地优先设备只存自己的数据，可用端到端加密，「any servers that store a copy of your files only hold encrypted data that they cannot read」。
  7. **You retain ultimate ownership and control** — 这里的 ownership 不指知识产权，而指「user agency, autonomy, and control over data」；云的访问方式受服务商 API/UI/条款限制，本地优先下所有字节在自己设备上。并明确：控制权不等于必须开源，「it is possible for commercial and closed-source software to satisfy the local-first ideals」。
  - 论文另给出一套同序的「记分卡」短名：`1. Fast 2. Multi-device 3. Offline 4. Collaboration 5. Longevity 6. Privacy 7. User control`。
- **论文自承的局限与未解决问题（原文摘录）**：
  - CRDT 历史膨胀与性能：「**CRDTs accumulate a large change history, which creates performance problems.** … Performance and memory/disk usage quickly became a problem because CRDTs store all history, including character-by-character text edits. These pile up, but can't easily be truncated because it's impossible to know when someone might reconnect to your shared document after six months away and need to merge changes from that point forward. **We continue to optimize Automerge, but this is a major area of ongoing work.**」
  - 网络层未解决：「**Network communication remains an unsolved problem.** CRDT algorithms provide only for the merging of data, but say nothing about how different users' edits arrive on the same physical computer. … these technologies are **nowhere near production-ready: NAT traversal, in particular, is unreliable** depending on the particular router or network topology where the user is currently connected.」
  - 明确不建议生产使用：「the underlying technologies are still a work in progress. They are good for developing prototypes … realistically, **it is not yet advisable to replace a proven product like Firebase with an experimental project like Automerge in a production setting today.**」
  - 权限/分享未解决：「**Access permissions for documents beyond secret URLs remain an open research question.**」；「any user who has a copy of some data cannot be prevented from locally modifying it … **If we can't remove documents from others' computers, what does it mean to "stop sharing" with someone?**」
  - 分支/版本模型研究空白：「There is **little work to date** on understanding the algorithms and programming models for collaboration in situations where multiple document versions and branches exist side-by-side.」
  - schema 迁移/兼容：「We see further interesting problems around types, schema migrations, and compatibility. … as there is no authoritative "current" schema for the data. How can we write software so that varying application versions can safely interoperate, even as data formats evolve?」
  - 版本历史 UI 未定：「how do we communicate this version history to users? … Are these the best we can do?」
  - 结论段： 「**But more work is needed to realize the local-first approach in practice.**」
- **核实状态**：**已核实**（DOI/页码/日期/作者机构经三处交叉：Crossref API 元数据、SPLASH 2019 程序页、作者官方全文页）。
  - 未实现的一点：ACM Digital Library 页面（<https://dl.acm.org/doi/10.1145/3359591.3359737>）本次返回 **403**（Cloudflare 拦截），**未能打开 ACM 页面本体**，因此 DOI 元数据以 Crossref 官方 API 为准。
