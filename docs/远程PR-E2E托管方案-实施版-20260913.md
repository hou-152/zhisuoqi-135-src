## 本地验收

```sh
node scripts/e2e-pr.mjs --profile=auto --artifacts=/tmp/zss135-e2e --result=/tmp/zss135-e2e/e2e-result.json
node scripts/e2e-report.mjs --input=/tmp/zss135-e2e/e2e-result.json --out=/tmp/zss135-e2e/e2e-report.md
```

`auto` 总是运行 `delivery`；没有变更列表时追加 `core-135`。变更匹配时追加 `shell-public` 或 `desktop`；测试契约、workflow、脚本、mock、地图、依赖和桌面版变更进入 `full`。Linux 执行 `desktop` 会得到 `NOT_APPLICABLE`，总 verdict 为 `BLOCKED`，不能借此合并。

## 机器状态

`PASS` 代表所有当前 profile 的必需机器断言通过；`FAIL` 代表产品或测试断言失败；`BLOCKED` 代表环境、关键边界或 profile 没有在对应平台执行；`UNSTABLE` 代表首次失败、重试成功，仍需人工判断；`NOT_APPLICABLE` 只写入场景，不可绕过总闸门。

同一个 SHA 最多自动重试一次。重试成功保留 `UNSTABLE`；新 push 由 workflow concurrency 取消旧运行。回执绑定 `headSha`、`baseSha`、合并候选 `candidateSha` 和 `evaluatorSha`，截图、DOM 快照和脱敏后的请求路径只作辅助证据。

## 权限边界

普通 PR 使用 `pull_request`、只读权限、离线页面和 mock，不读取 `.private/llm.env`、知乎凭证、真实 LLM 或生产数据。可信 workflow 从默认分支检出 evaluator，再把 PR 合并候选作为 SUT；测试子进程会清除 token、key、secret、LLM 和知乎相关环境变量。

当 PR 修改 `.github/`、`scripts/`、`e2e/`、`evidence/mock/`、`knowledge/`、`app/`、依赖文件、`SOURCE_OF_TRUTH.md` 或前端契约时，可信闸门写入 `TRUST-BOUNDARY-001 = BLOCKED`，自动合并停止，等待人工审查。真实 LLM／知乎检索应另设受保护的独立 workflow，不能成为普通 PR required check。

当前报告层使用零密钥的确定性分类，AI 解释接口尚未接入；未来若接入模型，只能把 JSON、脱敏日志和证据索引作为输入，不能写回机器 verdict，也不能获得 PR workflow 的写权限。这让“AI 说通过”永远不能替代 required check。
