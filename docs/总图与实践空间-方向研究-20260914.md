## 2. 「罗列一堆项目」的病根

不是样式问题，是**六个具体的 UI 决策 + 一个数据形状**共同造成的。

### 2.1 六个 UI 决策

1. **落地第一眼是三个总数**（`graph-view.js:740–746`）：`全部索引 3974 · 当前可见 3974 · 待装配 601`，后面还跟一行括号解释口径。用户打开总图，看到的第一句话是「这里有 3974 个东西」，不是「你现在在哪」。
2. **七层是等权网格**（`graph-view.js:826–862`，`.gv-grid`）：七张卡一样大、一样重，每张只有「N 个节点 / 待装配 X / 阻塞 0」三个数。七张并列的等权卡天然读成「七个抽屉」。层与层之间**没有方向、没有主次、没有先后**。
3. **点开层给的是 kind 列表，不是故事**（`graph-view.js:846–859`）：展开一层 → 看到 `Concept 999`、`SourceSpan 685`、`ApplicationReview 404` 这种行；再点开才是节点行。**三跳才到人话**，而中间那一跳用的是模型字段名（`SourceSpan`、`ApplicationReview`），不是用户语言。
4. **节点行只有身份，没有关系**（`graph-view.js:886–899`）：一行 = 状态点 + label + sub + kind 徽章。没有「跟我什么关系」、没有「我做到哪了」、没有「下一步」。代码注释（`886–888`）明说 id 不进行内，因为真库 id 是 `concept:cm_0a4ca4ce`，所以**行里连一个可复制的身份都没有**。
5. **层间连接摘要是一张给做数据的人看的账**（`graph-view.js:908–938`）：读起来是「公共知识与关系 → 公共知识与关系 5033 条 [知识 5033][候选／未核实 3651]」。这是正确、诚实、可核对的——但它不是给学习者看的关系。
6. **整页没有「我」**：A 页完全不含 session。右侧详情面板六段里的第 4 段叫「当前状态」（`graph-view.js:1075–1087`），但它讲的是**节点的** `status`（ready / scaffold），不是**用户的**进度；第 6 段「可运行入口」（`1103–1124`）在 76 个批量单元上**全是空的**——回执原话：「76 个批量单元没有页面可运行入口」「宁可不给按钮，也不给一个点不动的空按钮」。

### 2.2 一个数据形状（这条最根本）

7. **`graph.json` 的第一身份就是「索引」，不是「课程」。** `stats` 的键是 `indexed / pendingAssembly / blocked / gaps / byLayer / byKind / byEdgeKind`；`coverage` 是 `fullIndex` 与 `playable` **两个字符串**。契约 §4（`docs/总图视图契约-20260914.md`）明确要求这两件事**必须分开陈述**——「允许『全量索引完成、全量课程未完成』」。README 的措辞更直白：「结构完整 ← 做到了 / 内容完成 ← 没做到」。
   **所以：想让总图不读成清单，只改样式没用。要么换页面口径（方向 A/B/C），要么换数据的默认视角（方向 E），二者必选其一。**

### 2.3 附带发现（不是病根，但影响方向取舍）

8. **契约说要五种边，实际只有四种。** `docs/总图视图契约-20260914.md` 写五种（provenance / knowledge / curriculum / transition / evidence），而我实测 `graph.json` 只有 4 种：`knowledge 5725 / transition 2675 / curriculum 2167 / provenance 2077`。**`evidence` 边 0 条**——契约说它「运行期创建」，而 runtime 层现在是 **0 节点**。这不是 bug，是「还没运行过」。
9. **`reviewStatus` 在节点上不存在。** 字段真名是 `reviewState`，且**只长在边上**（12644 条边全有），节点上 3974 个一个都没有。做任何「这个节点可信吗」的界面，都得从边取，不能从节点取。另：`stats.byReviewState` 这个页头数字**描述的是边，不是节点**——很容易读错。
10. **一个会让任何「按关系分组」的界面踩坑的数据形状**：2675 条 `transition` 边的 `relation` **全是空字符串**。不能只按 `relation` 给边分类——会得到一档 2675 宽的空白；必须走 `event / guard / effect` 三个字段（实测 16 个 event / 23 个 guard / 14 个 effect）。
11. **`runnable` 是个对象（或 `null`），不是布尔。** 3974 个节点里 3068 个是 `null`，906 个非空（activity 897 + Unit **7** + Route 2）。**85 个 Unit 节点里只有 7 个有入口**（六章 + 内参单篇 `unit:agent-skills-api`），**76 个批量单元一个都没有**。任何「每个单元给一个『学习这个』按钮」的设计，**在现有字段上做不出来**——必须先给它们造 `runnable`。

### 3.0 关系图谱值不值 —— 它现在到底有没有发挥作用

**结论：关系图谱（632 条依赖 ＋ 3410 条关系）现在没参与任何一个教学决定。它被展示，但没被用来选课、排序、门禁、回补、选材料、诊断误解、匹配案例或判通过。** 三条硬证据，都不是印象：

1. **运行时根本不读它。** 驱动全部学习状态的 `scripts/lib/graph-runner.js` 全文只认两种 `curriculum` 边：`taught-by`（第 40 行）与 `has-step`（第 247 行）。我逐个字符串数过：`prerequisite` / `related-to` / `part-of` / `contrast` / `used-with` / `co-article` / `dependencies` / `relations.json` / `mapHard` / `conceptMap` / `prereq` —— **在 `graph-runner.js` 里出现次数全部是 0**；跑着的那个服务 `scripts/serve-lib.mjs` 同样全 0。实测 2675 条 `transition` 边里，**没有一条**的 `guard` / `effect` 提到前置。
   **连生产课程的那条流水线也不读它**：`scripts/build-batch-units.mjs` 与 `scripts/lib/batch-units-rules.mjs`（76 个单元的全部装配逻辑）对 `dependencies` / `relations.json` / `prerequisite` / `mapHard` / `topics.json` 的出现次数**同样是 0**。那 76 个单元的 `order` 其实只是 `build-batch-units.mjs:105` 的 `sort((a,b) => a.id.localeCompare(b.id))`——**按 CON 的 id 字符串字母序**，连人工顺序都不是，更不是关系图谱排的。
2. **契约从结构上禁止它参与。** 契约 §5 规则 1：「只有 `kind === 'transition'` 的边参与 `allowed()`；出处／知识／弱相关边**永不作为「下一步」**。」而概念地图的依赖与关系在 `scripts/lib/graph-adapter.mjs:240` 与 `:250` 被建成 **`kind: 'knowledge'`** 的边——也就是说它们**按设计就永远不能成为「下一步」**。这是结构性保证，不是疏漏。
3. **人工路线明确不认领地图的 hard 前置。** `evidence/paths-260913/validate.json` 里 6 步**全部** `mapHard: []`（`mapSoft` 依次 0 / 1 / 1 / 2 / 0 / 1）。`prereqBasis` 是 `route`（第 2–6 步）与 `none`（第 1 步）。`scripts/paths-validate.mjs:60` 的注释写明口径：「**「路线前置」与「地图 hard 前置」必须分开说：地图里没有这条边时，不许在页面上写成 hard**」。第 64 行是一道**真的会拦的门**：某步声称 `basis === 'hard'` 却在 `dependencies.json` 里找不到这条边，脚本 `process.exit(1)`。顺带一句：界面自己也是这么说的——`shell.template.html:1440` 对用户写「概念地图里这一步没有 hard 前置——整条路线的顺序是人工确认的（basis: route），不是从依赖边自动推出来的。」

**所以负责人怀疑的答案：成立。** 路线顺序来自 `routes.json` 的人工策展（`curator: "human"`），判据来自 `authored.json` 与图鉴卡 `boundaries`，补讲材料来自卡与阅读梯度。**关系图谱目前只在总图里作为 `knowledge` 边被显示。**

#### 3.0.0 一个必须同时说清的区分：**卡片在用，边没用**

上面说的是**边**。**节点不是这样——概念卡是真在用的教学材料**，这一点不能一起否定：

- 六章**全部 6/6** 的 `chapters.json[].reading.original.text` 与 `chapters.json[].cm.sourceContext` **逐字节相同**（程序比对过）。也就是说正文流里那块「原文 context」**就是概念卡的字段**。
- 概念卡还被直接塞进**真实模型判定**的提示词里：`shell.template.html:2801` 的 `概念：${c.cm.name}（${c.cm.description}）`。
- 判据那一侧同样如此：契约 §6 白名单里 `Concept` 节点的 `meta` 带 `name / description / feynman / evidence / difficulty / stage / verification`，都是教学用的。

**所以准确的说法是：概念地图的「点」在教，「点与点之间的线」没有在教。** 负责人的疑问针对的是线——线确实是闲置的。

**它现在被用的三处**：① `scripts/cm-validate.mjs:100–114` 拿依赖做**依赖子图**的 DAG 无环校验（Kahn 拓扑，`seen === ids.size`；我实跑过一次 `node scripts/cm-validate.mjs`，只读，输出 `✓ 全部通过`，999/632/3410/21）；② `graph-adapter.mjs` 把边投成 `knowledge` 边供总图显示、并按 `origin` / `audit` 现算 `reviewState`；③ `paths-validate.mjs:64` 那道**构建期的配置门**（见上）与 `:70–72` 写进 `validate.json` 的对照表。**三处里只有 ③ 能改变什么东西能否出厂，而它管的是配置文件，不是学生的学习路径。**

#### 3.0.0b 两个顺手查出来的既有问题（不是本轮引入，但影响判断）

- **一条永远不会失败的断言。** `scripts/test-graph.mjs:92` 写的是 `kind==='knowledge' && e.relation==='related-to' && /prerequisite/.test(e.relation)`——`relation` 不可能同时等于 `'related-to'` 又匹配 `/prerequisite/`，所以第 93 行那句「相关关系没有被升级成先修」**永远为真、测不到任何东西**。它对应的正是「不许拿未核实的关系当先修」这条规则——**规则是对的，守它的测试是空的**。
- **界面上有一处过度声称。** `shell.template.html:1470` 对用户说「还有 N 条相关关系，画布中已全部保留」，但被过滤掉的 `co-article`（2419）＋ `rejected`（66）共 2485 条**并没有保留**。而且同一个 `relatedCount` 在两处差了 13 倍：`validate.json` 报 Harness 271（用未过滤的 3410 条算），壳里是 21（用过滤后的 910 条算）。**没有教学影响，但它正属于「不许把建议写成已实现」那一类问题**，改任何涉及 `relatedCount` 的界面之前要先把它对齐。

#### 3.0.4 它「不能」做什么 —— 三条，建议直接写成设计约束

1. **网状图不需要被压成一棵树。** `cm-validate.mjs:114` 只断言**依赖子图**无环（Kahn 拓扑），**不是**断言整个概念图是一棵树；实测也有 153 个语义单元零关系、999 个概念里多的是多父。任何「把概念图渲染成树/大纲」的做法，都是在**丢掉它唯一的优势**（多路径、多解释），换一个它本来就不需要的东西。
2. **没有足够强前置时，必须沿用人工策展顺序并注明 `curator: human`。** 这不是退而求其次，是当前唯一诚实的做法——`mapHard` 实测全空、632 条 prerequisite 全机器生成。**不许拿未核实的关系当先修**：`graph-adapter.mjs:239` 已把 `audit !== 'yes'` 的依赖标成 `unreviewed`，按契约 §3 视图必须显式标「候选／未核实」，且运行器不许拿它当先修。
3. **它不能替负责人做课程决定。** 它最多能给「候选人 ＋ 理由 ＋ 可信度」，决定留在人这一侧。

### 方向 A｜路线优先：打开就是「当前路线」，关系图谱**不参与排序**（明确「不用」的那一个）

- **一句话**：把 B 页（当前路线）提成默认，A 页（系统总图）收成一个「换成全景」的开关。打开总图 = 一条竖着的 6 步路线，每一步一句话 + 我做没做到。**顺序只来自人工策展，不用关系图谱推。**
- **回答用户哪个问题**：我该学什么 / 我学到哪了。
- **长什么样**：**分层**只留一层（路线），3968 个非路线节点降成背景水印；**聚焦**当前步放大、前后各一步可见、其余折叠成计数；**交互**点一步展开「为什么现在学 / 卡住回哪里」，点「看它在全图里在哪」才切回 A 页并高亮。
- **它跟关系图谱的关系：明确不用 —— 而且这是它的主张，不是它的遗憾。** 理由在 3.0：632 条 `prerequisite` **全部机器生成**、其中 311 条未过审计；**人工策展的先修是 0 条**；而 `validate.json` 实测 6 步 `mapHard` **全空**——当前这条路线本来就没声称任何地图 hard 前置，它是纯人工策展的产物（`curator: "human"`）。这个方向的主张是：**在 224 条之外的关系被人过一遍之前，课程顺序就该留在人这一侧**；界面要做的是把「为什么是这个顺序」讲清楚，而不是把排序权交给一张未经核实的网。图谱在这个方向里只承担一件事：用户问「这个知识点跟别的什么有关系」时，作**一跳参考**显示，并显著标「候选／未核实」。
- **数据够不够**：**「学什么」够，「学到哪了」不够。**
  够的：`evidence/paths-260913/routes.json` 有 1 条正式路线（`agent-continuous-action-v1`，`curator: "human"`）、6 步，每步带 `conceptId / order / type / why / prereq / fallback`；`evidence/agent-loop-260913/chapters.json` 6 章各带 `routeStep 1..6 / routeTitle`——所以「为什么现在学」和「卡住回哪」都有真数据。`graph-view.js:1245–1288` 已经在渲染这两块。
  ⚠️ 一个具体的坑：**`routes.json` 的每一步没有 `title`**，只有 `conceptId`（`cm_0608c405` 这种）。步名要靠下游 `evidence/paths-260913/validate.json` 补（那里加了 `name / nameEn / domain / level / verification`）。所以「每一步一句话」里那句话**得从别处取**，不能直接从路线配置读。

- **不适合**：① 想「看看这堆材料里都有什么」的时候——那条路只有 6 步，剩下 3968 个节点无处可去；② **想靠它扩充课程的时候**——它把「下一门课学什么」明确交回给人。如果你要的是「机器帮你排下一门课」，这个方向帮不上，得看方向 E。

### 方向 B｜以人为中心：总图 = 我的学习记录

- **一句话**：把 A 页翻过来。主视图是「我」：一条时间轴，每个我碰过的节点是一张票根（什么时间、我讲了什么、模型判了什么、补讲了哪一处）；图只作为票根背后的坐标。
- **回答用户哪个问题**：我学到哪了 / 我上次卡在哪 / 这堆材料跟我什么关系。
- **长什么样**：**分层**三层——我的记录（表层）/ 我碰过的节点（中层）/ 全图（底层，只在点「看背景」时露）；**聚焦**按时间倒序，最近三次置顶；**交互**点票根回到那次会话的 trace，点节点跳到图里。
- **数据够不够**：**字段够，持久层不够，而且现在会是一张空表——这是它最大的问题。**
  够的：契约 §9.1 冻结了 `evidenceByCriterion` 的形状（`status / evidence / source / turnId / version / at`，补讲过的还有 `previous / conflictAt`），`graph-view.js:1437–1458` 已经在按这个渲染。localStorage 里 `zss135.learn.inline.v1` 存了 `{draft, draftVer, rounds[{n, at, statuses, evidence, gaps, focus, raw}]}`——**逐要点状态、学生原话 evidence、补讲 focus 都在**。

- **跟两个 tab 的关系**：**替代 A 页的默认位置，并与 C 页（学习与轨迹）合并**——C 页（`graph-view.js:1316–1365`）现在就是这件事的雏形，只是它读内存 session，且空着时照实写「尚无运行记录」。
- **不适合**：冷启动的第一天。空记录页比全量索引更难解释「这个东西是干什么的」。

### 方向 E｜回补地图：用关系图谱算「我缺的最小那几个点」（明确「用得多」的那一个）

- **一句话**：打开总图不是看全集，也不是看路线，而是看**「要往这走，我还缺哪几个点」**——系统沿**已审计的 hard 前置边**往回走，算出一个**最小的回补闭包**（通常是 1–3 个点），把它们摆成一张短清单：每个点一句话说清「为什么它是前置」＋「可信度是哪一档」＋一个能立刻读的入口。

- **代价**：新建 = 一个闭包算法（纯确定性、可断言的纯函数，**不调模型**，符合这个项目「能算的就别问模型」的既有偏好）＋ 一个回补页；要改 = `renderMap` 加第四页或替换 A 页；**不改任何源数据**（`dependencies.json` 只读）。**会动已绿测试**：`test-graph-page.mjs` 40 项要加一页的验收；`check-graph.mjs` 465 项里跟 knowledge 边计数有关的部分要跟着调。

- **不适合**：① **把这 224 条当成完整的先修体系**——它只覆盖一部分概念，且全部是模型判的（虽然过了审计）；② **想「不用人就能决定下一门课」的时候**——这个方向刻意只给「候选 + 理由 + 可信度」，出题与放行仍然留给人；③ 目标概念不在 224 条边覆盖内时，它会**诚实地什么都不给**——那时必须回落方向 A 的人工策展顺序（这正是 A 和 E 该并存而不是互相取代的原因）。

**一个关键观察：③ 的产生方式本身已经回答过「机器能负责哪一段」这个问题。** 76 个单元是**纯确定性脚本**产出的（`build-batch-units.mjs`，回执写明「一个模型调用都没打」），而它**主动拒绝**生成决策题——施工单 §1：「**决策题这一轮一律不生成**，每个单元写一条缺口」，理由是「批量装配不补造唯一正确答案」。**这就是一条项目自己已经验证过的分工线：机器负责「把已有材料装配成可运行单元 ＋ 逐条挂出处」，人负责「出题和定对错」。**

#### 三条真实可选的做法

**做法 甲｜人继续全包（沿 ① 的模式）**
- **谁做什么**：人读 58 篇 → 选 3 个概念 → 写阅读梯度（定义/直觉/机制/边界）→ **出 3 道决策题并指定正确项与依据** → 定费曼判据 → 装配成章。
- **依赖关系图谱哪部分**：**几乎不依赖**。最多借 `topics.json` 的领域归属给章节分组。
- **代价**：最贵（六章 = 18 题 ＋ 18 判据 ＋ 正文流 32 条逐字引文，全部要人核）。但它是**唯一已经被负责人走过一遍、且页面真的能跑完的路**。
- **什么时候选**：要保证「学得完」的时候。

**做法 乙｜机器按关系图谱排顺序 ＋ 人只卡出题门（把 ③ 往前推一步）** ← **我的推荐**
- **谁做什么**：机器从 `dependencies.json` 取 **224 条已审计 hard 前置**，对目标概念算**最小回补闭包**、排候选顺序，**把理由（`reason` 原文）与可信度（`audit` / `strength` / `origin`）一起摆出来**；**人只做一道门：为每个进入课程的单元出 3 道决策题**，或明确签字「本单元不出题，按纯阅读单元上线」。
- **依赖关系图谱哪部分**：**只用 `dependencies.json` 的 `audit==='yes' && strength==='hard'`（224 条）**。明确**不用** `co-article`（2419）与 `relations.json` 的非 `curated` 部分（3351）。
- **代价**：要新建闭包算法与它的验收；要接受覆盖面未知（224 条覆盖多少概念**还没量**，这是最大不确定性）；**人的那道出题门仍然是最贵的一环**——因为出题这件事机器既没被授权做、也没被验证过。
- **什么时候选**：想「下一门课不再完全靠人手排顺序」、但**还不敢让机器出题**的时候。这正是方向 E 那条线。

**做法 丙｜机器全推，人只审（最激进）**
- **谁做什么**：机器从关系图谱选概念、排顺序、装配材料，**并从 `CAS` 情境 ＋ `SOL` 动作路径 ＋ 卡 `boundaries` 误区清单里自动生成三道决策题及其判据**；人只抽检放行。
- **依赖关系图谱哪部分**：要 `prerequisite` **全量 632 条**，还要把 2419 条 `co-article` 当「可选补充材料」的候选——**也就是必须先用那些未核实的关系**。
- **代价**：**这条现在不能做，原因是硬的，不是保守**：① 632 条 prerequisite **全部机器生成**、311 条未过审计，人工策展的先修是 **0 条**；② **66 条 `rejected` 关系混在同一批 `knowledge` 边里**，不做显式过滤就会吃进去；③ 出题一旦自动化，项目自己立的「不补造唯一正确答案」这条线就断了；④ 一旦错了，错在**课程内容**上，而内容错误比顺序错误贵得多。
- **什么时候选**：**只有在 224 条之外的关系也被人过了一遍之后**，才谈得上。

**一句话建议**：走**做法乙的机器部分 ＋ 做法甲的人门**。也就是：机器用 **224 条已审计 hard 前置**算「回补哪几个点」和「候选顺序」，把理由和可信度一起摆出来；**决策题仍然由人出**（或由人明确签字豁免）。这和 ③ 那一轮已经验证过的分工线是同一条——**机器装配、人出题**。

### 3.6 顺带说一句：还有一个「不算方向」的前置施工

有个改法**不构成第六个方向**，因为它跟 A–E 任何一个都不冲突，可以当成任选其一之后的前置修补：
**把 A 页的七层压成三层（材料 896 / 语义+知识 538+1020 / 课程+活动 387+1130），每层给一句人话标题和一句「这一层现在缺什么」。**
数据完全够——`graph.layers[]` 每层已带 `id / label / order / count / pending / blocked / kinds[]`，合并只是把 7 个数加成 3 个；`gaps` 180 条带 `kind / label / why / where`（`graph-view.js:1089–1101` 已在渲染）。要补的只有一张约 20 行的映射表。

## 4. 实践空间像第一张图 —— 三个方向

### 4.0 先回答一个前提问题：正文流套到 76 个批量单元上，会暴露什么？

第一张图那种观感，靠的是六章里**四样东西**。76 个批量单元**四样缺三样半**——这决定了「像第一张图」这件事能做到哪一步。

| 第一张图靠什么 | 六章 | 76 个批量单元（我实测） |
|---|---|---|
| `narrative`（导语 `lead` + 过渡句 `bridges[]` + 关系句 `links[]` + `nextBridge`） | **6/6 有**（bridges 共 14 条、links 共 18 条，每条都带逐字 `quote` + `quoteFrom`） | **0/76 有**（`narrative` 字段整个不存在） |
| 三道决策题（`questions[3]`，含 `options[{text, correct, why, basis, basisQuote}]`） | **6×3 = 18 道 / 54 选项 / 18 个正确** | **0 道**（`decisions: []`，全 76 个都是空数组；`quiz / options / correct` 字段名根本不存在） |
| 页面入口 | `#learn=<chapterId>`（6 个 `runnable`） | **0 个**（全图 85 个 Unit 节点里只有 7 个有 `runnable`，**不含这 76 个**） |
| 费曼判据 | 人工配对（`checks[].id/point/condition/misconception`，**无 `derived` 标记**） | **264 条机械推的**（`misconceptionSource` 全是 `derived`：否定翻转 152 + 整条否定 112，**0 条人工撰写**） |

判据机械推这件事有施工单原文（`docs/批量装配学习单元-施工单-20260914.md` §1）：「`feynman.checks[]`：**卡的 `boundaries[]` 一条一条当判据**：point = 该边界的前 12 字，condition = 该边界的全文，misconception = 该边界的反面转述（**必须标 derived，不许标 authored**）」。规则实现在 `scripts/lib/batch-units-rules.mjs`：一张 15 条的否定词典（`不等于→等于`、`不是→是`、`不能→能`… ），按短语长度降序取**第一处**命中；一条都没命中时退化成「误以为这条边界不成立：」加原文。
另外 57 个 scaffold 单元的 `opinions[]` **长度就是 0**（实测分布 `0→57, 1→9, 2→4, …`）——「缺 OPI」在单元数据里是**可以直接数出来的**，不是文档说法。

**具体会暴露四个问题：**

1. **正文流四个块里三个直接消失。** `renderLearn` 的三块正文各有守卫：`blockLead`（`shell.template.html:3015`）要 `n.lead`、`blockBridges`（`3021`）要 `n.bridges.length`、`blockLinks`（`3047`）要 `n.links.length`。76 个单元这三个都是 0 → **页面直接退化成「原文 context + 定义/直觉/机制/边界」的卡片堆**。第一张图最像「课」的那两块（黄框「这一页要弄明白」+ 蓝边「上一单元留下了什么问题」）**没有数据可填**。这不是排版问题，是内容不存在。

2. **没有决策题 → 章末验收卡会提前出现，这是一处真实的语义塌陷。** `shell.template.html:2999` 写 `const decisionsDone = s.decisions.every(Boolean)`。`[].every()` 返回 **`true`**。在六章里永远不会发生（都是 3 道）；在 76 个单元上会立刻显形——**一个从来没有决策题的单元，会直接显示「用自己的话讲清楚」的章末验收卡**。要先决定「空决策题时怎么办」，否则这是一个假绿。

3. **判据读起来是机械的，而排版只会让它更显眼。** 例如 `batch-agent-B1` 的 `condition` 是卡片 `boundaries[0]` 逐字原文「Agent 不等于 LLM；模型负责推理与生成……」，`misconception` 是把「不等于」翻成「等于」算出来的（`derivation.rule: "negation-flip"`）。页面会把这条当「常见误解」摆在补讲块里——**内容是机械的，但版式会赋予它权威感**。回执原话：「还没人读过一遍」。

4. **右栏「本次课题」在这 76 个上是编不出来的。** 第一张图右栏靠的是「第 N / 共 6 章 + 上一章没过就锁」串成课程（`chapterUnlocked`，`shell.template.html:2694`）。76 个单元之间**没有顺序关系**：全图只有 2 条 Route / 8 个 RouteStep，其中只有 1 条正式路线 6 步，**76 个单元不在任何路线的步上**。硬做只能是「全部解锁」，那右栏就退化成一张目录。

> **一句话结论**：第一张图的**版式**可以复用（`lcard` / `lstep` / `lquote` / `lrail` / `lpair` 全在 `shell.template.html:568–599`），但它要的**内容**在 76 个单元里缺一半。所以「实践空间像第一张图」这件事，现在只能做**六章那 6 个**，做不了 76 个。

## 5. 跟两个 tab 的连接
