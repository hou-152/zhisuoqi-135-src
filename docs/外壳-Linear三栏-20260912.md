# 外壳：Linear 式三栏（2026-09-12 09:xx）

## 所有者指出的

09-12 09:4x，所有者贴了一张真 Linear 的 Inbox 截图，说：

> 「没有 linear 的味道」

对的。我之前那版是**「全屏画布 + 滑出抽屉」**——左边一条导航，中间一张图铺满，
点东西右边滑出一块面板盖住图。

**Linear 的骨架是三栏：导航栏 | 列表栏 | 详情栏。**
我那一版里，**中间那一栏根本没有**。而那一栏才是 Linear 的形状：
一行一个东西、行高 30px、左边一个色点、右边一行元信息、扫一眼就知道有哪些。

「味道」不是配色问题，是**结构问题**。

### 两个关键细节

1. **详情打开时画布让位重排，不盖住图。** 这是 Linear 的列表|详情分栏，不是浮层。
   踩过一个坑：`#main` 本身没变宽，画布是被 `inset` 掉的，所以 `resize()` 里
   必须自己减掉 412px——否则布局按 914 算、画布只有 502，右边两列被切掉。
2. **配色按 Linear 收**：`#08090a` 底 / `#1b1c1e` 边 / `#5e6ad2` 强调，
   去掉光晕和渐变，字号收到 12–13px。

## 顺带修的两个 bug

| bug | 后果 | 修法 |
|---|---|---|
| `.dot` 是 inline，`width/height` 不生效 | 底部「复述过了 / 没过 / 读过」三个色点完全不显示，只剩 `0 0 0 /194` | `.dot{display:inline-block}` |
| `resize()` 量的是 `#main` 而不是画布 | 详情打开时右边两列被切掉 | 减掉 `pinned ? 412 : 0` |

还有一个我自己写错的：左栏计数把 `e2`（待你看一眼）和 `e5`（策展）**都写成了 `tags.length`**，
结果两个数字同时是 10。已按元素逐个对正。

## 这轮测试暴露的两件事（照实记）

1. **判定器在我自己写的测试答案里连续挑出 4 处真错**：
   - 把「外在·集体」说成右上角（四象限里上面是个体、下面是集体，应是右下角）
   - 行列混用，把一格说成「一整行」
   - 说要补内在那一列，却填了外在·集体那一格
   - C04 的定义是「定位纯粹派与自动机各砍掉哪半个现实」，我只拿它算自己的时间账，
     根本没落到那两个人身上
   **判定器是对的，是我的答案错。** 这是「倒逼层真的在挑刺」最硬的证据。
2. **通过侧断言会翻。** `deepseek-flash` 是推理模型，`temperature=0` 也不保证逐字复现；
   边界答案会 pass/fail 翻转。所以：
   - 测试里的两条好答案是**在真壳里验到 `missing:[] wrong:[]` 才固化**的
   - 通过侧断言带**一次重试**，重试时把判定器给的 `why` 打出来
   - 翻的时候先看 `why`——多数情况下它挑得对

## 这一层**没做**的事

1. **列表栏没有虚拟滚动**。194 行一次渲染，目前不卡；上千行会卡。
2. **没有键盘导航**。Linear 的 `j/k`、`⌘K`、`Esc` 都没有。
3. **没有多选、没有批量操作**。待你看一眼那 16 条只能一条条点。
4. **没有 Linear 的窗口 chrome**（红绿灯／标签页），那是桌面 App 的壳，
   网页版做不了也不该假装。
5. 窄屏（<1100px）下**列表栏直接隐藏**，是权宜，不是设计过的降级。
