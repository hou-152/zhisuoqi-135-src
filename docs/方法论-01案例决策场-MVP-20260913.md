# 01 案例决策场 · MVP 方法论

## 目标

把已经完成的「文章 → 五类语义单元 → 概念」接到一个可执行的案例决策场。本轮只跑一个案例和一个方向，不扩展 03、05，也不假设概念与案例一一对应。

## 固定链路

```text
概念集合
→ 找候选案例
→ 选择一个 CAS
→ 组织一个假设情境
→ 给出多个方向
→ 只验收一个正确方向
→ 记录判断依据
```

## 选择规则

1. 以当前概念集合的 `relationships.target` 找候选 `CAS`。
2. 候选案例可以多于一个；不能用 `CAS-{概念 slug}` 直接假定唯一结果。
3. 本轮由负责人选定一个案例，并登记 `CAS` ID。
4. 案例若是 `假设场景`，页面必须明示，不能写成真实复盘。
5. AI 可以改写情境和选项，但必须保留原始语义单元 ID 和来源。

## 本轮 A

输入概念：`CON-context-rot`、`CON-context`、`CON-context-window`。

候选案例：`CAS-context-rot`、`CAS-context`、`CAS-context-window`。

选定案例：`CAS-context-rot`。

唯一验收方向：固定模型、任务、关键证据和评分方法，只分档增加无关输入，判断输入长度是否造成可靠性退化。依据为 `OPI-CTX-03-03` 与 `SOL-context-rot`。

## MVP 验收

- 从实践空间进入 01；
- 能回到对应概念；
- 能看到选定案例及其假设性质；
- 能做一次方向选择；
- 选中本轮方向后给出依据；
- 其他方向只作为对照，不继续展开；
- 03、05 只显示未接入，不提前承诺。

## 批量复用

队友只需替换概念 ID、候选 CAS ID、选定 CAS ID、OPI / SOL 依据和一个正确方向。每次只新增一份材料，先跑通再扩展。
