## 2. 三处旧结论要改

### 2.1 额度按天刷新，不是总量封顶 ⚠️ 改写路演边界

| 观测 | 数值 |
|---|---|
| 09-11 那轮实测（写在 3.5.5） | 搜索 89、直答 5、创作 3 |
| 09-12 01:53 再查（同一凭证、同一账号） | 搜索 **2**、直答 **0**、创作 **0** |

**推断**：额度按自然日归零。**未取得官方文档确认**（知乎开放平台文档站与 GitHub 在本次网络环境不可达，`quota` 响应也不含周期字段）——按项目规则标注为**实测推断，未升级为事实**。

**对文档的影响**：3.5.2 那条「直答 100 次封顶 → 只能当 demo 与实验级，不能宣称生产能力」**成立前提已变**。改为：「直答**每日** 100 次（实测推断），够跑路演 demo + AB 实验 C3 组 + 每日回归；能否对外称生产能力，取决于重置周期是否被官方确认。」

### 2.2 `question answers` 能用，别被 `question recommend` 连带误伤

3.5.3 证明的是「**推荐**不能用」，但当时没测「**回答**」。本次实测：给一个真实问题 URL，返回真实回答摘要（`ContentType: answer`、`Summary` 字段可用）。

**产品含义**：多了一条「真实知乎问题 → 真实回答当学习材料」的入口，不必只靠搜索。

### 2.3 直答不是「一个模型」，是三个，且行为差很多

同一个费曼判定任务（3 概念各 3 要点 + 一段只讲了「景别」的复述），三模型实测：

| 模型 | 耗时 | JSON 直接可解析 | 判定正确 | 结论 |
|---|---:|---|---|---|
| `zhida-fast-1p5` | 2.58s | ✅ | ✅ | **费曼判定首选** |
| `zhida-thinking-1p5` | 1.38s | ❌ 被 ` ```json ` 围栏包裹 | ✅（内容对） | 需剥离围栏才可用 |
| `zhida-agent` | 7.83s | ✅ | ✅ | 慢 3~6 倍；通用问答幻觉 |

`zhida-agent` 通用问答实测（问「知所栖135是什么」）：把项目说成莫干山民宿品牌，还编了一句《大学》引文。**不要用它做产品问答**。

## 3. 产品级发现

### 3.1 真缺陷：换直答模型会「静默降级」

产品 `reviewFeynman()`（`prototype/知所栖-135-基础框架.html` 第 421 行）是裸 `JSON.parse(out)`，外面套 `try/catch`，catch 落到规则引擎。所以如果把模型换成 `zhida-thinking-1p5`，**不会报错，只会悄悄退回规则判定**。

**一行修法**（需授权才动 `prototype/`）：

```js
const parsed = JSON.parse(String(out).replace(/^```(?:json)?\s*|\s*```$/g, ''));
```

**兜底已存在**：`verify-135.mjs` 有一条「引擎标识与运行模式一致」断言，正是为探测这种静默降级而设——换模型跑一次验证就会报红。这条设计没白做。

### 3.2 三模型均不返回 `usage`

复核 3.5.2 的硬约束：**成立**。`usage: null`，token 成本核算仍然做不了。

### 3.3 全网搜命中了项目核心命题的原话

`search global --query "费曼学习法 间隔重复"` 返回一条：

> 思维导图、费曼学习法、间隔重复，三者都能帮助人搭建知识连接，但存在共同短板：所有连接都是静态、一次性的。

这句直接对上知所栖「1/3/5 是动态教学动作，不是静态知识连接」的立论。**可作为路演引语候选**（引用需回原帖核实作者，标注为知乎内容）。

### 3.4 真实知乎内容 → 3 概念，可行（此前是手写）

原型里的 3 概念是**手写原创**（`prototype/知所栖-135-基础框架.html` 第 171 行注明）。本次实测了「能不能自动生成」：把上面那条**真实知乎内容**喂给 `deepseek-flash`，要求产出 3 概念 + 每个 3 条可判定费曼要点。

**结果：一次成功，JSON 可直接解析，1074 tokens，质量可用**：

| 概念 | oneLiner | 要点数 |
|---|---|---|
| 静态连接 | 思维导图等工具搭出的连接画完即固定，不会随新知识自动更新 | 3 |
| 间隔重复 | 在即将遗忘知识点的时刻及时安排复习，用最少次数加固记忆 | 3 |
| 记忆即肌肉 | 记忆不是存完即固定的硬盘文件，而像肌肉靠主动回忆锻炼变强 | 3 |

**产品含义**：「真实知乎内容 → 3 概念」这条路没有技术障碍，且成本极低（~1000 tokens/次）。当前没接，是**产品选择**，不是能力限制。

### 3.5 直答能不能生成「3 决策」（案例决策场）：**能生成骨架，不能当信源**

给一个**全新情境**（30 秒竖屏产品片／只有 10 张静态图／零预算／明天交付），一次 `zhida-thinking-1p5` 调用（18.4s，2272 字符）产出完整四步结构，JSON 可直接解析：3 个选项 + 3 条案例（带 URL 和倾向）+ 3 行「条件 → 路线」表 + 复盘。

**逐字段核验结果（拿返回的标题回 `zhihu_search` 对）**：

| 字段 | 结果 |
|---|---|
| 结构完整性 | ✅ 四步齐全，倾向判断合理（案例分别 lean 到 A/B/B） |
| 案例 URL | ⚠️ **3 条里 1 条标题 + URL 完全命中**（`p/2037111453166088603`），另 2 条标题**搜不到**，存疑 |
| 作者名 | ❌ **3 条全是编的**：「知乎剪辑实战作者」「知乎视觉创作专栏作者」这类占位描述，不是真名——而 `zhihu_search` 本身返回真实 `AuthorName` |
| 延迟 | 18.4s（对比搜索 0.77s，慢 24 倍） |

**判定**：直答是这套接口里**唯一**能做「多源综合 + 条件化判断」的（搜索只能给原文，LLM 只能给通用答案）。所以它该放在 **3 决策的骨架生成**位置——但**每条案例必须回 `zhihu_search` 核验**，核验不过的丢弃；作者名一律以搜索返回为准，直答给的一律不用。

这条同时是「机器发现、人裁决」的接口版：**直答负责发现，搜索负责裁决。**
