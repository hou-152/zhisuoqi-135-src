# 准入门改版：用「区分度自证」替代「上线前人工审」（2026-09-14 讨论定稿）

> **这是讨论稿定下来的设计，尚未实现。** 下游 agent 不要再按「机器生成的内容必须逐条人工审」这条老规矩走——
> 那条规矩已经被两次实测证明：**审的不是"对不对"，是"考不考得出来"**。

## 为什么要改：两次审计打死的其实都是同一件事

| 被打死的 | 表面病因 | 真实病因 |
|---|---|---|
| 228 道机器决策题 | 正解是唯一那句逐字材料原文 → 不读材料就全对 | **零区分度** |
| 264 条机器派生判据 | 照抄 `boundaries` 原文就满足 | **零区分度** |

**两次都不是「教错了」，是「考不出来」。** 判据永远 `met` 就是死的；题目人人全对就是废话。

## 关键限制（决定了新机制长什么样）

**内容正确性拿不到用户信号。** `dbs-learning`（493 行，已读完）从头到尾没有回答「讲错了怎么办」——
它唯一问用户的四个问题是「哪里看懂了 / 哪里没看懂 / 想展开什么 / 跟你的真实问题什么关系」，
**从来不问「你觉得我讲得对吗」**。因为「我没看懂」这个信号**天生不可区分**：可能是我笨，也可能是你讲错了。

**所以正确性不能靠"从使用中收集"来解决。区分度可以。**

## 新准入：三条机器条件，替代人工审

一条判据要参与**通过判定**，必须同时满足：

1. **绑了逐字原文** —— 逐字 `indexOf` + `sha256` **机器可查、零人力**。
   > 这才是六章不用审、264 条要审的真正原因：六章 18 条**每条都绑了逐字原文**；264 条绑的是**"边界的反面"**——一个**没有原文的转述**。
2. **有至少一条真实轨迹证明它从 `not-met` 走到 `met`**。
3. **缺口在轨迹上真的下降过**（第一轮就全 `met` ＝ 死判据，自动淘汰）。

**不满足的照实标「待验证区分度」：可以看、不参与通过判定、不挡住上线。**

## 配套的「代际指标」

不看「对不对」，看**每一轮缺口是否必须下降**：

- **下降** ＝ 判据有效，激活
- **不下降** ＝ 判据可疑，自动降级为提示
- **第一轮就全 `met`** ＝ 死判据，自动淘汰

## 唯一真正绕不过去的一条

**一个「稳定地教错」的判据，轨迹上看不出来** —— 学生会稳定学会错的东西，缺口稳定下降，指标一切正常。
**这一层只能靠来源（人写）或外部权威（可核实的原文）。** 没有别的办法。

**所以「作者签字」不能自动化，但能极小化**：从"事后审 264 条"变成**"写的时候必须引用一条原文"**——
签字动作被压进写作动作里。**这就是 dontbesilent 不用审的原因：他自己写。**

## 对 76 个单元的直接后果

**可以上线**，但只有**走过一遍**的那些会被激活；其余照实标「待验证区分度」，能看、不进通过判定。

**代价照实说**：这不叫「绕过审计」，叫**把「上线前审」换成「上线后自证」**，而自证**需要真人轨迹**。
**所以负责人本人走一章不是可选项，它是这套机制的启动条件。**

## 边界

- 本文件是**设计**，不是已实现。改代码前先确认负责人拍板。
- 不许拿这份文件去放宽已有的闸门：**现有 `review.json` 驱动的准入机制在改版落地前照旧生效。**
- 「待验证区分度」必须显式标注，**不许把未验证的判据说成已验证**，也不许让它参与通过判定。
