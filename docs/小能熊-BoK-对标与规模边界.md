# 小能熊 BoK 对标与规模边界

观察日期：2026-09-06。范围：公开页面的实际浏览器交互、当前 Demo 源码只读分析。本文是候选判断，不是新的产品定稿。

## 结论

知枝 v2 验证了小规模点亮反馈，但没有验证知识体系扩展后的可用性。建议把全图放到探索入口，把默认学习界面收束为「当前目标、眼前缺口、少量下一步」；个人进度按固定任务范围计算。

小能熊证明了数千节点可以被组织、筛选和定位，也同时展示了全量前置展开后的负担。能展示大图、能追溯依赖、能生成适合某人的学习计划，是三个需要分别验证的能力。

## 实际看到的设计

| 页面观察 | 可借鉴之处 | 尚不能由此确认 |
|---|---|---|
| 图谱洞察显示 3,598 个微主题、4,593 条依赖、最长链 38 步；有基础概念排序 | 用统计与少量入口帮助理解大图结构 | 中心度高或累计后继多，是否就是当前用户应该先学的内容 |
| 学科、课标、学段、年龄与硬依赖筛选；可双击只看一个学科 | 先缩小浏览范围；布局有明确维度 | 筛选在底层如何执行、万级规模性能及维护成本，本次未测 |
| 学科图谱与智慧星球两个布局 | 同一套数据可以提供不同观察方式 | 更换布局能否降低学习决策负担，需要试用 |
| 搜索分数能返回带学科、年龄的候选；选中后定位并打开详情，地址包含稳定主题 ID | 搜索和详情提供直接进入局部的通道 | 本次只观察到这组结果，不推断排序算法或全局结果上限 |
| 主题详情分别列出直接前置、累计前置、直接后继、累计后继，并附观察证据和关系理由 | 区分「眼前有关」和「远处可追溯」 | 累计后继是结构可达性，不足以证明学会一项就自动具备全部后继能力 |
| 公开详情没有显示我的学习证据或个人完成率 | 公共结构与个人学习可以分别呈现 | 本次没有登录，不能断言登录后的个人能力或进度功能不存在 |

来源：[小能熊知识体系](https://infra.candobear.com/bok)。上述数量为页面当时报告值，不是独立审计数据。

## 最能说明规模问题的实例

实际路径：搜索分数 → 分数表示法 → 化简分数。

[分数表示法](https://infra.candobear.com/bok/topics/mt_vKcxX6iNOA)显示 0 个前置、6 个直接后继、236 个累计后继。[化简分数](https://infra.candobear.com/bok/topics/mt_b7T-CjOYUR)显示 3 个直接前置、40 个全部前置、链深 14，并列出 41 步完整路径。路径包含早期的计数与握笔等基础内容。

这是结构追溯的价值，也是个性化计划的边界：某人不会化简分数，不等于他还需要重新学习这 40 个前置。应先判断哪些已有证据、哪些存在缺口，再决定推荐什么。链深 14 与列出 41 项也提醒我们：祖先集合和一条线性的学习路线不是同一个东西。

来源面板同时说明中文及课标对齐来自衍生项目，相关文本和映射仍有人工审核边界。这意味着维护翻译、概念粒度与先修理由，本身就是长期工作；不能只看节点计数增加。

## 回看知枝 v2：问题已经出现

- 18 个节点、27 条边中，选择完成首支短片会高亮 16 个祖先，几乎又回到全图。当前路径高亮没有真正减少信息量。
- 分类按钮只降低无关节点的透明度，仍然渲染全部节点与边；每次选择和缩放都重建页面。固定画布及手写坐标只适合当前样本。
- 景别与完成短片属于不同粒度，按节点等权计数不等于学习量。相同的 3 条通过记录，若分母从 18 扩到 180、1,800、18,000，现有一位小数显示会从 16.7% 变成 1.7%、0.2%、0%。用户没退步，数字却趋近于零。
- 目前只有 3 个可学节点，以 18 为分母的最高可体验进度也只有 16.7%。它能演示当前位置，却不适合作为本次任务的完成度。

代码依据：`prototype/知枝-demo.html` 中 `AtlasModel.ancestors`、`stats`、`atlasGraph`、`atlasUpdate`；数据依据：`docs/ai-video-map-v1.json`。

严格区分增长来源：当前祖先遍历使用去重集合，单次扫描约为 O(V + E)，没有枚举所有路径；路径组合数量在某些 DAG 中才可能指数增长。实际危机还包括关系密度、反复比较、界面交叉、概念治理和用户决策负担，不需要等算法达到指数复杂度才发生。未做 180／1,800／18,000 节点性能实测。

## 下一版的候选方向

1. **默认只呈现当前目标附近。** 当前节点、少量直接前置、最多 3 个下一步；更远的上游按需展开并显示隐藏数量。类别目录用于归属，先修边用于学习建议，不把所有关系同时画线。
2. **先诊断已有理解，再补前置。** 用解释、练习或作品观察判断缺口；不把全体祖先当作必须从头完成的清单。学过但没有记录时允许展示不确定状态。
3. **进度绑定一个固定任务包。** 例如镜头表达 3 项中已完成 2 项；新知识入库不改变这个任务的分母。全体系保留探索价值，次级显示版本与统计口径。
4. **成就绑定可完成的行为。** 例如写出可检查的镜头描述、修改一个失败镜头、完成一次迁移练习；先验证这些反馈是否帮助行动，再讨论长期成就机制。
5. **限制知识体系的生成范围。** 黑客松只维护明确范围内的候选概念与关系。新的问题先匹配已有 ID；无法确定归属时进入待整理，不自动新增正式节点并连向一切。

## 下一次应怎样验证

用同一个用户目标对照两种界面：全图默认展开与局部目标默认展开。记录是否找到下一步、是否误把所有前置当必修、是否能解释进度含义。再用更大规模的合成数据检查可见节点预算、搜索定位及响应情况；合成数据只能证明交互和性能边界，不能证明知识关系正确。
