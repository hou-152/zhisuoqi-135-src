### 已在代码里核实的两个真实缺陷（读的是 prototype 真字段，不是推演）

- **字段撒谎闭环**：`state.feyn='pass'` ＋ `remediation='none'` 同时驱动绿点、结算条、待补清单、倒回按钮、下一轮起点，**无第二来源**；且只有 `hit:false` 才渲染倒回按钮 → **pass 的概念永不回头，永无新证据推翻**。
- **降级丢粒度**：`saveCheckpoint` 只存 `{at, state, labTries}` → 刷新后待补清单只剩 `pending`，不知漏哪条，**「漏哪倒回哪」降级成「漏了哪个概念」**。另 LLM 失败退回 `ruleBasedReview` 关键词子串匹配（写「我不确定景别算不算」也会判过）。

### 下一步设计方向（09-12 凌晨新增，取代记忆线成为主线）

**从 dbs-standard-answer 倒推 dbs-learning。** standard-answer 的第一层产出不是答案，是**这个问题的答案等级**（SKILL.md 347–349 行已有的三档：成熟共识／条件性答案／尚无统一答案）。现在的实现把第三档当失败等级用；倒推之后它应升为平级分支，并直接决定学习形态：

| 判级结果 | 能教什么 | 学习序列 | 终点 |
|---|---|---|---|
| 成熟共识 | 可教 | 机制 → 条件 → 边界 | 能复述机制、能说出失效条件 |
| 条件性答案 | 教判据 | 条件识别 → 判据 → 你的情形落在哪 | 能说出自己落在哪个条件里 |
| 尚无统一答案 | 教不了答案 | 判据 → 代价 → 只有你能回答的问题 | 敢选，且知道怎么反悔 |

这是 `dbs-learning-beta` 的正确接入位置：它**不是**一个处理无标准答案的补丁 skill，而是**标准答案判级的第三个出口**。135 现在缺的正是判级步骤——1 阅读器默认所有问题都有东西可教，所以「我要不要去找工作」进去就会出来一篇行动方案。

待验证：判级本身能不能稳定做对（无先例可循，见本文件「不能对外说」清单里「缺口驱动的反向提问零先例」）。

- **知乎 CLI 返回 PascalCase**（`Data.Items[].Title` / `.ContentText`），不是小写。09-12 出过一次真事故：`ab-feynman-test.mjs` 写成 `data.items`，导致 C1 检索永远失败却**静默回退成 B**，实验会得出「不用检索」的假阴性结论。已修，并在主流程前加预检（检索不通直接 exit(3)）。**重跑时确认输出是 `C1-lightweight-pipeline`，不是 `C1-fallback-to-B`。**
- 任何「降级/回退」路径都要报警，不能静默（本项目已有「开环报警」原则）。verify 里那条「引擎标识」断言已改成模式感知，否则接上 key 就假失败。
