## 2. 评审权重（决定做什么最划算）

| 维度 | 初审 | 路演决赛 | 说明（手册原文要点） |
|---|---:|---:|---|
| **AI 场景价值** | **40%** | **35%** | 是否构建有意义的 AI 场景；是否解决真实用户/业务痛点；**能否在知乎生态内产生实际价值（效率、体验、内容质量）** |
| 创新度 | 25% | 25% | 场景选择是否有想象力，玩法是否新颖 |
| 完成度 | 25% | 25% | 产品是否可用、体验是否流畅、**Demo 是否跑得起来** |
| 产品体验与设计感 | 10% | 8% | UI/UX 是否美观、交互是否直觉 |

**读法**：40% 压在「场景价值 + 知乎生态契合」。这意味着**把知乎的位置讲清楚，比多加一个功能更值钱**。而「完成度 25% + 体验 10%」合计 35%，是纯执行分——项目现有的 61/61 自动验证正好服务这一块。

## 4. 实证发现：官方质量字段能不能当闸门

### 4.1 知乎搜索 API 的完整字段（实测）

`GET /api/v1/content/zhihu_search` 返回：`Title`、`ContentType`（Answer/Article）、`ContentID`、`ContentText`（摘要，高亮用 `<em>`）、`Url`（带溯源 utm）、`CommentCount`、`VoteUpCount`、`AuthorName`、`AuthorAvatar`、`AuthorBadge`、`AuthorBadgeText`、`EditTime`、`CommentInfoList`（精选评论）、`AuthorityLevel`、`RankingScore`。

`AuthorityLevel` 定义（官方 skill `references/http-api.md` L152）：**1 低权威，2 中权威，3 高权威，4 超高权威**。

### 4.2 拿现成的三张案例卡去量

| 案例卡 | AuthorityLevel | 赞同 | 评论 | 认证标 | 作者签名 |
|---|---:|---:|---:|---|---|
| 景别·元力共生AI | 3（高权威） | **1** | 0 | 空 | `8eiozztv` |
| 运镜·凯k | **4（超高权威）** | **0** | 0 | 空 | `kai-k-52` |
| 提示词·叁虫 | **4（超高权威）** | **0** | 0 | 空 | `ham-68` |

**结论：`AuthorityLevel` 不是内容质量信号。** 零赞、零评论、无认证的新号营销文，被平台标为「超高权威」。它是**作者级权重**，不是**内容级验证**。

**这恰好证实了用户 09-12 的判断**（「知乎充满广告与故事性、缺结构」）——而且现在有了可量化的证据，不再只是印象。

### 4.3 由此得到的产品机会：信源质量闸门

不用权威度，改用**社区验证信号**做闸门：

```
进案例卡的条件：VoteUpCount ≥ N 或 CommentCount ≥ M
不满足 → 不进案例卡，只在「更多讨论」里以原始链接列出（标明「社区未验证」）
```

**为什么这是加分项而不是补丁**：

- 直接服务 40% 权重里的「**内容质量**」分项；
- 把用户的批评变成产品特性——**我们知道这个源脏，所以我们做了闸门**，而不是假装干净；
- 与项目已有的诚实边界一脉相承（现有页面已标「案例三含产品推广，案例不能当因果证明」）；
- **成本极低**：字段已经在响应里，只是没用。

**必须同时写进路演边界**：闸门只过滤「社区是否验证过」，**不等于**「内容正确」。高赞也可能是流行的错误。
