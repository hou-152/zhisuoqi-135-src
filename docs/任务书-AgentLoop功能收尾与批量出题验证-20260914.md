## 目标与范围

优先完善网站自己学习空间中的 Agent Loop 六章，UI 美化后置。交付标准是实际入口能连续完成学习，并用小批量验证生产方法能否复用。

本任务替代旧 Issue 中「以 agent-skills-api 内参文章作为主 MVP」的实施范围。旧文档保留为历史，不据此继续扩展内参 overlay。

核心内容入口：`evidence/agent-loop-260913/chapters.json`，装配器 `scripts/build-learning-materials.mjs`，页面 `scripts/shell.template.html`。

六章已有决策题。先核实现有能力，缺什么补什么，不重新生成已有合格内容，不把内参的测试通过当作学习空间验收。

不处理小龙虾；不重做 UI、不加实验台、不扩展内参文章、不修改概念图源数据、不让 LLM 重排路线。本轮不 push、不发布、不处置错方向产物；例如 linear-principles overlay 保留原状并在回执标为排除项，不擅自移入 .trash。

读取 AGENTS.md、SOURCE_OF_TRUTH.md、工作日志、六章材料、装配脚本和对应测试。检查 Git 分支、HEAD、既有未提交改动；只处理可分离的本任务修改。

给出简短能力表：功能／对应源码／对应测试／是否需要改动。核对真实页面请求与接口，不能因为 verify-135.mjs 测过另一份原型就认定六章页面通过。

## 1．六章功能闭环

固定路线：Agent → 工具 → Agent Loop → 状态与持久化 → Harness → 验证闭环。

逐项验证并修复缺口：

1. 从现有知识体系入口进入独立学习空间，当前概念和章节正确；返回恢复位置。
2. 当前章只加载其阅读 context、定义、解释、来源和判据；假设案例继续明确标注。
3. 阅读中可以即时费曼：复述 → 定位一个具体缺口 → 针对该缺口补讲 → 一次追问 → 补答 → 返回原活动。保留已有有效证据；新增回答有矛盾时重新核对，不能把一次局部补答当作整章掌握。
4. 即时费曼与章末验收状态分离；即时反馈无权解锁章节。
5. 每章 3 道决策题，每题 3 个选项且恰好 1 个正确项；按顺序完成，答错可重试；正确依据必须能定位到本单元 OPI 或 SOL 原文。
6. 三题完成后进入章末费曼，未通过不解锁下一章。空题数组、缺题或缺判据不得自动通过。
7. 刷新可恢复状态；切章不串材料、答案和反馈；修改复述使对应旧验收失效；晚到响应不得覆盖新输入；材料／判据更新后不得复用不匹配的旧通过记录。
8. API 失败、返回格式无效或依据不足显示未判定／待复核，不冒充通过。

本轮不往六章新增“5 个实验动作”。旧内参实验是否常显的规格争议不阻塞六章收尾。

## 2．A/B 盲评与批量候选题

保留已有预注册规则与结果。A 为结构法、B 为模型法；本文件不宣告胜者，也不改变原始实验判定记录。

### 盲评

- 给负责人一份只包含 X/Y 题面、选项、匿名来源材料和评分表的文件，不含 answerKey 或能揭示方法的注释。
- 负责人分别评价：干扰项是否像真实误解、正确答案在题面条件下是否唯一、依据是否能回到本单元材料。可判两组均不合格，不能强行二选一。
- 当前对话未包含 X/Y 全文，不能替负责人编评分或宣称已盲评。
- 收到评分后才揭盲。一次比较只用于本题方法选择，不得宣称统计显著或全库有效。

### 两种方法共用的准入检查

1. QST／CAS／SOL／OPI 按实际出处信封字段取值；缺少本题必需输入时停止该题，并写缺口。不得拿空材料生成题目。
2. sourceFile、locator、sourceSha256 可解析并匹配；引用文本可定位。哈希匹配只证明来源版本一致，不等于观点正确。
3. 逐条核对选项、理由中的事实与适用条件；原文不存在的主张不能被包成引用。
4. 正确项是 SOL 原文也不自动合格：它必须回答当前题面，且另两项在题面条件下不成立。
5. 干扰项应对应具体误解或缺条件，不能靠荒谬选项、答案长度或词面照抄制造通过。

### 分批生产

阶段 A：六章闭环先通过，不等待批量题完成。

阶段 B：选 3 个具备可靠材料且类型不同的批量单元试装配，记录选择理由。每单元目标 3 题，覆盖不同判断点；来源不够就登记缺口，不凑数量。记录耗时、调用次数、人工修改、失败原因；核对课程概念与单元 ID，不能只按名字硬配。

阶段 C：试装配检查通过后，才生成最多 76 个单元的候选题。单元缺材料就跳过并报告，不把成功写成 76/76。自动生成的题只进入候选层，不能自动升级 ready、接进正式解锁或写回概念地图。

批量接入正式学习空间，需要负责人依据候选质量确认。沿用原实验的胜者选择规则，不等于跳过全量质量检查。

输出生产清单：单元 ID／材料映射／题数／依据定位／生成方法／检查结果／人工审核状态／阻塞原因。用这次 3 单元实测估算后续成本，不沿用未经测量的“半天刷完”承诺。

## 3．验收与停止条件

至少运行以下现有命令，并按本次实际改动补充相关测试：

```sh
node scripts/check-learning-materials.mjs
node scripts/test-learn-agent-loop.mjs
node scripts/test-path.mjs
```

若涉及批量装配或对应接口，再运行相关 `check-batch-units`、`test-batch-walk`、`test-learn-api`、`test-feynman-teaching-map`；先确认它们覆盖的是本次对象。若文件或入口已改变，报告替代关系，不照抄旧断言数量。

选一章做真实模型往返：错误复述 → 定位漏点 → 补讲／追问 → 局部补答 → 返回决策 → 独立章末验收。保存脱敏请求、响应、判据版本和状态变化。测试稿明确标成测试稿，不冒充真人学习记录。未配置可用接口则如实记录阻塞，不读取或打印密钥，不擅自新增付费服务。

页面证据给出可复现地址和实际学习状态即可；UI 美化不作为本轮前置。基本可操作性仍必须保证，例如按钮可点、题目可读、返回可用。

新增测试必须验证实际边界：恰好 1 个正确项要统计数量；顺序门禁要尝试先点后面的题；失败响应不得解锁。不能删断言或用空集合恒真制造通过。

MVP 合格不等于批量合格；批量候选生成不等于审核完毕；测试通过不等于已证明学习效果。
