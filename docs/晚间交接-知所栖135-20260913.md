## 先说人话：这个产品是什么（给完全没有上下文的人）

**一句话**：你抛出一个问题，它把你从「看懂了」推到「讲得出来」。

**它做四件事**（演示就讲这四步，全程 8 分钟）：

1. **1 次阅读**——同一个知识点讲三遍：先给直觉，再给机制，最后给怎么用。
2. **3 次判断**——它不给你答案，只摆出条件和别人的同类案例，让你自己选，再拿你的选择和真实案例对照。
3. **5 次实验**——看懂了不等于会做，让你动手做一遍。
4. **复述验收**——让你用自己的话讲一遍，系统只挑你漏掉的那一点，把你退回去补；补完再讲一次才算过。**没复述不算完成。**

**对外那一句**：我们不比谁的模型强，我们比的是——学完之后能不能讲出来。

**群里的黑话 ＝ 大白话**：

| 群里说法 | 什么意思 |
|---|---|
| 壳 | 演示用的那个网页 |
| 1 阅读／3 决策／5 实验／费曼验收 | 上面那四步 |
| 冻结线 | 过了这个时间点，那样东西就不再改 |
| mock | 一份假的接口数据，让前端不用等后端也能把页面做出来 |
| 验收脚本 | 一条命令，跑完打印「通过几项」；做没做完由它说了算，不由人说 |
| A ／ R | A ＝这条活没走通时第一个被问的人；R ＝实际动手的人 |

**文件在哪**：下面写的路径都在项目仓库里，不在群里。没拿到仓库的人，按「要交什么」那一段做内容就行，落盘交给有仓库的人。
