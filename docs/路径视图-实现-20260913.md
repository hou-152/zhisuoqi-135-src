# 路径视图 · 实现说明（2026-09-13）

对两份执行件：`docs/路径视图-PLAN-20260913.md`（产品与交互计划）＋ `docs/路径视图-HANDOFF-DeepSeek-20260913.md`（交给 DeepSeek 的执行件）。
本轮完成的是 HANDOFF §十 说的那件事：**在现有知识体系网站里，让一条真实前置路径被看见、能走通、能回退，并且不破坏原有图谱探索。**

## 1. 做成了什么

主区顶部从 `图谱｜关系｜星球` 变成 `路径｜图谱｜关系｜星球`，「路径」是默认学习观察方式：

| 位置 | 行为 |
|---|---|
| 主区画布 | 同一张图谱，路线上 6 个点放大加亮、标步号、当前步加白环；**其余概念变灰缩小**（不是删掉，仍可点、仍可探索） |
| 左上路径条（262px） | 方案 B 的「导师」：第 N 步 / 共 6 步 · 路线标题 · 入口问题 · 目标 · 六步清单（当前/下一步/已走）· 为什么现在学 · 前置 · 下一步 · 卡住回退 · 分支（≤2）· 回到全图 |
| 中间栏（主题下钻后） | 主题顶部出现「推荐路径」入口（`.prow`，与概念行 `.row` 分开计数）；点一下进路径 |
| 右侧概念卡 | 顶部多一块路径上下文：`当前路径第 N 步 / 共 6 步` · 为什么现在学 · 前置（带 ✓/未走）· 下一步 · 卡住时回退 · `[学习这个] [查看前置理由]` |
| 前置理由（折叠） | 四类关系分开显示：**强前置 hard / 弱前置 soft / 支撑材料 support / 相关概念 related**，各带依据 |

四类关系按 HANDOFF §五 映射自现有数据，**没有改全量关系数据结构**：

- `hard` ← `dependencies.json` 里 `strength === 'hard'` 的边；
- `soft` ← 其余依赖边；
- `support` ← 该概念的来源原文与掌握证据（就是卡上已有的「来源」「深看」，不重复渲染）；
- `related` ← `relations.json` 里除 `prerequisite` 外的边（相关 / 一起使用 / 组成 / 对照）。

## 2. 那条真实路线（ID 逐个核过，没有猜）

配置落在 `evidence/paths-260913/routes.json`（**独立于概念图谱**，顺序不写回 `topics.json` / `dependencies.json`）：

| 步 | 真实 ID | 概念地图里的名字 | 主题 | 层级 |
|---|---|---|---|---|
| 1 | `cm_0608c405` | Agent | Harness 与运行时 | L0 |
| 2 | `cm_a72ef18d` | 工具 | 工具调用与沙箱 | L1 |
| 3 | `cm_1973b1d3` | Agent loop | 循环与自主执行 | L1 |
| 4 | `cm_be951649` | 状态子系统与进度持久化 | 状态与持久化 | L1 |
| 5 | `cm_0a4ca4ce` | Harness | Harness 与运行时 | L0 |
| 6 | `cm_7cd7335d` | 验证闭环 | 验证与评估门禁 | L1 |

入口问题：**为什么 AI 能连续做事，而不只回答一次？** 主题挂在 `loop-autonomy`（循环与自主执行）。
分支（在 Agent loop 之后，2 个，各带理由）：状态子系统与进度持久化（主推荐）／权限与推理的架构分离（分支）。

`node scripts/paths-validate.mjs` 每次都会重核：ID 是否都在 `topics.json` 里、步数是否在 5—7、分支是否 ≤2 且都写了理由、声称的 hard 前置在 `dependencies.json` 里是否真有这条边。结论落 `evidence/paths-260913/validate.json`。

## 3. 必须照实说的一件事：这条路线在图上没有 hard 前置

PLAN §5.2 设想的排序方式是「先反向收集 `hard` 前置，再由人工确认顺序」。**实测：这六步在 `dependencies.json` 里一条 hard 前置都没有**（工具/Agent loop/状态/验证闭环各只有 1—2 条 soft，Agent 与 Harness 是 0 条），所以：

- 主路径顺序**全部来自人工策展**（PLAN §6 定的顺序），不是从依赖边自动推出来的；
- 页面上的「卡住时回退」因此取**路线里的上一步**，并把依据标成 `basis: route`（人工确认的路线前置），不冒充 hard；
- 只有当地图里真有这条边时，才显示成 `hard` / `soft` 并附地图给的理由。

这不是缺陷，是数据事实；把 `route` 说成 `hard` 才是错的。要让它变成真正的 hard 依赖，得改概念地图的依赖边（本轮明确不做，见 §6）。
