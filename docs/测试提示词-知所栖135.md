## 一、冒烟测试 · 提示词

**用途**：每次改完数据或契约，30 秒内知道「新队友 clone 下来还能不能开工」。

```
给「知所栖 135」项目写一个冒烟测试 scripts/test-delivery-smoke.mjs。

被测对象：交付给队友的数据包。目标是回答一个问题——
「一个人 git clone 下来，最短路径能不能走到『前端能画出图』」。

要求：
1. 只测主干，不测边界。边界归对抗性测试。
2. 断言要打在这条链上，按顺序：
   文件存在 → JSON 可解析 → count 字段自洽 → manifest 计数与文件实况一致
   → manifest 校验和与文件 SHA-256 一致 → 图能建起来（id 唯一、依赖两端可达）
   → 契约声明的接口与 serve-lib.mjs 实际路由一致 → mock 包可加载 → 壳 payload 形状对
3. **契约里点名的每一个数据源都要逐个断言存在**，并在输出里标出它是契约的哪一条。
4. 接口那条要**双向**查：契约声明了但没实现 → 红；实现了但没写进契约 → 也红。
5. 不需要 serve、不需要 API key、不联网。
6. 输出格式：`✓/✗ + 一句人话`，最后一行 `=== N 通过 · M 失败 ===`，失败时 exit 1。

不要写「检查文件是否看起来合理」这种模糊断言 —— 每条都要能指出具体是哪个字段、哪个数对不上。
```

## 二、对抗性测试 · 提示词

**用途**：假设数据被改坏 / 投毒 / 注入，问「谁会发现」。

```
给「知所栖 135」项目写一个对抗性测试 scripts/test-delivery-adversarial.mjs。

被测对象：概念地图交付包（topics / dependencies / relations / clusters / manifest）
+ 壳的单文件产物 + wiki 文件名生成 + 契约文档。

【最重要的一条设计原则】
每一条攻击都必须交给**真验收器**（scripts/cm-validate.mjs）去判，不许自己写个判据判一遍。
自己判自己等于没判。验收器支持 --dir=<路径>，所以做法是：
把真数据复制到临时目录 → 投毒 → 用真验收器跑那份副本 → 看它红不红。
另配一条阳性对照：干净副本必须绿。否则后面全是假阳性。

每条攻击要同时满足两个条件才算通过：
  ① 验收器必须红（抓得到）
  ② 错误信息必须提到对的东西（不是被别的错碰巧撞红）
  所以每条攻击都要带一个关键词，去匹配验收器的输出。

要覆盖的攻击面：
A. 篡改检测 —— 改一个概念名 / 删一条，不动 manifest，校验和必须抓到
B. 引用完整性 —— 依赖或关联指向不存在的概念
C. 图结构 —— 自环、A→B 且 B→A 成环、重复 id
D. 分布表 —— 两类都要单独测：
   ① 少一个桶（合计变少）② 把一个桶的内容挪进另一个桶（**合计不变**，只有逐桶比对能抓）
E. 类型混淆 —— centrality 给字符串 / 越界、depth 给负数、id 用 SQL 风格字符串、id 用 __proto__
F. XSS 静态 —— 扫壳源码里所有 ${...} 插值，凡是不以 esc( 开头的都算未转义；
   按字段名分出「自由文本字段」（name/gloss/why/description…）。
   **必须全文扫，不能按行扫** —— 跨行模板里的插值按行扫会整个漏掉。
   允许白名单，但**每条白名单必须写理由**（比如「来源受 ^[a-z0-9-]+$ 约束」），
   不许写「这个字段我懒得管」。
G. XSS 动态 —— 真投毒 + 真无头浏览器：
   - 把 payload 注入概念名，写一份临时单文件，用 Chrome 打开，调 openPanel(id)，看 window.__XSS__ 有没有被置 1
   - **必须有阳性对照**：同一段 payload 直接写进 innerHTML，必须执行。
     没有这一步，「没执行」既可能是转义生效了，也可能是 payload 根本不 work —— 那样整节都是空断言
   - 每段探测**各自先清零标志位**，否则第一次置上的 1 会被第二次读到（假阳性）
   - 等面板**真的画成目标节点**再断言，不要固定 sleep
H. 路径穿越 —— wiki 页名生成函数。**从 cm-build-wiki.mjs 源码里现抽那个表达式再施加**，
   不要复制一份到测试里（复制的那份会和真源码漂移）。用 ../../etc/passwd、..、.、
   反斜杠、重叠斜杠、空名、NUL、RTL override 等构造，断言生成的文件名始终关在 concepts/ 目录内。
I. Unicode 与数据质量 —— 扫真实数据：零宽字符、方向控制符、首尾空白、超长名、重名
J. 契约漂移 —— 契约 §三 声明的 payload 字段 vs 实际字段，缺的必须红
K. 陈旧检测能力 —— manifest.generatedAt + 校验和够不够让消费者自证手上是最新的，
   不够就照实说「这是 git 的固有属性，不是交付包的缺陷」

输出：`✓/✗ + 一句人话 + 失败时的诊断信息`，最后 `=== N 通过 · M 失败 ===`。
临时目录用 mkdtempSync，跑完删掉（Chrome profile 目录要 maxRetries，否则 ENOTEMPTY）。
```

## 三、压力测试 · 提示词

**用途**：数据涨 10 倍后会不会崩。测**规模**，不测正确性。

```
给「知所栖 135」项目写一个压力测试 scripts/test-delivery-stress.mjs。

被测对象：概念地图交付包（936 概念 / 531 依赖 / 3333 关联 / 936 个 wiki 文件）。

要求：
1. 每个指标都**记真实数字**，只在「病态退化」时判红。阈值放很宽 ——
   目的是抓「某天数据涨 10 倍后突然变慢/爆内存」，不是卡今天这点量。
2. 覆盖：
   - 冷启动：读盘 + JSON.parse 四个文件，分别计时，报常驻堆与磁盘的膨胀比
   - 图构建：邻接表（前端画图前第一件事）
   - 全源可达性：从**每个**概念出发 BFS（最坏情况），上下游两个方向都做
   - 拓扑排序 + 最长依赖链
   - 度数分布 + 最坏节点识别（前置最多的是谁、解锁最多的是谁）
   - JSON 往返（前端要往 localStorage 塞）
   - wiki 936 个文件全量读（模拟 Obsidian 打开这一层）
   - 单文件壳：内联 payload 的 parse 成本，换算成弱机首屏
   - 服务端并发（--serve 才跑）：50 / 200 并发打 /api/health，30 并发取 721KB 页面
   - 稳定性：同一件事跑 3 轮，看耗时极差
3. 【踩过的坑，必须写进注释】邻接表命名要说清方向：
   needs[x] = x 必须先会的前置；unlocks[p] = 会了 p 之后解锁的。
   第一版用了 fwd/back 这种含糊命名，把方向搞反了，
   结果「拓扑序只覆盖 511/936、最长链 0 层」—— 看着像数据有环，其实是测试写错了。
   所以加一条断言：最长链必须 >0 层，等于 0 就说明边方向算反了。
4. 用 performance.now() 计时，用 --expose-gc 时的 heapUsed 测内存。
```

## 六、这一轮测试查出来的真问题（都修了）

| # | 问题 | 谁发现的 | 怎么修的 |
|---|---|---|---|
| 1 | **`cm-validate` 遇到悬空引用会崩**（未捕获 TypeError），而「依赖指向不存在的概念」正是它该干净报出来的那种损坏 | 对抗性 [2] | DAG 阶段加端点存在性检查，跳过悬空边；悬空已在上游逐条报过 |
| 2 | **分布表的「合计检查」挡不住重分类**——把 80 条 neican 算进 harnessOnly，合计仍是 936，整个溜过去 | 对抗性 [4] | 加「逐桶比对」：从 topics 现算分布，和 manifest 一个桶一个桶对 |
| 3 | **`depth` 负数能溜过去**（schema 写了 minimum 0，校验器从没查） | 对抗性 [5] | 补 `Number.isInteger(t.depth) && t.depth >= 0` |
| 4 | **`cm-validate --dir=` 传绝对路径会被拼进项目里**（`path.join` 吃掉绝对路径） | 对抗性准备阶段 | 改成 `path.resolve`，相对路径行为不变 |
| 5 | **壳里 6 处自由文本没转义**，其中 `<h2>${n.name}</h2>` 是概念详情的大标题 | 对抗性 [6] 全部 + [7] 真浏览器**确认可利用** | 6 处补 `esc()`；重建后真浏览器复测不执行、渲染成 `&lt;img` |
| 6 | 我自己的测试代码把邻接表方向写反了（拓扑序 511/936） | 压力 [4] | 改成 needs/unlocks 命名 + 加「最长链必须 >0 层」断言 |

**第 5 条要说清楚**：不是理论风险。2026-09-13 03:0x 的真无头 Chrome 实测，
在当时的构建里把 `<img src=x onerror="window.__XSS__=1">` 塞进概念名，
调 `openPanel()` 后 **`window.__XSS__` 真的被置成了 1**。
今天不可利用**只因为** 936 个名字里恰好 0 个含 `<`/`>` —— 而概念名来自
Notion / 飞书 / 内参外部内容，重新生成一次就可能带进来。

## 七、没测的（照实标）

1. **没测数据本身的「对不对」** —— 定义准不准、依赖边成立不成立。
   那归 `cm-validate` 的抽检和 `docs/概念地图v2-审核报告-20260913.md`，测试只保证**结构和一致性**。
2. **没测 LLM 输出质量** —— `/api/llm` 的回复好不好，压力测试只打 `/api/health`（不打 LLM，会烧 token）。
3. **没测浏览器兼容性** —— 只在 Chrome 上验证过。
4. **没测移动端 / 弱网** —— 首屏 1.2MB 那个数字是算出来的，不是在真 3G 上量的。
5. **没测桌面版（Electron）** —— 归 `scripts/test-app.mjs`。
6. **并发压测只打了本地 127.0.0.1** —— 没有公网链路、没有 GitHub Pages 的 CDN 行为。
