## 0. 结论先行

**内参调研的净结果：形态不需要改，需要改的是「对外怎么讲」和「验收层再补一件小东西」。**

三条结论，按可执行性排序：

1. **最强的外部先例不是 llm_wiki，是吴恩达的 LearnVector**（内参 260906 期）。它把行业最强的一笔钱押在同一件事上——「学的单位从课程变成下一步教学动作」。知所栖 135 的 1/3/5 正是「下一步该讲解、提问、练习、测试还是反思」的一次具体编排。**这条要在路演稿里顶到最前面**，因为它把「你们是不是想多了」这个质疑，换成「你和吴恩达在同一个问题上，而你的粒度更细」。
2. **费曼验收层缺的那一件，是「限速器」，不是「更强的判定」**。两条独立证据指向同一处：Anthropic 的随机对照实验（内参 260317 期）显示，学习效果的分水岭不在用不用 AI，而在**生成之后有没有主动追问**（最高分模式 86% vs 全委托 31%）；Geoffrey Litt（内参 260815 期）把「解释末尾放测验、答不过就不交付」称为**速度调节器**。知所栖现在只有判定、没有节流——答不过就倒回，但**没有阻止用户跳过复述直接点下一章**。
3. **「机器反过来向人提问」有了一手佐证，但仍然没有先例，别当卖点讲**。内参 260902 期 howie 直播把「错题 loop／概念 loop」说成成人版错题本，机制上与我们一致；但他做的是**人主动走 loop**，不是**系统主动回问**。我们那条「无同构先例」的判断（`research/历史案例-结构同构-10案例.md`）仍然成立，且现在有了更清楚的定位：**我们是把「人主动走 loop」翻成「系统替人记账并回问」**。

**一句话交付**：形态不动，路演稿换先例（llm_wiki → LearnVector），验收层加一个可跳过的限速器。

## 2. 三条落地依据（把内参翻译成产品语言）

### 2.1 依据一：学的单位变了，135 的口径正好踩在变化点上（E1 + E5）

LearnVector 的中心命题是：过去的平台生产一门课程，未来的平台生产「针对这个人、此时此刻的下一个教学动作」。吴恩达把问题追到成本结构上——印刷术、广播电视、MOOC 降低的都是**内容复制的成本**，从未降低过**为每一个学习者分别作出教学判断的成本**。

**这句话就是知所栖 135 的立项理由，而且是内参里能拿到的最高级别背书**（Coursera 投 1 亿美元、估值近 3 亿）。135 的 1/3/5 不是三个功能，是**三个不同的教学动作**：读（讲解）、决策（提问 + 判断）、实验（练习）。费曼验收是第四个动作：测试。

**路演稿可直接用的一句**：

> 以前的平台生产的是一门课，我们要生产的是「你此刻应该做的下一个动作」。读懂 → 判断 → 尝试 → 讲一遍，每一步都是一个不同的教学动作，而不是同一节课的不同章节。

**必须同时说的边界**（否则变成硬蹭）：
- LearnVector 到 2027 年初才出产品，它的判断是**假设**，不是已验证结论；
- 它明确不做聊天机器人，也不做「把现有课程用 AI 重讲一遍」——和我们的「不做裸聊天」是同一条纪律（与项目已有的 Bastani 2025 结论一致）。

### 2.2 依据二：学习效果的分水岭是「有没有追问」，不是「有没有 AI」（E3 + E6）

Anthropic 的 RCT（52 名有经验的 Python 开发者，学一个从未用过的异步库 Trio）给出了本项目能拿到的最硬的量化证据：

| 交互模式 | n | 测验分 | 说明 |
|---|---:|---:|---|
| 渐进依赖 Progressive Reliance | 4 | **24%** | 第一题自己想，第二题全交给 AI |
| AI 全委托 AI Delegation | 4 | **31%** | 直接让 AI 写完；**速度最快、错误最少、学到最少** |
| 反复让 AI 调试 | 4 | 35% | 遇到错误就丢给 AI |
| 混合代码-解释 | 3 | 65% | 每次同时要代码和解释 |
| 只问概念 Conceptual Inquiry | 7 | 68% | 只问概念，自己写代码 |
| **先生成后理解** | 2 | **86%** | 行为看起来**几乎等同全委托**，多了一步主动追问 |

总体：AI 组平均 50%，对照组 67%，差 17%（Cohen's d = 0.738, p = 0.01）。**效率上 AI 组只快约 2 分钟且不显著**。

**这张表对知所栖的直接含义**：

1. **产品最该防的失败模式是「渐进依赖」**，不是「不用 AI」。24% 是所有模式里最低的——用户第一题认真做、第二题起全部外包，正是学习产品最常见的真实轨迹。
2. **「先生成后理解」和「全委托」在界面上几乎一样**。这说明**关键差异不在交互形态，在有没有强制的那一步追问**。这一步在 135 里就是费曼演练室。
3. **费曼演练室的正确定位是「不许跳过的追问」**，而不是「一个额外的可选环节」。目前它的实现是「点开 → 复述 → 判定 → 漏点倒回」，但**没有阻止用户不点它、直接走完三个概念就离开**。这是产品与最强证据之间唯一的实质缺口。

E6 补上了机制细节：好反馈必须「**一定会带来跟进练习**」。135 的「漏点 → 倒回对应模块」符合这条，但倒回之后**没有再验收一轮**（Bloom 的掌握学习要求「形成性测验 → 纠正 → 平行测验」，135 缺了第三个）。

### 2.3 依据三：「错题 loop」已经有人在做，但没人做「系统回问」（E4 + E7 + E9）

howie 直播把学习系统的内核说得很直白：

> 「一个 agentic 的数学／编程／理科学习系统，核心不是里面那五六个 skill，而是它建立了**一个错题 loop**。」
> 「学生要发现自己的错题，成年人要发现自己概念的缺口。概念 loop 是成人版的错题 loop。」

他的概念 loop 操作流程是：在具体问题中发现缺口 → 新建笔记、用 5W2H 初始化 → 让 LLM 做概念综述 → 反复重读重编（第二遍、第三遍……到第八遍）→ 输出和应用。

**与我们形态的关系，要说清楚两件事**：

- **同**：都认为「缺口」是学习系统的入口单位；都认为「变成 Markdown 文档」这个动作本身让知识成立；都反对全 AI 驱动（「如果全部都是 AI 驱动的，那只能说它是一个 slop」）。
- **异（这才是我们的位置）**：他的 loop **由人主动发起**——人发现自己不会 git worktree，才去建那条笔记。我们主张的是**让系统替人记账、并在下一次主动回问**。E7 那篇正好给出了为什么需要这一步：750 篇笔记之后，「一年前写的内容在脑海中已基本不剩痕迹，以至于看见某些新东西会不自觉地当作新知识重新学习」——**人不会主动发现自己忘了什么**。

**结论不变**：这条仍然没有已运行先例（`research/历史案例-结构同构-10案例.md` 的「SuperMemo 与 mnemonic medium 只问你记得吗，不问缺什么」判断成立，且现在有了内参侧的独立印证）。**可以做，但对外不要说「机器提问提升学习」**——内参 E1 与项目理论文档给出的是同一条纪律：提问有效有强证据（Yang 等 2021，g = 0.499），但「机器生成问题带来学习收益」只有小样本，没有元分析支持。

## 3. 形态收敛：动什么、不动什么、加什么

### 3.1 不动（已建成且证据支持）

| 机制 | 内参证据 | 结论 |
|---|---|---|
| 1 互动阅读器（dbs-learning 三层梯度） | E2「先直觉，后细节」 | 与 Litt 的两条原则逐字对上，保留 |
| 3 案例决策场（同构比较 + 条件答案表） | E6「反馈要具体、可追溯」 | 「不给唯一正确答案」符合「对人不对事」的反馈原则 |
| 5 技术实验台（动手 + 写结论） | E2「微世界：住进去而不是读进去」 | Litt 的 micro-worlds 与「动手改参数看结果」同构，且他明确说「亲手做的过程才是理解生长的地方」 |
| 不接裸聊天、所有 AI 介入带结构 | E3「先生成后理解」+ 项目 Bastani 2025 | 两条独立来源同结论，纪律保留 |
| workflow 而非 agent | E4「agent 在 loop 里调用工具」 | 不冲突：我们的 loop 是**教学设计**的 loop，不是 runtime 的 agent loop |

### 3.2 改一处：费曼演练室从「可选环节」变成「限速器」（2026-09-12 已实现）

**问题**：E2 把测验称为 speed regulator——「和 AI 一起工作时，循环极容易转得比人类理解的速度更快」。E3 显示 24% 的失败模式是「第一题认真、第二题外包」。135 原先无法阻止这个轨迹。

**改法（已落地，不新增依赖）**：

1. **未复述不结算**：三个模块走完后未进费曼演练室，首页显示「本次尚未验收」并给出直达按钮。`state.feyn[].pass` 从记录项提升为结算条件。
2. **补过之后必须再讲一次**（补 E6 的「跟进练习」与 Bloom 的平行测验）：漏点记为 `remediation='pending'`，倒回模块后**不自动销账**；只有再次复述并覆盖该点才转 `done`，报告显示「补上了上一轮的漏点」并统计本轮闭环数。
3. **验收标准写成可当场判定的动作**（抄 E5 的写法）：界面明写「3 个概念都要讲到，每个概念至少讲到位 2 条要点，全部通过才算验收」——与引擎实际判定阈值一致，不泄露答案要点。
4. **必须可跳过**（Horvitz 1999 硬边界）：新增「这次跳过验收」按钮，跳过后 `state.feynSkipped=true`，首页记「已跳过验收——不算未通过」。误报会导致整体弃用（Parasuraman & Riley 1997），这条不能省。

**改动位置**：`prototype/知所栖-135-基础框架.html`（`freshState` / `viewHome` / `viewFeynman` / `skipFeynman` / `runFeynman`）、`scripts/verify-135.mjs`。

**验收结果**：`node scripts/verify-135.mjs` **60/60 通过**（原 43 项 + 新增 17 项），无 JS 异常。新增检查覆盖：未复述显示未验收、跳过记为未验收且不产生「未通过」、漏点进 pending、重讲后转 done、闭环数统计。测试用两次真实验证复述（先只讲景别制造真漏点，再讲全）跑通完整闭环。

### 3.3 加一件（可选，只在 48 小时有余量时做）：把「概念缺口账本」的措辞收紧

`docs/135-llm_wiki-融合形态方案.md` 已把它定为唯一的新增件。按内参证据只需改一处措辞：

- 现状表述：「缺口由机器发现、由人裁决」
- **收紧为**：「机器只记账，人做裁决；机器不新增提问类型」

理由来自 E4 与 E5：howie 的概念 loop 里，判断「这个缺口值不值得补」始终是人做的；OpenAI 学习模式提示词的写法是**把约束写成能当场判定的动作**并**收窄动作集**（「一次只问一个问题」「尝试两次」）。我们的三动作（回答／建页／跳过）已经是收窄设计，保持即可，**不要**在 48 小时内新增第四种动作。

## 3.4 接真实 LLM API（2026-09-12 已接通）

**结论：C1 管线（真实知乎检索 → LLM 单轮判定）已在页面、验证脚本、AB 实验三处全部跑通。**

| 项 | 值 |
|---|---|
| 提供方 | DeepSeek（OpenAI 兼容） |
| 模型 | **DeepSeek V4 Flash**，canonical id `deepseek-flash`（`/models` 列出的就是它）。`deepseek-v4-flash` 是**等价别名**，实测解析到同一模型；`deepseek-v4-pro` 为升级项 |
| 凭证位置 | `.private/llm.env`（600；`.private/` 已在 `.gitignore`）——**key 未出现在任何会提交的文件里** |
| 加载方式 | `scripts/serve-135.mjs` 启动时自动读取，只补未设置的变量，不覆盖 shell 已有值；文件不存在则静默跳过并回退规则引擎 |
| 健康检查 | `GET /api/health` → `{"ok":true,"llm":true}` |

**页面行为**：经 serve 访问时顶栏徽章变「轻量 Agent：真实检索 + LLM」，费曼报告引擎标识为 `C1-pipeline(llm+live-search)`；双击直接打开仍走离线规则 + 检索快照。

**验证**：`node scripts/verify-135.mjs` 在**两种模式下各 61/61 通过**（LLM 模式与离线模式分别实测）。原来那条写死的「离线规则引擎标识：A-rules」已改为**断言引擎标识与当前运行模式一致**——否则一旦接上 key 测试就会假失败。这条断言同时成了**静默降级的探测器**：LLM 若调用失败而回退规则引擎，测试会直接报红，而不是悄悄放过。

### 3.4.1 一个已知约束：DeepSeek JSON 模式要求提示词含 "json"

`serve-135.mjs` 固定带 `response_format: {"type":"json_object"}`。DeepSeek 的约束是**提示词里必须出现 "json" 字样，否则直接 HTTP 400**（实测报错原文：`Prompt must contain the word 'json' in some form to use 'response_format' of type 'json_object'`）。

- **产品路径不受影响**：费曼提示词含「只输出 JSON」，满足条件（实测返回 `{"pass":true}`，响应 `model` 字段为 `deepseek-flash`）。
- **诊断已改进**：`llmForward` 失败时现在原样带出上游报错体（`detail` 字段），不再只回一个无从下手的 `llm-http-400`。
- **注意**：若日后新增不带 JSON 字样的 LLM 调用，会 400 并回退规则引擎；靠 verify 那条引擎标识断言兜底。

### 3.4.2 顺带查出的一个真 bug：C1 从未真正跑过检索

`scripts/ab-feynman-test.mjs` 的 `zhihuSearch()` 读的是 `j.data?.items`（小写），而知乎 CLI 实际返回 `Data.Items`（PascalCase，与 `serve-135.mjs` 一致）。后果：

- 检索 **100% 失败** → `groupC1()` 静默回退 → 实验组名变成 `C1-fallback-to-B`，**C1 与 B 是同一条路径**；
- 而预注册的决策规则是「B 准确率 ≈ C → 用 B」「C1 与 C2 打平 → 用 C1」——**拿这样的数据去比，结论必然指向「B 就够了」**；
- 这是一个**由解析 bug 制造的假阴性**，不是证据。差一点就用它替团队做了「不引入检索」的决策。

**已修**：改为 `j.Data?.Items`、字段改 `Title` / `ContentText`；并在主流程前加**预检（开环报警）**——检索不通直接 `exit(3)` 并打印原因，不再允许静默降级。这条对应用户项目已有的「开环报警」原则：后端没有反馈时应当报警，而不是继续跑。

**修复后实测**（`evidence/ab-feynman-smoke-test.json`）：

| 组 | 平均准确率 | 平均 tokens | 平均耗时 |
|---|---:|---:|---:|
| A-rules（离线基线） | 100% | 0 | 1 ms |
| B-bare-llm | 100% | 1638 | 6204 ms |
| **C1-lightweight-pipeline** | 100% | 1628 | **3393 ms** |

**这张表不能当结论用**：样本是模板里的 2 条示例，太简单，三组都是 100%，区分不出差别。它只证明**三组都能跑通、C1 已走真实检索**。正式结论仍需 10 份真人复述 + 人工标注真值（填入 `scripts/ab-samples.json` 后重跑）。已删除示例版 `ab-samples.json`，避免被误当成实验数据。

## 5.5 「我想成为怎样的学者」是知识问题还是心理问题（2026-09-12 讨论结论）

**结论：它是两段，产品只能做前一段。判据是「有没有 ground truth」。**

| 段 | 内容 | 类型 | 有无 ground truth | 产品该不该做 |
|---|---|---|---|---|
| 前段 | 不知道**有哪些**学者形态、各自在做什么、代价是什么 | **知识问题** | 有——可核实、可枚举 | **该做**：供给参照点 |
| 中段 | 知道了但不想要 | 动机／价值问题 | 无 | 不做：不是信息能解决的 |
| 后段 | 想要但不确定自己能不能 | 自我效能感 | 无（但可由行为观测代理） | 间接做：靠「做到 → 及时反馈」而非靠问 |
| — | 想要什么一直在变 | 建构而非发现 | 无（对象尚未存在） | **不问**：快照式提问测的是移动靶 |

**四条推论**：

1. **「了解人」成本高的真正原因不是成本，是对象还不存在。** 身份是**建构**出来的，不是**发现**出来的。用一次问答去「了解」它，等于用快照仪器测移动靶。所以 `purpose.md` 那一层如果做成「你来说说你想成为什么样的学者」的输入框，方向就是错的。

2. **不能假设学习者知道自己想成为什么**，和不能假设他知道自己缺什么是同一条边界。项目理论文档已用 Loewenstein（1994）写死了后者（「觉察缺口是好奇心的必要前提」，且人对自己的无知「fat but happy」）；前者是同一条的镜像——**参照点不足时，他连可选项都列不出来**。Loewenstein 原话「好奇心源于信息参照点升高到超过当前知识水平之上」正好说明：先给参照点，才谈得上想要。

3. **真正的顺序是反的：先做到，再看见自己想成为谁。** E4 的内驱力 loop 链条是「最近发展区 → 做到一些事情 → 及时正面反馈 → I can do it → 驱动下一步」，链条里**没有**「先想清楚想成为谁」这一环。身份是行动的副产品，不是行动的前提。

4. **所以「了解人」的正确输入不是 self-report，是行为轨迹。** 你提的「用文档记录 / AI agent 自迭代去拟合学习曲线」这个思路成立，但拟合的输入该是**他实际做成了什么、在哪里卡住、卡住后又去做了什么**（可观测），而不是**他说他想成为谁**（不可靠）。这也是为什么限速器必须记 `remediation` 状态——那份账本正是将来拟合曲线要用的原料。

**对产品的三条落地含义**：

- **demo 阶段**：默认面向「已有学习意图的学习者」，把「了解人」整段推到后面。这个取舍是对的，且与 E3 的纪律一致——**产品的可做边界是「调动」主观能动性，不是「判定」它**。
- **意图层若要做**：只做**参照点供给**（这个领域有哪些学者形态、各自日常在做什么、代价是什么），不做**偏好采集**。前者是知识问题、有 ground truth、可验证；后者是心理问题、无 ground truth、答了也不准。
- **对外表述**：可以说「我们不问你想成为谁，我们让你先做到，再看见」；不能说「我们能判断你的学习动机」（无依据，且属心理评估边界）。
