# 语义单元到 135：队友傻瓜教程

这套方法只做一件事：从已经存在的五类语义单元，装配一份判断材料。A 已有可运行页面；B / C / D 由队友各自选择入口问题后补写。

## 你要交付什么

每份材料都必须有：

```text
QST 问题 → 1 阅读材料 → 3 个判断选项 → 5 个可执行步骤 → 费曼复述
```

五类单元的职责固定为：QST 提问，CON 定义边界，OPI 给判断依据，CAS 给假设情境，SOL 给动作路径。缺哪类就标记缺口，不现场编造事实。

## 先查，再装配

在项目根目录运行：

```sh
node 内容结构化系统/模块/ai-concept-base/scripts/query.mjs --q "你的主题" --type 问题单元 --json
node 内容结构化系统/模块/ai-concept-base/scripts/query.mjs --id 你的-QST-ID --json
```

确认 QST 后，再确认至少一个相关 CON、一个 OPI、一个 CAS 和一个 SOL。优先使用语义单元的 `relationships` 和 `source_documents`；不要只按标题相似度拼接。

## 批量装配

编辑 `docs/mvp-materials.json`，每个材料填写真实 ID：

```json
{
  "id": "B-your-topic",
  "qst": "QST-...",
  "concepts": ["CON-..."],
  "opinions": ["OPI-..."],
  "cases": ["CAS-..."],
  "solutions": ["SOL-..."],
  "selfChecks": ["QST-..."],
  "out": "docs/mvp-generated/B-your-topic.md"
}
```

运行：

```sh
node scripts/build-mvp-materials.mjs docs/mvp-materials.json
```

脚本会校验 ID 和类型；已有文件默认跳过，不覆盖。需要重建时先人工确认，再加 `--overwrite`。输出只是可追溯的语义装配包，不代表材料已经跑通。

## 把装配包变成判断材料

1. 从 QST 写清一个具体判断问题。
2. 从 CON 写出概念边界，最多保留 3 个。
3. 从 OPI 写出支持判断的理由；不能把观点写成实验结果。
4. 从 CAS 改写一个明确标注“假设场景”的情境。
5. 从 SOL 提取 3—5 步动作，说明每一步记录什么。
6. 加一个费曼复述题，让使用者解释自己的判断。

AI 可以帮助改写情境和选项，但必须标注“AI 生成／改写、假设场景”，并保留所有语义单元 ID 与来源。

## A 的验收方式

直接打开 `prototype/mvp-a-context-rot.html`，完成阅读、选择、控制变量、行动记录和费曼复述。页面只确认填写完整，不替你生成结果；实际观察值由执行者记录。

B / C / D 复用同一结构即可。不要补全 538 条单元，也不要启动服务或调用模型。
