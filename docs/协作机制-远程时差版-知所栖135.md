# 协作机制 · 远程 + 有时差版（知所栖 135）

> 前提：我们不在同一间屋子，还各自有时差。**所以团队同步不靠会议，靠这四样东西**：
> 契约、命令、日志、交接件。任何一句"我以为你知道"都是 bug。
> 建立：2026-09-13 01:4x（开赛前夜）

## 一、四条铁规

1. **契约只加不改**：`docs/前端契约-知所栖135.md` 里的字段名与含义冻结。要改 → 先说一声 → 改完**同一次提交里**更新契约文件。
2. **产物不手改**：前端只改 `scripts/shell.template.html`，不碰 `prototype/` 下的产物（那是构建结果，会被覆盖）。
3. **说了不算，脚本说了算**：任何人说"改好了"，必须附上四套验收里相关那几套的输出。
4. **演示里出现的每条命令、每个地址，必须是本人跑过一遍的**（不许写"应该可以"）。

## 二、一条命令（所有人都用同一条）

```sh
node scripts/serve-135.mjs        # 起服务 → http://127.0.0.1:5180/知所栖-壳.html
node scripts/shot-shell.mjs       # 截图 + 面板越界断言
node scripts/test-daobi.mjs       # 倒逼层 + 分类层 + 三栏外壳
node scripts/verify-135.mjs       # 主流程 61 项
node scripts/check-public.mjs     # 公网单文件 22 项（必须假域名 + --no-proxy-server）
```

**跨时区不靠嘴**：谁在什么时候改了什么，看脚本输出 + 工作日志，不看聊天记录。

## 三、班次交接件（每班结束写，5 行，1 分钟）

写在 `docs/工作日志-知所栖135.md` 最新一轮的最上面，格式固定：

```markdown
### 班次交接 · <你的名字> · <结束时间 HH:MM>
- 做了什么：（一句话）
- 证据：（跑了哪个脚本 / 哪个地址返回 200 / 哪个文件变了）
- 卡在哪：（没有就写"无"）
- 下一步：（下一个人可以直接开始的那一件事）
- 需要谁：（要点谁的名，就 @ 谁并写清要他做什么）
```

**下一班开工第一件事：读上一条交接件**，读完再动手，不要重新问一遍。

## 四、冻结线（今晚起生效）

| 时间 | 冻结什么 | 冻结后谁都不能碰 |
|---|---|---|
| 今晚 24:00 | **契约 + 数据字段** | 字段名与含义；要加字段可以，改不行 |
| 明天 10:00 开赛后 | **主流程与判定口径** | 1 阅读 → 3 决策 → 5 实验 → 费曼验收 的步骤顺序；判定标准 |

## 五、PR 与分支（防互踩）

- `main` 只接受 PR，**任何人不得直接推 main**。
- 一个 PR 一件事，标题写「改了什么 + 影响到谁」。
- PR 描述里必须贴：跑过的验收脚本输出 + 是否动了契约字段（动了就 @ 技术负责人）。
- 冲突了不要自己乱合：**谁后改谁 rebase**，rebase 完重跑验收。

## 六、谁兜底（按当前在线的人轮）

因为有时差，任何时刻只有一部分人在线。所以要明确**当前这一班的兜底人**：

- 兜底人负责：接现场提问、跑验收、决定"能不能合"。
- 换班时在交接件里写清「下一班兜底人是谁」。
- 没人兜底的时段：**不合并、不发版、不改数据**——只做本地草稿。

## 七、这份机制为什么值得花 10 分钟

我们不缺人，缺的是**同时在线的时间**。上面每一条都是把"需要两个人同时在线"的事情，变成"一个人就能完成、另一个人起床后能读懂"的事情：

- 契约 → 代替「我跟你讲过」
- 命令 → 代替「你帮我看看」
- 交接件 → 代替「昨天那个进度到哪了」
- 冻结线 → 代替「别乱改」（因为不用再问）
- PR 规则 → 代替「你先别推，我这边还没好」
