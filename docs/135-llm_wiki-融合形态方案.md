## 0. 直接答案

能平均，但只在「人机分工」这一层平均。llm_wiki 的产品形态（Tauri 桌面端、摄入队列、向量库、图谱工程、Tavily 深度研究）服务的是「材料持续增长、维护记账记不过来」这笔账；135 的形态服务的是「一次理解要能被检验、被讲出来」这笔账，两者不是同一件事。可搬的是它从 Karpathy 模式原样继承的那条分工——人策划、机器维护——以及由这条分工长出来的两个零件：**意图层**（purpose.md）与**「缺口 → 收敛动作」结构**（图谱洞察 + 三动作评审队列）。把这两个零件接到 135 上，锦上添花只落在一处：费曼验收暴露的漏点从一次性结算升级为**跨会话的认知缺口账本**，让产品在下一轮先拿旧漏点问你。

**灵魂与分工的定稿建议**：灵魂 = **把「你意识不到自己缺什么」变成产品替你做的事**。理论依据是 Loewenstein（1994）的边界原话——觉察缺口是好奇心的必要前提，而人对自己的无知普遍浑然不觉（"fat but happy"）——所以「让知识库反过来向你提问」这条直觉机制上成立，但方向要改一处：**缺口由机器发现、由人裁决**，不是「人提供认知缺口」（人恰恰看不见它）。分工写成一句话：**人提供意图与判断（学什么、为什么学、认不认这个缺口），机器提供记账、发现与提问。**

**这一条的历史证据**：十个同构案例里，「系统向人提问」只有两张先例——SuperMemo 的 items 排程与 mnemonic medium 的提示调度，且都只问「你记得吗」，不问「你缺什么」；由**缺口 / 意外连接驱动**的提问**没有任何已运行先例**。它既是可占位的差异点，也意味着没有可抄的设计参数：必须小步、默认关闭或可一键终止（Horvitz 1999 的混合主动式原则），并且要防误报——Parasuraman & Riley（1997）指出 disuse 常由误报引起，一次判错缺口就可能让用户整体关掉这个功能。

**两处必须纠正的前提**：
1. **「让知识库反过来向你提问」不是 llm_wiki 的已实现功能**。README 里对应的是 Graph Insights（surprising connections / knowledge gaps，度 ≤ 1 的孤立页）＋一键 Deep Research＋异步评审队列；「反问」是 AI内参 的解读，仓库代码里没有「知识库主动向用户提问」这一条（唯一相关的 `AskUserQuestion` 是 Agent 技能向用户要参数）。上游没做，谁先做谁占位。
2. **对外表述别宣称「机器提问提升学习」**。「提问有效」有强证据（Yang 等 2021：222 项研究、g = 0.499）；「机器生成问题带来学习收益」只有小样本实验，没有元分析支持；「检测缺口后自动提问」没有任何直接研究。路演稿的统一说法是「提取练习 + 反馈」，机器出题只是实现方式。

## 1. 前置筛选：JTBD 判断（组合里的第一道闸）

**表面请求**：用 llm_wiki 的 idea 和 135 三个模块做一次「平均」，再加一层锦上添花。

**任务陈述**：当我处在「48 小时内要把自有方法论工程化成可演示产品」这个情境，我想要把已成型的三模块和一个外来 idea 收敛成一条一眼能看懂的骨架，以便在 DDR 与评审现场被记住为「有方法论的骨架」而不是「三个功能的拼盘」。

**三层任务**：
- 功能：一份可讨论、可拍板的融合形态（保留什么、改什么、加什么、不做什么）；
- 情绪：摆脱「我们只有三个模块、没有长期骨架」的不安；
- 社会：让团队与评委看到骨架和角色分工，而不是功能清单。

**为什么是现在**：09-12 08:30 要交基础框架并整合公共版；09-13 10:00 开赛，48 小时里再改形态的成本极高。

**选择标准**：
1. 必须满足：评委或团队听完 30 秒能复述出「这个产品的灵魂一句话」；
2. 必须满足：每个被搬进来的机制都能回答「人做什么、LLM 做什么」；
3. 加分项：搬进来的东西在 48 小时内可落地，不需要新调研、新依赖、新硬件；
4. 可接受代价：为了骨架清晰，砍掉已经写好的炫技功能。

**切换四力**：
- 推力：135 目前是「读 → 判断 → 尝试 → 验收」的一条流水线，跑完即结束，学习者下次进来从零开始，没有长期资产；
- 拉力：llm_wiki 给了「编译一次、持续维护」的长期结构，以及「人策划、机器维护」这条极好讲的分工线；
- 焦虑：它是 Tauri 桌面端 + Rust + 向量库 + 22 项跨平台工程的完整产品，48 小时内复制形态必然做成半成品；照搬还会稀释「方法论来自自有 skill」这条血统；
- 习惯：1/3/5 口径已拍板、43/43 自动验证通过、团队已按此对齐，推翻形态的协调成本高于收益。

**淘汰结论**：
- **必须进（服务同一进展或成本极低）**：人机分工这句话（人策划、机器维护）；意图层（回答「为什么存在」）；缺口 → 收敛动作（把发现的问题变成人可处理的少量动作）；来源可溯（每个页面挂 sources 字段，我们已有真实知乎链接可挂）。
- **属于「为像 llm_wiki 而加」，淘汰**：桌面端形态、摄入队列、向量库 / 嵌入、Tavily 深度研究、浏览器剪藏、多格式解析、级联删除、四信号权重调参、Louvain 社区发现与内聚度评分、多项目与场景模板。

**关键错位（这道闸的主要产出）**：两个产品的 job 不同。llm_wiki 让**资产随材料增长**（瓶颈是维护记账），135 让**能力随反馈增长**（瓶颈是理解深度）。所以「平均」不能发生在形态层，只能发生在**分工层**：把它的「知识记账」换成我们的「认知缺口记账」。

## 2. 第一部分：知识与理论挖掘

> 证据来源：`research/理论来源核实-10条.md`（书目全部经 Crossref 核对，主理论原文为 CMU 自托管 PDF 全文 OCR 核对）。

### 2.1 命题审查

**原命题 A：「人提供好奇与认知缺口，LLM 负责维护与交互」→ 审查状态：`收窄`。**
Loewenstein 原文的关键边界是「对信息缺口的觉察是产生好奇心的必要前提。因此，意识不到自己不知道什么，会成为好奇心的绝对障碍」，并指出过度自信与 "fat but happy" 是普遍现象。这条边界正好否掉了命题里「人提供认知缺口」那半句：**人恰恰看不见自己的缺口**。能成立的分工是：人提供好奇心与意图（学什么、为什么学、认不认这个缺口），机器负责记账、发现缺口、把缺口变成问题。
**修正后的标准**：人提供意图与判断，机器提供记账、缺口发现与提问；缺口由机器提出、由人裁决，而不是由人提供。

**原命题 B：「系统反过来向人提问」→ 审查状态：`保留（降级为条件性）`。**
提问作为提取事件有强证据（Yang 等 2021 元分析：222 项独立研究、48,478 名学生、g = 0.499）；「机器生成问题带来学习收益」只有小样本实验与系统综述，**没有任何元分析支持**；「系统检测缺口后自动提问」没有任何直接研究。可以说「提问有效」，不能说「机器检测缺口的提问有效」。

**原命题 C（隐含）：「费曼」作为验收层的证据 → 审查状态：`重构（命名层）`。**
费曼本人描述该「技巧」的一手文本未找到，主流索引期刊上也没有针对该具名方法的随机对照实验或元分析（只有区域小刊 2021 与 n = 14 的 Feynman Bot 可行性研究）。**有证据的是它的成分**：提取练习（g ≈ 0.50）、自我解释（元分析 g = 0.55）、生成效应（86 项研究平均 0.40）。对外应说「复述 + 漏点倒回」，把费曼当类比，不当证据来源。

### 2.3 主理论

**人物定位**：美国行为经济学／决策心理学研究者 乔治·洛温斯坦（George Loewenstein）；论文署名单位为卡内基梅隆大学社会与决策科学系。
**理论名称**：信息缺口理论（information gap theory of curiosity）。
**理论原义**：好奇心不随信息量单调增长；当注意力聚焦到「我知道什么」与「我想知道什么」之间的落差时，缺口带来剥夺感，驱动人去填补它。
**中文意译**：「人并非总是好奇，尽管他们被大片无知包围着；对自身知识状态的不满，像对物质处境的不满一样，取决于客观处境与主观参照点之间的对比。」「对信息缺口的觉察是产生好奇心的必要前提。因此，意识不到自己不知道什么，会成为好奇心的绝对障碍。」
**原始出处**：Loewenstein, G. (1994). The psychology of curiosity: A review and reinterpretation. *Psychological Bulletin*, 116(1), 75–98. DOI: 10.1037/0033-2909.116.1.75
**核实状态**：原始来源（Crossref 书目 + CMU 自托管 PDF 全文 OCR 核对）。

### 2.4 理论如何解释当前问题

| 当前问题 | 理论解释 | 得出的判断 |
|---|---|---|
| 学习者说不清自己缺什么 | 觉察缺口是好奇心的绝对障碍，且过度自信普遍 | 缺口必须由外部指出；机器的职责偏向「发现」而不是「整理」 |
| 为什么提问比继续讲解更能驱动 | 提问／谜题是最直接的好奇诱发方式（thematic probes） | 反向提问应该放在入口，而不是放在结尾总结 |
| 为什么「我懂了」不可信 | 重复学习提高信心，却不提高延迟保持 | 验收只能用提取（讲出来），不能用自评（懂了按钮） |
| 为什么难度要匹配 | 缺口必须可达到；困难需匹配先备知识 | 「缺多少问多少」：题太难变成不合意困难，太易不产生好奇 |
| 为什么漏点要倒回而不是重讲 | 提取 + 纠正性反馈才放大效应 | 漏点倒回对应模块是对的；「再讲一遍」方向相反 |

### 2.5 第一部分边界

**适合**：已有材料、有基本先备知识、缺口可被外部检测的学习场景（135 的三个概念正好属于这一类）。
**不适合**：先备知识不足时的开放式探究（Kirschner 等 2006）；把学习者的自评好奇心或自信度当作缺口存在的证据。
**反例**：SuperMemo 一次性导入 1000 页后保持率降到 60–80%；Anki 现实中 97.6% 的用户用现成牌组（「人愿意持续做判断动作」不成立）。
**仍需核实**：ZPD 定义的原书页码；「讲给别人听／教学预期」这一支的实证证据；「费曼技巧」这一名称的最早出处。

## 3. 第二部分：历史同构与标准答案

> 证据来源：`research/历史案例-结构同构-10案例.md`（695 行、115 条链接，逐条标注【已核实事实】/【作者解释】/【推断】/【待核实】）。

### 3.1 当前问题的历史定位

**现实角色**：个体方法论作者 + 小团队，处于产品化冲刺阶段（48 小时后交付演示）。
**必须实现的结果**：一个能被评委 30 秒复述的产品骨架（灵魂 + 分工 + 取舍）。
**正在争夺的稀缺资源**：时间、注意力、可信度（我们的硬规矩是「宣称必须有核实过的来源」）。
**主要矛盾**：想要 llm_wiki 那种「越用越厚」的长期骨架，但它的形态是为「材料持续增长」设计的后期工程。
**反复出现的失败循环**：加功能 → 说不清灵魂 → 再加功能。
**结构命题**：一个处于 `首次交付` 阶段的 `方法论作者团队`，依赖 `把自有方法论工程化成可演示产品`，因 `维护与长期资产仍由人承担` 难以把一次演示变成能长大的产品，同时受到 `48 小时截止与已拍板口径` 的持续牵引。

**结构指纹**：价值结构 = 方法论 → 产品 → 演示；稀缺资源 = 时间 + 判断力；核心张力 = 借来的长期骨架 vs 自己的进展；锁定机制 = 「形态平均」的冲动（把别人的完整工程当模板）；压力机制 = 截止时间 + 已对齐的口径。

### 3.2 候选问题家族

| 问题家族 | 相似结构 | 关键差异 | 研究价值 |
|---|---|---|---|
| 自动维护 + 人保留判断的分工切在哪 | 都是「机器执行、人判断」 | 那些场景有 ground truth 与公开审计，我们没有 | 高：直接决定分工线画在哪 |
| 机器按排期向人提问 | SuperMemo / Anki / mnemonic medium 都长期运行 | 它们只问「你记得吗」，不问「你缺什么」 | 高：找到差异位 |
| 自动生成的结构是否产生价值 | 社区发现、图谱视图、文献耦合 | 无同行评议的用户研究可依 | 中：作为不做清单的依据 |
| 维护成本导致弃用 | PKM / 第二大脑 | 该交叉领域几乎没有同行评议定量证据 | 中：防止引用伪数据 |
| 默认开启 vs 可撤销的信任成本 | Recall / Rewind | 我们数据量小、可本地存储 | 中：决定缺口账本的默认行为 |

### 3.3 历史案例（按同构度取六例，其余见研究报告）

**① 卢曼卡片盒（Niklas Luhmann，1951–1996）｜类比有效性：中**
规模双源核实：比勒菲尔德大学项目页 "approximately 90,000 notes"，德国科学院联盟 "mehr als 90.000 handschriftlichen Notizen"。他 1981 年《Communicating with Slip Boxes》给出「系统向人提问」的人肉版前例：卡片盒可作 "partners of communication"，沟通的前提是双方能 "mutually surprise"；同时给出成本边界："needs a number of years in order to reach critical mass. Until then, it functions as a mere container"。
能提取的机制：机器反问的先例确实存在，但价值来自**维护动作本身即思考动作**。不能照搬：90,000 张是 45 年产物，「产出 600 种出版物」不能当因果证据（n=1）。

**② SuperMemo 渐进阅读（Piotr Wozniak，1987 起）｜类比有效性：高**
机制核实成立：导入 → 提取片段 → 转 cloze → 进队列，用**优先级队列**处理过载。关键分工线：items（问答）由算法排程、用户几乎不能干预（"you do not have much influence on the timing of repetitions"），topics 的间隔由人控制。这是唯一长期运行的「机器决定何时向你提问」先例。
效果证据必须分层：间隔 + 提取本身有强证据（Cepeda 2006 元分析：184 篇文章、317 个实验；Maye & Hurley 2026：13 项研究、21,415 人、SMD=0.78）；**专有算法的 95–98% 是目标口径**，作者自报第一年实测保持率 89.3%（同一官方页面），且「扩展间隔最优」的前提被 Karpicke & Roediger 2007 直接反驳。官方自承边界：一次性导入 1000 页，保持率降到 60–80%。

**③ Anki｜类比有效性：高（揭示瓶颈）**
调度层自动化已被验证可用（FSRS 于 23.10 集成，但 2026-09-11 官方手册仍要求手动启用，「已默认」的说法不成立）。关键发现是**调度自动化之后瓶颈必然转向内容生产**：Almaabreh 等 2026（n=318）原文 "Card creation was also identified as the most time-consuming aspect of use"，"Burnout was frequently reported"；Nour & Harris 2025：97.6% 用现成牌组、82.1% 不堪重负。
对我们最要紧的一条：**「人愿意持续做提示 / 判断动作」在规模上没有证据支持**。

**④ Andy Matuschak 的 mnemonic medium / Quantum Country｜类比有效性：高（分工可行性）、低（效果论证）**
原文分工：mnemonic medium 提供 "expert-authored prompts to remove the burden of prompt-writing"，调度器按成功与失败做指数伸缩。注意：网传的「提示由人写、调度由机器做」**在他原文里找不到该字面表述**，不得当直接引语。他本人的证据自评是 "small-but-promising"、"informal experiment"、"should be taken with a grain of salt"，四层证据中泛化性一层为 "We have no evidence of 4 yet"；成本是阅读时间 +35–50%。
能提取的机制：把人从写提示的负担里解放出来是有效设计，前提是有**专家级提示作者**；这正好解释我们为什么必须让 LLM 生成提示、人只做判断。

**⑤ 维基百科机器人维护 + 人类巡逻｜类比有效性：高（分工与精度预算）、中（直接迁移）**
官方分工表述（ORES FAQ）："Potentially damaging edits are flagged and brought to the attention of human patrollers who make the final decisions"。ClueBot NG 的阈值政策由人设定：误报率 0.1% 时捕获约 40% 破坏，0.25% 时约 55%；官方明示 "False positives ... are (essentially) inevitable"。失败模式（Halfaker 等 2013）："the algorithmic tools used to reject contributions are implicated as key causes of decreased newcomer retention"。
对我们的意义：**人定精度预算、机器换召回**是可直接借用的分工形状；但维基有 ground truth 与公开审计，个人学习产品两者皆无。

**⑥ Louvain / Leiden 社区发现 + 文献耦合（Kessler 1963 / Small 1973）｜类比有效性：高（该不该做）、低（语义正确性）**
「共享同一份来源」的学术前身是文献耦合：Kessler 1963, *American Documentation* 14(1):10–25；共被引为 Small 1973, *JASIS* 24(4):265–269。但**「共享来源比显式互链更可靠」这一比较命题没有任何实证检验**，只能作类比。
社区发现实现门槛低（networkx 3.6.1 同时含 louvain 与 leiden），但语义正确性买不到：Leiden 论文实测 Louvain "may yield arbitrarily badly connected communities"（最多 25% 社区坏连通、16% 不连通）；Fortunato & Hric 指出分辨率限制是模块度目标函数本身的问题，"there is no magic heuristic that can circumvent this issue"。**未检索到任何「社区发现用于个人笔记库」的已发表用户研究。**

**失败与反例**：Rewind.ai 被 Meta 收购后于 2025-12-19 关闭全部屏幕与音频捕获、用户须限期导出否则永久删除；Microsoft Recall 四次后撤后改为 opt-in（默认值与可撤销性决定信任成本）；反例是 Notion AI——「AI 功能采用率低」不成立，官方 2026-01 披露超过 50% 的 ARR 来自 AI-enabled 客户。

### 3.5 反复出现的机制

| 重复机制 | 出现在哪些案例 | 成立条件 | 失败边界 | 证据强度 |
|---|---|---|---|---|
| 维护与判断切开，切在「人可表达为参数」的位置 | SuperMemo、维基、Matuschak、卢曼 | 判断可参数化或为低频稀缺选择 | 涉及语义正确性时无法参数化 | 高 |
| 精度预算优先于召回（人定误报率，机器换召回） | 维基、SuperMemo、Recall | 错误可见、漏检有人兜底 | 学习场景漏检代价相反（漏掉一个缺口会被当成学会了） | 高 |
| 过载必须用队列 / 优先级处理 | SuperMemo、Anki、BASB | 存在可排序的优先级信号 | 优先级难判断时退化为随机丢弃 | 中高 |
| 自动生成的结构本身不产生价值 | 图谱视图、社区发现、文献耦合 | 结构被人消费才产生价值 | 把「自动生成」当「自动有价值」 | 中（阴性结果 + 算法证明） |
| 调度自动化后瓶颈必然转向内容生产 | Anki、Matuschak、SuperMemo、BASB | 调度已自动化 | 内容生产成本无人承担 → 退化为只读收藏夹 | 高 |
| 默认值与可撤销性决定信任成本 | Rewind、Recall、维基 | 用户可局部拒绝 | 不可局部验收 → 一次失败即全量返工 | 高 |
| 收益延迟 + 成本即时，需要早期可感知回报 | 卢曼、Matuschak、BASB、SuperMemo | 早期可见小规模收益 | 弃用发生在收益出现之前 | 中 |
| 自动化的元层仍需人工治理 | 维基、Recall、社区发现 | 有可问责操作者与回滚路径 | 无审计的自动维护累积不可逆错误 | 高 |

### 3.6 标准答案判断

**结论等级：条件性答案**（不是成熟共识——社区发现与个人知识库这一交叉领域没有同行评议的用户研究）。

> 当 `机器的维护只覆盖调度、筛选、索引与来源记账`，且 `人只需做低频、可参数化、可撤销的选择` 时，历史上反复有效的做法是 `机器换召回、人定精度预算，语义判断留给人`，因为 `一旦自动化伸手到「该建什么页、什么结构才对」，既没有 ground truth 也没有语义正确性的先例`。当 `人不再愿意持续做那个判断动作`（Anki 现实中 97.6% 的用户用现成牌组）或 `收益延迟而成本即时`（卢曼的卡片盒要数年才到 critical mass）时，这个答案容易失效。

**对「系统反过来向人提问」的单独判定**：这是**无同构先例的新命题**。十个案例里只有 SuperMemo 与 mnemonic medium 会向人提问，且都只问「你记得吗」，不问「你缺什么」；由**认知缺口 / 意外连接驱动**的提问没有任何已运行先例。含义有两面：这是真正可以占位的差异点；同时它没有可抄的设计参数，必须做成小步、可选、可跳过。

**禁止在路演稿里出现的说法**（完整 33 条见研究报告）：图谱视图的价值与使用率、个人 wiki「三个月死掉」、a16z 领投 Roam 两亿美元轮、「PKM 使用者六成认为建系统最耗时」、SuperMemo 98% 保持率、Matuschak 的字面分工引语、Anki「几千万用户」。

### 4.3 锦上添花新增（只加一件）

| 机制 | 形态 | 服务哪个进展 | 人做什么 | LLM 做什么 | 48h 可做 |
|---|---|---|---|---|---|
| 认知缺口账本（跨会话反向提问） | 费曼判定的漏点标签持久化；下次进入该课题时，先用旧漏点问 3 个问题再开始新内容 | 让「学过」变成「记住了并补上了」，产品第一次拥有跨会话记忆 | 回答 3 个问题，或点「跳过」 | 把漏点转成问题、按旧漏点和新内容排序、判断是否已补上 | 3–4h（state 已持久化，只差落盘漏点明细） |

设计理由：这一件同时用上了上面的三件平均件（意图层给方向、缺口给信号、动作收窄给交互），并且是 llm_wiki **没有做**的那一条（它的洞察停在一键 Deep Research，没有回问用户）。它不新增模块、不新增依赖，只改验收层的结算方式。

**必须同时满足的五条硬边界（全部有来源，见第 2、3 节）**：
1. **不假设学习者知道自己缺什么**（Loewenstein 1994）：缺口只能由机器发现、由人裁决；不要做「你自己说说哪里不会」的输入框。
2. **够得着**（Bjork & Bjork 2011；Kirschner 等 2006）：题目必须匹配先备知识，太难会从合意困难变成不合意困难；默认只问 1–3 个旧漏点，不贪多。
3. **可跳过、可终止、可关掉**（Horvitz 1999）：默认关闭或首次出现时给明确说明；误报会导致整体弃用（Parasuraman & Riley 1997 的 disuse）。
4. **不把通过率当学会了**（Roediger & Karpicke 2006；Soderstrom & Bjork 2015）：账本只记录「这次补上了哪个漏点」，不宣称掌握；效果要看延迟后是否还讲得出。
5. **动作收窄**：人只回答、建页、跳过三种，机器不新增动作类型（对应 llm_wiki 的 constrained 设计）。

## 6. 48 小时最小落地顺序

依赖关系：先有意图层，缺口才有方向；先有漏点落盘，才有账号可问；先有动作收窄，交互才可控。

| 序 | 动作 | 估时 | 依赖 | 完成信号 |
|---|---|---|---|---|
| 1 | 首页加意图层（课题一句话 + 3 个问题），并入 LLM 上下文 | 2–3h | 无 | 首页 30 秒读出灵魂；断网也显示 |
| 2 | 概念 / 案例卡挂 sources 字段（真实知乎链接） | 1–2h | 无 | 每条可点开、可核对 |
| 3 | 费曼漏点明细落盘（本地存储，键为课题 + 概念 + 漏点标签） | 2h | 无 | 关掉页面重开，漏点还在 |
| 4 | 下次进入先反向提问（旧漏点 3 问 + 跳过），答完再进新内容 | 3–4h | 3 | 第二次进入能问出第一次的漏点 |
| 5 | 待处理清单（建页 / 深挖 / 跳过三动作，不阻塞主流程） | 2–3h | 1,3 | 漏点与疑问在同一处处理 |

合计约 10–14 小时，可分给两人并行；1、2 与 3、4 互不依赖，可同时开工。

## 7. DDR 前可验证的 3 个动作

1. **30 秒复述测试**：找一位没参与的同学，只看首页意图层，让他复述这个产品为什么存在；说不出来就重写意图层。
2. **漏点记忆测试**：同一个人连做两次（第一次故意讲漏两个点），看第二次进入时是否被问到那两个点；问不出来说明账本没闭环。
3. **DDR 上只问两个问题**：①「人策划、机器维护」这条分工，团队认不认；②认知缺口账本是否进 48 小时范围。其余争论（要不要做图谱、要不要上向量库）按第 5 节直接引用不做清单结束。

## 9. 综合结论

**理论与历史共同支持什么**
1. 「机器发现缺口、向人提问」这条机制**在理论上成立**：觉察缺口是好奇心的前提，而人看不见自己的缺口，外部指出缺口正好补这个缺口；提问本身作为提取事件有强证据（g ≈ 0.499，222 项研究）。
2. 「人提供意图、机器提供维护与记账」这条分工**在历史上有条件成立**：凡是把维护切在「调度、筛选、索引、来源记账」上的系统（SuperMemo 的 items、维基的机器人、mnemonic medium 的调度）都长期跑住了；分工线一旦伸到「该建什么页、什么结构才对」，就没有 ground truth，也没有语义正确性的先例。
3. 「机器维护知识库」的先例**只覆盖调度与筛选**，没有任何一例覆盖「自动建页 / 自动重建结构」；社区发现实现门槛虽低（networkx 3.6.1 就带 louvain 与 leiden），但语义正确性买不到（Louvain 可能产生坏连通社区，最多 25%；分辨率限制是模块度目标函数自身的问题）。

**还不成立、因此必须降级表述的部分**
- 「系统检测缺口后自动提问能提升学习」**没有任何直接研究**；「机器生成问题带来学习收益」**没有元分析支持**。产品可以照做，对外只能宣称「提取练习 + 反馈」。
- 「人愿意持续做判断动作」在规模上被 Anki 的现实削弱（97.6% 用现成牌组、制卡最耗时、倦怠常见）。所以缺口账本要默认轻、可跳过，并且让**机器承担写提示的全部负担**（Matuschak 的 expert-authored prompts 是同一解法的高配版）。
- 「费曼」作为具名方法没有受控证据，只有成分层证据；命名建议改为「复述 + 漏点倒回」。

**边界**：以上结论的适用条件是「学习者已有材料与基本先备知识」（Kirschner 等 2006 的边界）；先备知识不足时，AI 介入必须带结构（这一点与 135 现有文档里的 Bastani 等 2025 结论一致）。所有「学会了」的宣称都必须放在延迟与迁移条件下检验，不能用当次通过率或自评顺畅度替代。
