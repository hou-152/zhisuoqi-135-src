### 1.3 伪概念检测：去掉「bad case」，还能不能说清？

逐个做。**能说清就直说这词是包装。**

| 原话 | 去掉「bad case」后的大白话 | 判断 |
|---|---|---|
| 「我们积累 bad case 来改进模型判定」 | 「我们把**判定和人类判断不一致的那些样本**存下来，用来调判定口径」 | ✅ **能说清** → 「bad case」是包装 |
| 「把 `every(Boolean)` 那个 bad case 修掉」 | 「那个**空数组返回 true 的断言**要修成会失败的」 | ✅ **能说清** → 包装 |
| 「这次串台是个 bad case」 | 「**另一个会话在错误的项目目录里干活，绕过了刚立的闸门**」 | ✅ **能说清** → 包装 |
| 「264 条判据全是 bad case」 | 「264 条判据**都是机械反面转述，照抄边界原文就能过**」 | ✅ **能说清** → 包装 |
| 「多攒 bad case 就好了」 | 「**多存一些坏例子就好了**」 | ❌ **说不清**——「好了」指什么？谁的什么变好了？改什么？这句话去掉「bad case」之后**什么都没剩下** |

**【已核实事实 → 判定】** 前四种用法都只是**包装**，去掉之后说得更清楚。
**第五句「多攒 bad case 就好了」是真出问题的地方**：它不是描述，是**一句没有谓词的祈使句**——
它掩盖的空白正好是「攒下来之后，**哪一步会发生什么**」。

所以：**这是概念混用，但混的方式不是「一个词四个意思」，而是「三种具体事件 + 一个没有内容的动词短语」。**
前三种（①②④）各自能对上一件真事；第四种（「多攒就好了」）**对不上任何机制**，
它是**用「积累」这个动作替代了「改进」这个结果**。

> 维特根斯坦那条在这里是真的：**一个词的意义是它的用法。**
> 「bad case」在本库的用法是四种互不相同的用法，所以它**没有**单一意义。
> 而「多攒 bad case 就好了」这句话**没有用法**——它不可操作，因此不可检验，因此什么也不承诺。
> 这就是为什么负责人会问「它到底有什么作用」：**这句话本身没有告诉他任何事。**

### 1.4 它到底是 Question 还是 Problem？

- **「bad case 怎么存、存哪、字段是什么」是 Question**——有标准答案，可以线性回答。
- **「积累 bad case 有什么作用」是 Problem**——它的答案不是一个句子，是**这套流程能不能产生一个可交付的版本**。
  本库至今**没有任何一条真人学习记录**（`README` 第 39 行：所有 `learnerIs` 一律是「合成学习者（脚本扮演）」；唯一一条真人记录是 2 个字符）。

它伪装成 Question 的方式是：**问「有什么作用」听起来像在问定义，其实是在问「我们做的这件事有没有指向结果」。**
而这个问题**不能用再多的 bad case 回答**——只能用一次带细节的真人使用回答。

### 1.5 一句话界定：积累的到底是什么资产

按能不能**自动跑、能不能失败、下一次会不会再发生**，把「积累物」分成四类：

| 候选资产 | 它是不是资产 | 判据（本库实测） |
|---|---|---|
| **测试用例** | ✅ 是 | `check-graph` 465 项、`test-graph` 281 项、`check-learning-materials` 581 项——**它们会在每次改动后自动跑，而且判过死**（如 `--selftest` 在 v2 坏样本上必须复现 228 条判死） |
| **判据**（criterion） | ⚠️ 有条件 | 六章 **18 条人工判据是资产**（负控实测：一条没被误杀）；批量 **264 条不是**（C 档 0/264，照抄 boundaries 就能过） |
| **语料**（corpus） | ⚠️ 只有一种算 | **「人会怎么错」这一层**才算。「材料里有什么」这一层不是——`units.json` 与 76 张卡片本来就有 |
| **闸门**（gate） | ✅ 是，但只在一种形态下 | **写成代码 + 带反证**的闸门是资产（伪造全绿仍进不去）；**写在文档里的话不是**（`6e79ce4` 只有 1 个文件、+122 行，纯 docs，被绕过了） |
| （第五类）**坏例子清单** | ❌ 不是资产 | 如果没有一条检查读它，它就只是日志 |

**收尾一句（这一节必须落成这一句）：**

> **我们其实在积累的是「下一次会自动跑、并且必须能失败的一次检查」，不是「坏例子的数量」。**

补一句同样重要：**这条界定也划出了它不能积累什么**——
它**不能**积累「人会怎么错」（那必须有人写，机器造不出来，264 条就是反证）；
**不能**积累「判定标准」（那是人给的约定，如「信息增量 ≥20 字」的报告自己就写明「是约定，不是理论值」）；
**不能**积累「真人行为」（样本量 1、2 个字符，是记录不是数据）。

### 1.6 奥派 / 维特根斯坦校准：该说不适用就说不适用

负责人要求别硬套。**逐条说清哪里适用、哪里不适用：**

| 框架 | 适用吗 | 说明 |
|---|---|---|
| **维特根斯坦：意义即使用** | ✅ **真适用，而且是主工具** | 1.3 已经用它得出结论：「bad case」在本库有四种用法，故无单一意义；「多攒就好了」无用法，故无意义。这不是修辞，是可操作的检验 |
| **维特根斯坦：反对语言对理智的蛊惑** | ✅ **适用** | 「积累」这个词让人以为**存下来就等于进步了**（就像「复盘」让人以为**说出来就等于改了**）。这就是蛊惑本身 |
| 奥派：**主观价值论** | ❌ **不适用** | 这是工程流程，没有交换、没有价格。不存在「这条判据值多少钱」的主观估值问题。**不硬套** |
| 奥派：**价格信号** | ⚠️ **只作类比，不作理论** | 唯一对得上的一点：**一个不能失败的检查，就像一条不能传递稀缺信息的价格**——它看起来在传递信息，其实什么也没传。我把这标成**类比**，不声称它证明了什么 |
| 奥派：**行动先于理论** | ✅ **适用** | 「多攒 bad case」是**用描述替代行动**：它描述一个动作，但不改变下一次的行为。检验方式只有一个：**下一次改动时，有没有一条新断言因此失败过？** |
| 奥派：**反理性建构主义（自发秩序 vs 可设计的秩序）** | ⚠️ **半适用，要说清** | 本库真实发生的事支持一半：**靠写在文档里的规则去约束多会话行为，失败了**（`6e79ce4` 被绕过）；**靠一个每次都真实运行的检查去约束，成功了**。但结论**不是**「规则该自发演化」——工程上正确的结论是「**规则必须绑定到一个能失败的执行体上**」。这是工程结论，不是奥派结论。**不假装它是奥派** |

## 第 2 件（standard-answer 主责）：这类机制历史上真起过什么作用

按第 1 件定下的边界（**「能失败的一次检查」＋「人会怎么错」这一层语料」**），做理论与历史同构。

### 2.1 命题审查

原命题（负责人转述的那句）：

> 「在这个过程中，我们去积累 bad case，其实有什么样的作用吗？」＋（他人说法）「多攒 bad case 就好了」

审查：**收窄**。
「积累」这个动作本身不构成机制；历史上反复有效的**不是积累**，而是**积累物被送进一个会真实运行的检查**。
另外原命题隐含一个绝对化（「多攒就好了」），反例轻易成立：**264 条判据数量上是 228 道的 1.16 倍，可用率 0。**

**修正后的标准：** 不是「攒了多少坏例子」，而是「**这些坏例子有没有变成一条下一次会自动跑、且在已知坏样本上必须失败的检查**」。

### 2.2 需要解释的核心机制（3 个研究问题）

1. 什么机制让「一次真实失败」变成「以后不会再犯的约束」？
2. 为什么有的领域靠这套机制真的把事故率降下来了，有的领域报告越攒越多、结果没变？
3. 什么条件下「收集人的错误」这件事本身会失败？

### 2.3 主理论

```
理论名称：证伪主义 / 反例驱动（falsificationism）
理论要解决的问题：一个断言凭什么算被检验过
核心机制：断言只有在一个可能让它失败的观察面前才有内容；不能被任何观察推翻的断言不传递信息
理论原义：Popper 主张科学陈述的可证伪性作为划界标准；「每次反驳都应被视为改进理论的契机」
原始出处：Karl Popper,《Logik der Forschung》(1934/1935)；英译《The Logic of Scientific Discovery》(1959)
核实状态：权威二手（本次未直接查原书页码；概念通行，但**页码未核实**，故不引页码）
```

| | |
|---|---|
| **能解释什么** | 为什么 `test-graph.mjs:92` 那条**恒真断言**等于没有断言（它不可能失败）；为什么 `decisions.every(Boolean)` 对空数组返回 `true` 会「白送解锁」；为什么 228 题的「九条硬门槛全过」不构成检验——**那九条是生成方自己写的，且从未在一个已知坏样本上失败过** |
| **解释不了什么** | 它**完全不解释**「为什么必须是人的错误」。机器自检也可以可证伪——本库 v3 就是（`--selftest` 在 v2 上必须复现 228 条判死）。**可证伪性管的是「检查能不能失败」，不管「检查覆盖了谁的错误」** |

**辅助理论 1（解释「为什么攒多了也会失效」）：**

```
理论名称：农药悖论（pesticide paradox）
核心机制：同一批测试用例反复运行，就不再发现新缺陷；增量只来自新的用例类型
原始出处：Boris Beizer,《Software Testing Techniques》(2nd ed., 1990)
核实状态：二手（本次只查到二手转述与从业者文章，**未取到原书页码**，故标二手；转引关系：Microsoft 归档博客 / PractiTest 等均转述 Beizer）
```

**辅助理论 2（解释「报告系统为什么常常无效」）：**

```
理论名称：单环学习 vs 双环学习（single-loop / double-loop learning）
核心机制：单环＝改流程与设置；双环＝改产生错误的隐性管理因素与心智模式
原始出处：Argyris & Schön,《Organizational Learning》(1978)
核实状态：本次通过 Stavropoulou 等 2015 用这两个概念做的系统评价间接使用（见 2.5 案例三）
```

**辅助理论 3（解释「为什么必须有外部方写检查」）：**

```
理论名称：坎贝尔定律 / 古德哈特定律
核心机制：当一个度量变成目标，它就不再是一个好的度量
理论原义（通俗版，**注意这是通俗版不是原始表述**）："When a measure becomes a target, it ceases to be a good measure." —— 这句话是 Strathern 1997 对 Goodhart 1975 的**概括**，常被误当成 Goodhart 原话
核实状态：**通俗版归属已核实为二手**；Goodhart 1975 原始表述我未直接查证 →【待核实】
```

**纠偏方向（用它建立边界）：** 见 2.5 案例五、六——**静态基准会饱和、会被污染**。这是「多攒」策略自身的天花板。

### 2.4 结构指纹

```markdown
现实角色：一个想在 48 小时内交付可被真人使用的学习产品的工程团队（多会话并行）
所处阶段：已交付可运行 MVP；机器侧证据充足，真人侧证据为零
必须实现的结果：让「课程能不能教」有一个答案
正在争夺的稀缺资源：**真人使用时间**（唯一真正稀缺的东西）
同时存在的任务：把 538 个语义单元继续装配成课程；修 P0；保持九条回归全绿
主要矛盾：**机器能自己判的那一半已经做完且很扎实；机器判不了的那一半（人会怎么错、人用不用）一份都没有**
反复出现的失败循环：生成 → 自检全过 → 独立复核判死 → 修生成器 → 再生成
第一部分确认的核心机制：检查必须能失败；而**能失败的检查目前只覆盖机器可算的那一半**
```

**结构命题：**
> 一个处于「已交付、缺真人证据」阶段的工程团队，依赖**机器可复算的证据链**，
> 因**「人会怎么错」这一层语料必须由人写**而无法用机器补足，
> 同时受到**「回归全绿＝可以说话」**这一压力机制的持续牵引。

#### 案例一（跨域重复 · 成功）：NASA 航空安全报告系统 ASRS（1976– ）

- **原始处境：** 1970 年代航空事故频发，但**飞行员不会主动上报自己的失误**——上报等于自证违规、可能被吊销执照。
- **真实约束：** 最危险的信息（人的失误）恰好是最不可能被自愿交出的信息。
- **当时可选方案：** ① 加强检查与处罚 ② 只统计事故（后果已发生，太晚）③ 建立一个非惩罚通道
- **实际决策：** 1976 年建立 ASRS，**NASA 作为第三方**收取与处理（不是 FAA 自己收）；**自愿、严格保密、去标识**；FAA 承诺不用于执法，并对**非故意**违规豁免处罚。
- **执行成本：** 需要制度承诺（豁免）、第三方中立（NASA）、专业分析人员（退休管制员/机务/飞行员），并要求分析人员**不得与 FAA 或航司有ongoing雇佣关系**（避免利益冲突）。
- **后续结果：** **累计超过一百万份报告，从未有过一次上报者身份被泄露**；产出 CALLBACK 月刊、Directline、研究报告、可检索数据库；FAA 依此「采取纠正措施以修补国家空域系统的缺陷」。
- **证据：** ASRS 官网 [Program Briefing](https://asrs.arc.nasa.gov/overview/immunity.html)、[Confidentiality and Incentives to Report](https://asrs.arc.nasa.gov/overview/confidentiality.html)、[Caveats](https://asrs.arc.nasa.gov/overview/caveats.html)
- **证据状态：** **已核实事实**（本轮直接抓取 NASA 官网三个页面）
- **与当前问题相同之处：** 想要的都是**「人会怎么错」这一层语料**；而这层语料不会自己出现，必须**设计一个让人愿意交出来的通道**
- **与当前问题不同之处：** ASRS 有**制度性豁免权**可交换；本仓库没有任何东西可以给「写误解的人」——**这是最关键的差异，见 2.7**
- **类比有效性：** **高**（同为「收集人类错误以改进系统」）
- **能提取的机制：** ① **保密 + 不惩罚是拿到人类错误的前置条件**，不是附加福利 ② 收集只是第一步，**必须有「分析 → 输出 → 责任方采取纠正措施」的完整链**（官网原文把「effectiveness depends on the free, unrestricted flow of information」和「FAA will take corrective action」并列写出）③ **事故与犯罪明确排除在外**（豁免有边界：非故意、10 天内、无前科）
- **不能照搬的部分：** ASRS 是**行业级、有法定豁免权**的机构；本仓库是**一个项目内部**，没有可交换的豁免权

#### 案例二（跨域重复 · 成功）：外科 M&M 会议（1910s– ）

- **原始处境：** 20 世纪初外科医生**不知道自己的结果有多差**——没有结果记录、没有同行比对，失败被归为「病人太弱」。
- **真实约束：** 主刀医生有极强的动机不公开自己的失败。
- **当时可选方案：** ① 不记录 ② 只记录成功 ③ 强制公开自己的死亡与并发症
- **实际决策：** Ernest Codman 提出 **End Result System**（追踪每个病人的最终结果）；M&M（Morbidity and Mortality）会议制度化：**定期、同行在场、逐案复盘死亡与并发症**。
- **执行成本：** 医生的面子与法律暴露；需要**同行评议**而不是行政追责，才能让医生继续报。
- **后续结果：** 1930 年代起成为外科住院医培训标准，延续至今；近年文献把它作为**质量改进**工具重新评价，并讨论「从 Codman 到当代实践」的演变。
- **证据：** JAMA Surgery, "Morbidity, Mortality, and the Moral Development of a Surgeon"；The American Surgeon, "Evolution of the Morbidity and Mortality Conference in Surgery: From Codman to Contemporary Practice"
- **证据状态：** **权威二手**（两篇独立同行评议文献；**本轮未取到一手档案**）
- **与当前问题相同之处：** 都是**个案级复盘 → 变成群体的约束**；都依赖「不追责」才能拿到真话
- **与当前问题不同之处：** M&M 靠**同行在场**（一个社会机制）而非靠代码闸门；本仓库没有「同行」
- **类比有效性：** **中高**
- **能提取的机制：** **复盘的价值在「同一个人群反复看到彼此的具体失败」，不在「存了多少条」**——即：**载体是会议（每次真的开），不是档案**
- **不能照搬的部分：** 本仓库没有同行群体；单人会话里的「复盘」缺少那个社会压力

#### 案例三（失败 · 关键边界）：医疗事件上报系统（IRS）与 NHS NPSA 的撤销

- **原始处境：** 1990s–2000s 各国大规模建事件上报系统（IRS），投入巨大，假定「报得越多 → 学得越多 → 越安全」。
- **真实约束：** 上报是**一线人员的时间成本**，而改动的责任在管理层；两者不重合。
- **当时可选方案：** ① 建中央上报系统 ② 由临床团队自建自管
- **实际决策：** 多数国家选了 ①（中央化）。
- **执行成本：** 巨大且持续；英国国家患者安全局（NPSA）在 2012 年被撤销，职能并入 NHS Commissioning Board 等机构。
- **后续结果（这是本次研究里最重要的反证）：** Stavropoulou、Doherty、Tosey 2015 在 *Milbank Quarterly* 的系统评价（43 项研究）结论：
  > **「我们没有发现强证据表明 IRS 比其他方法更有效。」** 只发现**一些单环学习**的证据（临床设置/流程改变），
  > **关于结果改善的证据很少**，关于**产生错误的隐性管理因素**的改动**几乎没有**；关于双环学习（文化/心智模式改变）的证据**不充分**。
  > 结论建议：IRS 要更有效，需要**「什么算一起事件」的标准明确**、**由临床团队自己拥有和主导而不是中央部门**、**嵌入更广的安全项目之中**。
- **证据：** Stavropoulou C, Doherty C, Tosey P. *How Effective Are Incident-Reporting Systems for Improving Patient Safety? A Systematic Literature Review.* Milbank Q. 2015;93(4). PMID **26626987**（本轮经 Europe PMC 取到完整摘要原文）
- **证据状态：** **已核实事实**（原始论文摘要，本轮直接取得）
- **与当前问题相同之处：** **高度同构**——「攒报告」被当成「改系统」；数量增长被当成安全改善
- **与当前问题不同之处：** IRS 至少还有报告量的真实增长；本仓库连报告量都没有（真人使用 1 条、2 字符）
- **类比有效性：** **高**
- **能提取的机制（三条恰好命中本仓库）：**
  1. **「什么算一起事件」必须明确** ←→ 本仓库**从未定义过什么算 bad case**（第 1.1 节的实测结论）
  2. **由一线拥有而不是中央部门** ←→ 本仓库的闸门是**中央**写在文档里的，一线会话（错目录的那个）直接绕过
  3. **必须嵌在更广的改进项目里** ←→ 孤立的 bad case 库不产生任何东西
- **不能照搬的部分：** 医疗的「结果改善」有硬指标（死亡率、并发症率）；本仓库的「学习有效」目前**没有可比指标**，也不该声称有

#### 案例四（跨域重复 · 成功但强边界）：掌握学习与 K12 错题本（Bloom 1968 / 1984）

- **原始处境：** 传统班级授课里，学生学习速度差异极大，跟不上的被判定为「能力不足」。
- **真实约束：** 教师时间有限；一对一矫正的成本无法规模化。
- **当时可选方案：** ① 按固定进度教完 ② 按能力分班 ③ **按掌握程度推进 + 对未掌握者做矫正**
- **实际决策：** Bloom 1968 提出 **Learning for Mastery**：单元化、形成性测验、**未达标者获得矫正后再测**，而不是继续往前。
- **执行成本：** 时间（Bloom 1984 的核心发现之一就是：掌握学习比传统课堂**更花时间**——时间投入从约 65% 升到约 75%，一对一辅导到 90%+）。
- **后续结果：** Bloom 1984 报告：**一对一辅导 + 掌握学习的学生，平均表现比传统班级学生高约 2 个标准差**（「2 Sigma Problem」）；并明确指出**问题在于找到能规模化达到这个效果的方法**，而不是证明个别辅导有效。
- **证据：** Bloom, B. S. (1984). *The 2 Sigma Problem: The Search for Methods of Group Instruction as Effective as One-to-One Tutoring.* Educational Researcher, 13(6), 4–16（本轮未取到原刊页面；经多篇独立二手确认，含 escholarship 与高校学位论文）
- **证据状态：** **权威二手**（多源一致；**原刊页码未核实**）
- **与当前问题相同之处：** 本仓库的 `dbs-learning` 梯度与「费曼没过就不解锁下一章」直接对应**反馈—矫正循环**；`docs/标准答案-关系图谱与课程编排-20260914.md` 已引过这条
- **与当前问题不同之处：** Bloom 的对照组是**真人学生 + 真人教师矫正**；本仓库的「学生」迄今是脚本，矫正来自本地模型

#### 案例五（最近成功 + 反例）：软件回归测试与农药悖论

- **原始处境：** 修好的 bug 会重新出现（regression）。
- **真实约束：** 手工复测不可持续；测试越多维护成本越高。
- **当时可选方案：** ① 每次改动全量手测 ② 只测新功能 ③ **把每个已修 bug 冻结成一条自动化用例**
- **实际决策：** ③ 成为行业标准做法：**每个 bug 修复附带一条会失败的回归用例**。
- **执行成本：** 用例库持续增长带来的维护与运行成本。
- **后续结果（正）：** 本仓库自己就是这条机制的**成功实例**——228 道题从 `0/228` 到 `228/228`，靠的不是「多攒题」，而是**把上一轮的坏产物当负控**：`node scripts/review-gen-decisions.mjs --selftest` 必须**在 v2 产物上复现 228 / 76 / 16 / 逐字照抄 228 / 依据 0 不符**，跑不过就不算有牙。**这是本仓库唯一被验证有效的改进机制。**
- **后续结果（反）：** **农药悖论**——同一批用例反复跑，就不再发现新缺陷；增量只来自**新的用例类型**。
- **证据：** Beizer,《Software Testing Techniques》(1990)（**二手**）；本仓库的 `--selftest` 正控/负控设计（**已核实事实**，见 `复核-228道决策题-v3-20260914.md` §2 与 `复核-264条判据-20260914.md` §2）
- **证据状态：** 机制＝**已核实事实**（本仓库一手）；理论归属＝**二手/待核实**
- **与当前问题相同之处：** 完全同构。第 1 件界定的「能失败的一次检查」就是这条
- **与当前问题不同之处：** 回归测试冻结的是**代码缺陷**——机器能自己复现；本仓库要冻结的一部分是**人的错法**——机器不能自己复现
- **类比有效性：** **高**
- **能提取的机制：** ① **坏样本是资产，前提是它被用作「必须失败」的负控** ② **同类用例攒再多也不产生新增量**——所以「多攒」的「多」是错的
- **不能照搬的部分：** 不能把「机器能复现的缺陷」和「人才会犯的错」当成同一类来冻结

#### 案例六（最近成功 + 反例）：AI 评测集构建史与 ANLI 的「人机对抗」

- **原始处境：** GLUE（2018）→ SuperGLUE（2019）→ 很快被刷满（饱和）；静态基准无法继续区分模型。
- **真实约束：** 由**基准作者**（专家）写的难例，覆盖不到模型真实的失败模式。
- **当时可选方案：** ① 继续扩大专家标注规模 ② 用模型自动生成对抗样本 ③ **让非专家的人，看着模型当前的表现，专门写能骗过它的例子**
- **实际决策：** ③ —— **ANLI**（Adversarial NLI, 2019/2020）：**迭代式、人机在环（human-and-model-in-the-loop）** 的收集流程。
- **执行成本：** 需要多轮迭代（每轮针对当前最强模型重写），成本高于一次性标注。
- **后续结果：** 论文摘要（本轮直接取得）：
  > 「我们引入了新的大规模 NLI 基准数据集，通过**迭代式、对抗性的人机在环流程**收集……**非专家的标注者能够成功地找到当前 SOTA 模型的弱点**……这种数据收集方法可以应用在**永不结束的学习场景**中，成为一个**移动靶**，而不是一个会很快饱和的静态基准。」
- **证据：** Nie et al., *Adversarial NLI: A New Benchmark for Natural Language Understanding*, arXiv:1910.14599（本轮直接抓取 arXiv 摘要页）
- **证据状态：** **已核实事实**（原文摘要）
- **与当前问题相同之处：** **这是全部六个案例里结构最同构的一个。** 本仓库要的正是「人写机器过不了的例子」；ANLI 证明了**这件事必须由人做，而且人要看着机器的当前表现来写**——这正是 264 条判据缺的那一层
- **与当前问题不同之处：** ANLI 有**大量非专家标注者**（众包）；本仓库只有**一个负责人**，且他极度没耐心
- **类比有效性：** **高**
- **能提取的机制：** ① **人的错误不可由机器合成**——这是被 ANLI 的整个方法论背书的 ② **它必须迭代**（针对当前模型写，模型变强后要重写）→ **静态的坏例库会饱和** ③ 反向风险：**基准一旦公开就会被训练进模型（污染）**，即「攒下来」的资产会**过期**
- **不能照搬的部分：** 众包规模；以及本仓库没有「模型变强」这个迭代驱动力（六章用固定判据）

### 2.8 标准答案

> **当 `{条件}` 成立时，历史上反复有效的做法是 `{机制}`，因为 `{因果解释}`；当 `{边界}` 出现时，这个答案容易失效。**

**条件：** 存在一个**已知的真实失败样本**，且存在**一个不从中受益的第三方**愿意把它写成一条**会在下次自动运行、且在该样本上确实失败**的检查。

**机制：** 把每一个真实失败**冻结成一条可复跑的负控**，并让**写入者与被检查者分离**；同时用**不惩罚通道**持续获取「人会怎么错」这一层语料，用**显式的准入定义**决定什么算一次失败。

**因果解释：** 改变下一次行为的从来不是「存下来」这个动作，而是「**下一次同样的错会被自动拦下**」这个事实。所以资产单位是**会失败的检查**，不是坏例子的条数；而这类检查里有一半（人的错法）**机器造不出来**，因为它不在机器的分布内，只能由人看着机器的当前表现写。

**失效边界（四条，全部有本仓库或文献对应）：**
1. **检查由被检查方自己写** → 必然 100% 通过（228 题自述「九条硬门槛全过」；264 条 264/264 自洽）
2. **「什么算一次失败」没被显式定义** → 攒下来的东西不能聚合（IRS 系统评价的第一条建议；本库从未定义 bad case）
3. **来源单一** → 「多攒」只是同一偏差的更多副本（农药悖论；76 个单元「三题一个正解」）
4. **没有不惩罚通道** → 「人会怎么错」这一层永远收不到（ASRS 的豁免是前置条件；本库真人语料 1 条）

### 2.9 结论等级

> # **条件性答案**

不是成熟共识：失败案例（IRS）与边界（饱和/污染）证明这条机制**在条件不成立时会整体失效**，而不是效果变小。
不是「尚无统一答案」：**六个案例、跨四个领域（航空、医疗、教育、软件+AI 评测），M1–M4 重复出现，方向一致。**

| **F2 264 条判据（0/264）** | ❌ **治不了根** | **这是最关键的一条。** 264 条缺的是**「人会怎么错」这一层语料**。bad case 库**只能收集**这一层，**不能生成**它——ANLI 的整个方法论（案例六）就是「必须由人看着模型的当前表现写」。本库的收集通道现状：**真人语料 1 条 / 2 个字符**，直到第 0 件才发现第 2 条（而且那条恰好就是一条**可用的**人类误解语料） |
| **F4 并发覆盖** | ❌ **治不了** | 这不是「例子不够」的问题，是**写权限与提交粒度**的问题。案例三的系统评价把它归到「由谁拥有和主导」——需要的是机制（分支/锁/逐文件 add 的工具化），不是更多案例 |
| **F6 真人使用 1 条** | ❌ **治不了** | 「课程能不能教」要的是 **N≥1 且带细节的真人走查**。再多 bad case 也不能替代一次真实使用——这是 `README` §7.1「管理闭环 ≠ 产品闭环」那句话的同一个意思 |

**一句话：能治「机器能自己判的那一半」（F1 已证、F3/F5 部分已证）；治不了「必须由人提供的那一半」（F2、F4、F6）。**

### 3.3 第三问：「多攒 bad case 就好了」——哪一半是错的？

把这句话拆成两个词：**「多」** 和 **「攒」**。**两个都是错的那一半，对的那一半不在这个句子里。**

| 半个 | 判定 | 证据 |
|---|---|---|
| **「攒」**（存下来） | ❌ **错** | 存下来不改变任何下一次行为。**IRS 系统评价**：43 项研究，**没有强证据表明上报系统比其他方法有效**，结果改善的证据很少。本库自己的反证：264 条判据**全部**存下来了、全部自洽，可用 **0** |
| **「多」**（数量） | ❌ **错** | **数量不是瓶颈，「谁写的」才是。** 264 条 > 228 道（1.16 倍），可用 0；六章 **18 条**人工判据，可用 18、负控零误杀。另外农药悖论（案例五）与基准饱和（案例六）说明同类样本攒多了**边际信息递减** |
| **（对的那一半，不在这句里）** | ✅ | **把一次真实失败冻结成一条「会失败且已经失败过」的负控，并让写它与被检查它的人分开。** 本库唯一的成功实例就是它（228 v2→v3） |

**还要指出一句话里更隐蔽的错：这句话绕开了「谁来写」。**
它把问题描述成**存量问题**（不够多），而真实问题是**来源问题**（没有人写）。
「多攒」这个说法的实际效果是**让一件需要人做的事，听起来像一件机器可以自己做的事**——
264 条判据不是「攒得不够多」，是**机器在没有那层语料的情况下自己造了 264 条**。

**本库的第一个反例已经出现了，就在第 0 件那条反馈里：**
他写的「Agent 可以调用工具、MCP 和 skill……需要根据这个上下文做下一步动作」，
被模型判 `agent-F1/F2/F3` 三条缺口全中，补讲直指「调用工具发生在模型之外的运行时里」。
**这正是 264 条判据造不出来的那种句子**——它是人的错法，不是边界的反面。
**它是一个样本，不是一堆样本。**

### 3.4 三问之外的第四条（照实记，不属于任何一问）

**证据的「载体」本身也在漂。** 第 0.6 节实测到的那件事值得单独记：
`zss135.learn.v1` 里那条**章末通过记录**（09-14 02:20:49），
在新快照里已经变成 `"feynman":null, "verdict":""`——**`said` 与 `at` 还在，通过状态没了**；
同时该章从 3 个决策位变成 6 个。

这跟 `ad61d29` 变成悬空对象是**同一类失效**：
**唯一一条真人证据，因为结构变了而不再被系统认作证据。**
**【本次推断】** 成因是页面在新题量下重写了记录（保留原话、清掉通过状态），属既有「改复述即清状态」逻辑的副作用；**我没有改任何代码去验证这一点**。

## 综合结论

**理论证据与历史证据共同支持什么：**
- 六个跨四领域案例（航空 / 医疗 / 教育 / 软件与 AI 评测）都指向同一条机制（M1–M4 重复出现）：
  **个案只有在被冻结成「会失败且已经失败过」的检查时才产生资产；而「人会怎么错」那一层必须由人写。**
- 本仓库已经**自己证明过这条机制有效**（228 题 v2 `0/228` → v3 `228/228`，靠的是把坏产物当负控）。

**仍然存在的边界：**
- 这条机制**不覆盖** F2 的根、F4、F6——那三件要的是**人写的语料**、**协作机制**、**一次真实使用**，不是更多案例。
- 「标准答案」是**条件性答案**，不是成熟共识：IRS 的系统评价证明条件不成立时它会**整体失效**，不是效果变小。
- **不得**把案例四（Bloom 2 sigma）读成本仓库的效果证据。本库的「学生」迄今是脚本；唯一真人样本量 1。

**对负责人那句话的最终回答：**
> 「积累 bad case 有什么作用？」——
> **作用不在积累，在于它有没有变成一条下一次会自动跑、并且在已知坏样本上必须失败过的检查。**
> 变成检查的，作用很大（本库已证）；没变成检查的，作用为零（264 条）。
> 而「多攒就好了」是错的，因为它把**一个必须有人写的来源问题**，说成了**一个机器可以自己解决的存量问题**。

**如果只做一件事：** 把第 0 件那条真人反馈**落盘成证据**。
它是全库第一条**可用的**人类误解语料，而它现在**在页面上已经不显示为通过了**。

## 请负责人拍板的两件事（各带我的推荐）

**问题 1：264 条判据这条路，下一步先写 76 条还是先写 264 条？**

> **推荐：先写 76 条（一个单元一条），并把判据结构从「一条边界一条」改成「一个单元一条」再重排。**
> 理由（全部来自复核报告自己的实测）：① 一个单元只有 1 条 `target_problem`，判据却有 3/4/5 条（共 264），**剩 188 条无来源可换**；② 一单元内复用同一条还会被检测器 ⑤ 判成重复；③ 76 条是 264 条的 **1/3.5**，且与「章末门」天然对齐。
> 代价与风险：76 条之后判据数会少于现在的 264 条，**图里的 Criterion 节点数和 `check-*` 的项数都会变**，需要照实改口径（不是放宽）。
> 不做会怎样：继续停在 `verdict=unusable`，76 个单元的形成性费曼段持续不开放——**这不算错，只是慢**。

**问题 2：第 0 件那条真人反馈，现在就落盘成只读证据文件吗？**

> **推荐：是。落成 `evidence/` 下的只读证据（逐字），并按「样本量 1」标注它能支持什么、不能支持什么；不写「学习有效」，不写「课程能教」。**
> 理由：① 它是**全库第一条可用的人类误解语料**，正是 264 条缺的那一层；② 现在**只有浏览器 localStorage 一份**，而页面已经把它重写成 `feynman:null`（通过状态丢了）；③ 它同时是 F6 那条「真人使用 1 条 2 字符」的更新——**真人使用仍是 1 次，但这一次带细节了**。
> 代价与风险：它会成为一份「看起来像效果证据」的文件，**必须写清它只证明「有一次真人使用，且暴露了一条真实误解」**。
> 不做会怎样：这份数据只存在于一个会被 Chrome compaction 处理的 LevelDB 里，**下一位接手的人不会知道它存在**。
