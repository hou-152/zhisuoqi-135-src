## 三、定位叙事（2026-09-11 晚新增，对外可讲）

**先例**：AI内参 260911 期收录 nashsu/llm_wiki——把 Karpathy 的一段 prompt 模式（gist）做成了桌面 app，README 逐条标注「原作有什么 / 我们改了什么 / 我们加了什么」。

**我们做的是同构动作，且血统更强**：把 **2 个自有 skill（dbs-learning、dbs-standard-answer）+ 1 个概念（费曼）** 工程化成 web。

| | llm_wiki | 知所栖 135 |
|---|---|---|
| 抽象模式 | Karpathy 公开 gist（别人的） | dbs-learning + dbs-standard-answer（自有 skill）+ 费曼（概念，验收层） |
| 形态 | 桌面 app（Tauri） | web（单文件 HTML + serve-135 workflow） |
| 方法论去向 | 骨架照抄 + 工程扩展（purpose.md / 图谱 / 评审队列） | 方法论写死编排层：1=三层梯度实时切层，3=同构比较+条件答案表，费曼=复述→漏点→倒回 |
| 底层哲学 | 知识 compiled once and kept current，反 RAG 每次从零推导 | 检索增强判定 workflow，反 agent 全自主；模型只做单轮调用 |

**可讲的点**：「skill → 产品」这条路径已有先例（llm_wiki），我们更进一层——他们的模式是别人的，我们的方法论是自己的。他们 README 的「继承/改造/新增」对照表形式可抄进路演稿：逐条对应 dbs skill 原文与产品实现。

## 七、今晚新增（2026-09-11 夜，llm_wiki 融合调研）

**做了什么**：把 AI内参 260911 的 nashsu/llm_wiki 拆成可迁移件，做了三路一手核查（仓库 README + Karpathy gist + 源码；10 组理论的 Crossref 书目；10 个同构案例的原文），产出五份材料（见上表加粗行）。

**给你的三句话版本**：
1. 「平均」只在**人机分工**这一层：**人提供意图与判断，机器提供记账、发现与提问**；它的产品形态（桌面端、向量库、图谱工程）服务的是另一笔账，搬过来 48 小时做不完。
2. 灵魂定稿：**把「你意识不到自己缺什么」变成产品替你做的事**——缺口由机器发现、由人裁决。这句有理论依据（Loewenstein 1994：觉察缺口是好奇心的前提，而人普遍看不见自己的缺口）。
3. 锦上添花只加一件：**认知缺口账本**（费曼漏点落盘，下次进入先问 3 个旧漏点，可跳过），3–4 小时可做。

**路演稿要改的三处**：
- 「让知识库反过来向你提问」在 llm_wiki 里**没有实现**（README 无此条，是 AI内参 的解读）——这句话可以留着讲我们自己要做的事，但不能说成「对标已经做到」。
- 「机器提问提升学习」**没有元分析支持**，统一说「提取练习 + 反馈」；「提问本身有效」有强证据（Yang 2021，g = 0.499）。
- 「费曼技巧」无一手表述也无受控证据，统一说「复述 + 漏点倒回」。

**2 Sigma 的写法**（你上次说的「R Sigma」= Bloom 的 2 Sigma，已核实）：可以说「我们在解 Bloom 1984 提出的 2 Sigma 问题——群体场景下接近一对一辅导；真正起作用的是反馈-纠正与掌握式过关，我们把它做成了费曼验收与漏点倒回」。**不能说**「我们实现了 2 sigma」：Bloom 的两个标准差来自六项 3 周短期研究，VanLehn 2011 的元分析把人类辅导下修到 d ≈ 0.79、智能辅导 0.76。详见 `research/2Sigma-理论锚定.md`。

**新发现的缺口（原以为只有两件）**：除 LLM key 与 10 份复述样本外，还缺一个决策——**认知缺口账本进不进 48 小时范围**。建议进，它是唯一能让产品跨会话有记忆的一件。
