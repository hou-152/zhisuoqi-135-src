# Issue · 在知所栖 135 现有网站中接入路径视图

- 执行人：DeepSeek
- 类型：产品视图 + 前端实现
- 优先级：P1
- 范围：前置内容／学习路径选择
- 日期：2026-09-13
- 状态：待执行

## 1️⃣ Why｜为什么做

知所栖当前有 936 个概念、604 条依赖和 3,406 条关系。知识体系可以回答「哪些概念有关」，但用户仍不知道：

- 为了一个目标先学哪个；
- 当前概念为什么现在出现；
- 哪些前置必须学、哪些可以跳过；
- 卡住后应该回到哪里；
- 如何从知识图谱进入一条有限路径。

本 Issue 只解决一个问题：

> 在现有知识体系网站中，让用户看见并走通一条由人策划、机器辅助裁剪的前置学习路径。

知识图谱继续负责展示「知识怎么连」，路径视图负责告诉用户「现在怎么走」。

## 2️⃣ What｜具体交付什么

### A. 新增一个「路径」视图

现有主区：

```text
图谱｜关系｜星球
```

新增为：

```text
路径｜图谱｜关系｜星球
```

「路径」放第一位，默认作为学习观察方式；图谱、关系、星球继续保留。

### B. 主题下增加路径入口

左栏现有 21 个主题和搜索保持不变。点击主题后，在主题内容顶部增加路径入口。

第一版只接一条真实路线，不为 21 个主题批量编造路线：

```text
理解 AI 如何持续行动
AI Agent → Tool → Agent Loop → State Management → Agent Harness → Verification Loop
```

入口展示：

- 路径标题；
- 目标问题；
- 概念数量；
- 「开始路径」。

### C. 主区高亮当前路径

进入路径后：

- 显示目标和路径标题；
- 显示 5—7 个以内的主步骤；
- 当前节点高亮；
- 已完成节点有状态；
- 下一步主推荐突出；
- 最多显示 2 个分支；
- 其他概念降噪，但仍可通过图谱探索。

主区呈现「导师编排 + 路径地图」：导师逻辑负责推荐，图谱负责提供空间位置。

### D. 概念卡增加路径上下文

复用现有概念卡，顶部增加：

```text
当前路径第 3 步 / 共 6 步
当前概念：Agent Loop
为什么现在学：不理解循环，就无法理解 Agent 如何持续行动。
前置：Tool ✓
下一步：State Management
卡住时回退：Tool
```

增加「前置理由」展开区，不重写已有定义、来源、关系和深看内容。

### E. 分支和回退

分支只在目标不同的时候出现，并写明理由：

```text
任务为什么能持续推进 → State Management
AI 怎样安全调用外部能力 → Permission Boundary
```

回退只回到最近的最小 `hard` 前置，不展示全部祖先节点。

### F. 路线数据与概念图谱分离

可以增加单独的 route fixture／配置，不把路线顺序写回 `topics.json` 或 `dependencies.json`。

最小结构：

```json
{
  "routeId": "agent-continuous-action-v1",
  "title": "理解 AI 如何持续行动",
  "entryQuestion": "为什么 AI 能连续做事，而不只回答一次？",
  "target": "能解释 Agent 从目标到行动再到验证的基本循环",
  "steps": [
    {"conceptId": "真实 ID 1", "order": 1, "type": "main"},
    {"conceptId": "真实 ID 2", "order": 2, "type": "main"}
  ],
  "branches": [],
  "skipRules": [],
  "fallbackRules": []
}
```

真实概念 ID、依赖方向和字段必须从当前数据读取，不得猜测。

## 3️⃣ How｜怎么做

### 执行顺序

1. 阅读 `AGENTS.md`、`SOURCE_OF_TRUTH.md` 和本 Issue；
2. 阅读 `docs/路径视图-PLAN-20260913.md` 与 `docs/路径视图-HANDOFF-DeepSeek-20260913.md`；
3. 检查当前壳的真实入口、主区 tab、概念卡和真实概念 ID；
4. 先做路径视图静态结构；
5. 接入一条真实 6 步路线；
6. 接入当前节点高亮、路径上下文、前置理由、分支和回退；
7. 回归主题筛选、搜索、图谱、关系、星球和概念来源；
8. 跑项目对应验收脚本；
9. 交付改动清单、验收输出、未做项和已知风险。

### 数据关系规则

| 关系 | 页面行为 |
|---|---|
| `hard` | 默认进入主路径 |
| `soft` | 推荐但可跳过 |
| `support` | 作为来源、案例或解释材料 |
| `related` | 放相关概念，不进入主路径 |

如果当前数据没有统一的 `support`／`related` 字段，先基于现有字段映射展示，不要修改全量关系数据结构。

### 不得采用的实现方式

- 不让 LLM 每次从 936 个概念自由重排路线；
- 不把所有关系边都变成页面按钮；
- 不用中心性、热度或关系数量直接决定教学顺序；
- 不批量为 21 个主题生成未经策展的路线；
- 不把 `related-to` 自动升级为前置。

### 文件边界

优先修改：

- `scripts/shell.template.html`；
- 对应的壳构建／路线配置文件；
- 必要的验收脚本。

不要直接手改由脚本生成的公网产物；不要改概念地图源数据；不要改 `.private/`。

若发现当前工作区有并发改动，先报告冲突文件和影响，不覆盖其他会话的改动。

## 4️⃣ How good｜做到什么算完成

### 页面验收

- [ ] 用户能从现有主题进入路径入口；
- [ ] 主区出现并默认可进入「路径」模式；
- [ ] 一条真实 6 步路径可以走通；
- [ ] 当前节点在图谱中明显高亮；
- [ ] 右侧概念卡显示路径位置、为什么现在学、前置、下一步和回退；
- [ ] 最多显示 2 个分支；
- [ ] 卡住时能回退到一个明确的最小前置；
- [ ] 可以返回图谱、关系和星球；
- [ ] 主题筛选、搜索、概念来源和既有概念卡功能不回归。

### 产品验收

陌生用户不看额外说明，能够回答：

1. 我现在在学什么？
2. 为什么现在学这个？
3. 下一步去哪里？
4. 如果我不懂，应该回到哪里？
5. 如果我想自由探索，怎么回到全图？

### 技术验收

至少运行：

```sh
node scripts/test-daobi.mjs
node scripts/shot-shell.mjs
node scripts/check-public.mjs
```

如果改动影响桌面版，再运行：

```sh
node scripts/test-app.mjs
```

验收输出必须贴回 Issue 或交接件。失败时区分产品失败、验收环境失败和已有并发改动冲突，不得为了让断言变绿而删除产品行为。
