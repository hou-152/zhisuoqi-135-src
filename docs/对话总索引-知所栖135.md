## 7. 从对话里提炼的行为规则（可直接用）

以下是从会话里反复出现、且当前 `AGENTS.md` 未写全的规则。

### 7.1 用户协作规则（来自 ZCode `adhd-output-style.md`，项目内无副本）

1. **收权闸门**：方案／交接类任务，用户会显式收权——「你先研究，然后我们讨论；我作为决策者确定的方案，OK 之后你再执行」。此时给完研究结论＋方案就停，**不抢跑执行**。「可逆的事直接做」只适用于执行细节。
2. **怒气峰值处置**：用户骂「叫叫叫」「答非所问」＝解释已经超量。立即转入执行、话降到接近零、把决策兜到自己身上；不道歉表演、不顶撞、不复述他的原话。
3. **公开信息先搜再问**：定义类信息若可能公开可得（开源项目、官方文档），先穷尽检索再问；向用户要公开能查到的信息会激怒他。注意语音转写变体（PIA≈PI、pwngluin≈Penguin）。

### 7.2 调研纪律

4. **没接真 API 之前不许说「可以发了」**：留 `endpoint: null` 空壳不算接。
5. **方法论要「体现」不是「提及」**：说模块参考了某 skill，交互本身就必须是该方法的落地，并标注出处与承诺句。
6. **成本／效果类断言必须给最小对比实验**（样本、分组、指标、提前定死的决策规则）；没有数据就明说「这是推理、待验证」。
7. **任何降级/回退/兜底路径必须报警**，不能静默降级（`Data.Items` vs `data.items` 那次差点用解析 bug 替团队做了架构决策）。
