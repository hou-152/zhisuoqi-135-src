## 3. 目标形态：网页版 + APP（两个都做，但有先后）

所有者 09-12 指令：「**我让 Codex 去做一个 APP 吧，如果可以的话；不行的话，就去做一个网站。**」

**先修正一处：APP 不是「网站做不了」的退路。两者是同一份代码的两层壳，而且 48h 内必须先有网页版。** 理由：

1. **赛制必交件是「公网可访问的线上 Demo 链接」**——APP 是下载物，不是链接，评委点不开。
2. **未签名的 `.dmg` / `.exe` 会被 Gatekeeper / SmartScreen 拦**，现场演示风险高。
3. **现有的东西本身就是网页**：`prototype/知所栖-135-基础框架.html` 是单文件 HTML，`scripts/serve-135.mjs` 是 95 行 Node 服务。套 Electron 壳是**小时级**工作量，不是天级。

**所以：**

| 阶段 | 做什么 | 估时 |
|---|---|---|
| **P0 必做** | 网页版上公网 + 服务端持有 key 的代理 | 中 |
| **P1 必做** | 产品说明计划书 | 中（素材已全） |
| **P2 该做** | 修检错器（决策 D3 + D5） | 3–4h |
| **P3 可选** | Electron 壳（同一份代码） | 2h + 打包 0.5h |

### 3.1 打包选型：Electron，不用 Tauri

| | Electron | Tauri |
|---|---|---|
| 当前稳定版 | **v44.3.0**（2026-09-08） | 2.11.5 |
| 前置要求 | **只要 Node.js** | **必须有 Rust** |
| 本机条件 | ✅ Node v24.15.0 | ❌ **本机无 Rust / cargo** |
| 许可 | MIT | Apache-2.0 |
| 体积 | 官方未给打包体积（**未核实**）；官方发布包 `darwin-arm64` 123.8 MB | 官方只给「minimal app can be less than 600KB」 |

官方原文（已核实，全文见 `docs/本地优先与打包运行时-事实核查.md`）：

- Tauri：「**Tauri is built with Rust and requires it for development.**」
- Electron：「you need to install the Node.js runtime…」＋「**Electron does not use your system's Node.js installation to run its code. Instead, it comes bundled with its own Node.js runtime.**」（→ **终端用户不需要装 Node**）

**结论：48h 内选 Electron。** 另有两条旁证：① 本机没有 Rust，装工具链是纯新增风险；② 所有者日常在用的 DeepSeek Harness 桌面壳本身就是 Electron。

## 7. 事实底座与未核实项

**运行时与打包**（全部已验证；逐条引文与 URL 见 `docs/本地优先与打包运行时-事实核查.md`）：

- Tauri：「Tauri is built with Rust and requires it for development.」**本机无 Rust / cargo**。
- Electron **v44.3.0**（2026-09-08，MIT）；「Electron does not use your system's Node.js installation to run its code. Instead, it comes bundled with its own Node.js runtime.」支持策略：最新 3 个稳定版。
- File System Access API：`showOpenFilePicker` / `showSaveFilePicker` / `showDirectoryPicker` = **Chrome 86 ／ Edge（mirror）／ Firefox false ／ Safari false**。
- OPFS：MDN 原文 "is private to the origin of the page and **not visible to the user**"；"**Clearing storage data for the site deletes the OPFS**"。
- PWA 的 A2HS：**Firefox 最新 = `n`，Safari = `a`（部分）**；Service Workers 四家皆 `y`（usage 96.07%）。
- local-first 七条理想（Kleppmann 等，Onward! 2019，DOI `10.1145/3359591.3359737`），其中第 3 条原文倾向「**locally installed executable** rather than a tab in a web browser」——这是「APP 作为终局」的正规依据，**但不是 48h 内必须交付它的理由**。

**未核实（不得当事实用）**：

- Electron 官方「打包后应用体积」数字；Tauri 分平台 bundle 体积。
- `file://` 双击打开时 `localStorage` 能否写入（playwright 禁 `file:` 协议；5 秒自检法记在 `决策/知乎黑客松/04_待解/待验证假设.md`）。
- Karpathy 推文一手链接（只有 gist 可核实）。

**本机网络环境事实（会拖慢你，先知道能省时间）**：
本会话 `web_fetch` 对**所有**外部域名返回 `resolves to a non-public IP address`（连 `example.com`、`doi.org`、`web.archive.org` 都一样）。可用的绕行：`bash` + `curl`、`r.jina.ai` 文本代理、Crossref / OpenAlex / Europe PMC 的 API。`web_search` 正常（但只回标题 + URL，不回正文）。

## 13. 补充：GitHub Pages 能不能当那个「公网 Demo 链接」

**结论：不能单独用，但可以当前端那一半。**

- **GitHub Pages 只托管静态文件，跑不了 Node。** `serve-135.mjs` 的三个接口它一个都跑不了。
- **但**原型本身已经有一条不依赖服务端的路：**「LLM 设置」里直连，key 仅存本浏览器**。把这条路设成默认，Pages 就能跑通单个学习者的全流程。
- **代价**：① 知乎**实时检索跑不了**（CLI 不在浏览器里）→ 必须用烘焙快照，并**在界面上明说**；② 评委得自己填 key，或者你提供一个公共 key 的代理（那又需要服务端）。

**三条候选：**

| 方案 | 能跑什么 | 代价 |
|---|---|---|
| **A. GitHub Pages + 烘焙快照 + 评委自填 key** | 静态页全流程（离线规则引擎） | 无实时检索、无真 LLM（除非评委填 key）；**零成本、HTTPS、最快上线** |
| **B. Cloudflare Workers / Pages Functions**（官方点名） | 静态页 + 三个接口全部 | 要写 Workers 版的 `serve-135.mjs`；知乎检索要改成直连 HTTP API |
| **C. Sealos / 任意容器**（官方点名） | 原样跑 `serve-135.mjs`，改动最小 | 要处理知乎 CLI 与凭证（**`.private/` 绝不能上传**）；有成本与运维 |

**建议：先落 A 拿一个能交的链接保底，再上 B。** C 只在 B 走不通时考虑。

### 16.6 六条硬规则（每条都来自一次实测或事故）

### 17.2 `dbs-jtbd` 的结论：两类用户，以及三处错位

`/dbs-jtbd` 交付的不是一张表，而是一个**判定**——**这个项目一直在把两个人当成一个人。这是 §14 视图与 §16 分流的设计前提。**
