## 二、一类一条真实样例（同一条主线：Agent 行动空间）

- **问题**：「什么信息应在什么时候、以什么形式进入？」（`QST-CAT-context-delivery`，分类问题，下挂 15 个概念）
- **概念**：Agent 行动空间 = 当前运行环境中可选择的动作集合，以及这些动作向模型呈现的名称、参数、反馈和组合方式。（`CON-agent-action-space`）
- **观点**：上下文工程不是 agent 时代的新发明，它至少有二十多年历史，把它当成 2023 年才出现的技巧会切断它与几十年 HCI 积累的联系。（`OPI-CTX-01-01`）
- **案例**：假设文件 Agent 只有一个「操作文件」工具，却能通过参数读取、覆盖、移动或删除 —— 工具数量没变，参数范围扩大后风险和选择难度都变了。（`CAS-agent-action-space`）
- **方案**：① 枚举当前环境允许的动作、参数范围、前置条件和返回反馈；② 用任务样本检查模型能否区分近似动作；③ 收窄无用选项、拆分危险能力或增加确认，再比较成功率和误调用率。（`SOL-agent-action-space`）

## 五、四个坑（照实说，别在队友面前翻车）

1. **76 个案例单元全是假设场景**（`case_type: 假设场景`，源卡 `scenario.type: hypothetical`）。它是「先自己选」的情境，**不是真实复盘**，不能当案例引用。
2. **去重候选 16,025 条 = 失控**，阈值没调。这层索引现在不可用。
3. **观点单元的标题被截断**（约 50 字，以「…」结尾，文件名里也是）。要读它的完整主张，看 frontmatter 的 `core_claim`，别只看标题。
4. **全程 0 次 LLM 调用**：概念／方案／案例／检验问题四类机械映射自图鉴站的**已审计**产物，观点与文章定位问题确定性解析自源文小标题。所以它不是「模型从文稿里抽出来的」，而是「复用 ＋ 照抄」。
