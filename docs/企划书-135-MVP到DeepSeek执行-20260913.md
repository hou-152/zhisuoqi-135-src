# 知所栖 135：从一个 MVP 扩展成学习路线

> 版本：2026-09-13
>
> 目的：先用一个概念跑通「读懂 → 判断 → 复述验收」，再把已经验证的材料规则、状态门和判定协议交给 DeepSeek Harness 扩展。本文只把已跑通的做法写成可执行方法，不把规划中的整条路线写成现状。

## 1. 先交付什么

本轮 MVP 只有一个概念：`CON-context-rot`（上下文腐烂）。它使用：

```text
QST-context-rot       章节问题
CON-context-rot       核心概念
OPI-CTX-03-03         判断依据
CAS-context-rot       主案例（假设场景）
SOL-context-rot       行动说明
```

入口文件是 `prototype/mvp-decision-context-rot.html`。页面当前只验证这一章，不显示“下一章已解锁”，也不把假设场景写成真实复盘。

用户路径固定为：

```text
一段 context 阅读（原文 context → 直觉 → 机制 → 边界）
→ 第 1 道决策题
→ 第 2 道决策题
→ 第 3 道决策题
→ 费曼复述
→ 通过 / 未通过 / 待人工复核
```

决策题采用一题一判。每题有 3 个选项，恰好 1 个正确；答错停留在当前题并给出依据，选对后才可进入下一题。三题全对后才出现费曼。

## 2. 五类语义单元怎么装配

五类单元是材料来源，不是五步教学流程：

| 单元 | 在章节中的职责 | MVP 落点 |
| --- | --- | --- |
| QST | 定义本章要回答的问题 | `QST-context-rot` |
| CON | 规定概念定义、边界和可复述要点 | `CON-context-rot` |
| OPI | 为正确判断提供可追溯依据 | `OPI-CTX-03-03` |
| CAS | 提供一个决策情境；可以有多个候选 | `CAS-context-rot` |
| SOL | 解释选对后应采取的动作 | `SOL-context-rot` |

材料层保留一对多关系。装配记录必须明确 `primaryCaseId`：

```json
{
  "conceptId": "CON-...",
  "caseIds": ["CAS-...", "CAS-..."],
  "primaryCaseId": "CAS-...",
  "opinionIds": ["OPI-..."],
  "solutionIds": ["SOL-..."],
  "status": "ready"
}
```

本 MVP 的规则是：一个章节一个核心概念；三张决策卡各自指向一个主案例；正确选项必须能回到 OPI 或 SOL；CAS 标成“假设场景”时，页面必须原样显示该标记。找不到可靠主案例就标记“待装配”，停止生成该章的决策题。相近案例不能因为标题相似而强行套用。

五类单元不是一一对应的原因很具体：一篇材料可以有多个概念、多个观点、多个案例和多个方案；教学章节需要先选一个核心概念，再从候选材料中指定一个主案例，其他单元作为依据和行动说明挂在材料层，不改写概念地图。

## 3. 阅读和费曼的边界

阅读只展示当前概念的 context，不默认展开整篇文章。MVP 的 context 取自 `CON-context-rot` 的“费曼一下／边界”，并保留语义单元 ID；判断依据取 `OPI-CTX-03-03`，行动说明取 `SOL-context-rot`。如果来源缺失，显示缺口，不能由模型补成事实。

费曼判定只把下面这段固定材料交给本地 `/api/llm`：

```text
上下文腐烂要在固定模型、任务、关键证据和评分方法的条件下分档增加无关输入，观察可靠性变化；上下文窗口的容量不等于长上下文的利用可靠性。
```

要求模型只返回：

```json
{"covered":["变量","证据","边界"],"missing":[],"next":"一句下一步"}
```

页面只在 JSON 结构完整、`covered` 覆盖“变量／证据／边界”且 `missing` 为空时显示“费曼通过”。格式错误、请求失败、公网静态版和缺少来源都进入“待人工复核”；有漏点则显示“费曼未通过”。任何异常都不能变成通过。

## 5. 扩展路线时 DeepSeek 必须遵守的顺序

1. 先读 `AGENTS.md`、`SOURCE_OF_TRUTH.md`、五类语义单元文档、MVP 方法论、`evidence/paths-260913/routes.json` 和当前脚本模板。
2. 先建立材料配对索引，核对 ID、类型、`relationships`、`source_documents` 和状态；不改 `knowledge/概念地图-260913/` 的源数据。
3. 先复制一个已跑通的章节，替换真实的 QST、CON、CAS、OPI、SOL；人工指定 `primaryCaseId`，然后才生成 3 道题。
4. 每章先通过数据体检，再接页面；找不到可靠案例就保持“待装配”，不生成题、不显示“开始学习”。
5. 只在当前章节三题通过后进入费曼；费曼的“未验收”不能伪造为完成，也不能解锁下一章。
6. 先完成 Agent Loop 六章的材料和状态，再考虑 21 个主题的路线目录。路线顺序放在独立路线配置中，顺序来自人工策展时标 `curator: human`。
7. LLM 只能辅助检索、解释、选项改写和费曼缺口整理；运行时不能自由规划整条路线。核心流程在没有 LLM 时仍能用预先生成的材料和机械兜底运行。

## 6. 这轮明确不做

- 不接知乎 API，不把知乎检索当作费曼依据。
- 不做技术实验台；`SOL` 的动作路径留给后续真正的实验模块。
- 不批量补齐 21 条完整路线，不把候选材料冒充已确认材料。
- 不修改 `topics.json`、`dependencies.json`，不把人工教学顺序写回概念地图。
- 不发布公网版，不把本地凭证写进产物。

DeepSeek 的逐文件边界、命令和交付回执见同目录的 `交接-DeepSeek-Harness-135-MVP扩展-20260913.md`。
