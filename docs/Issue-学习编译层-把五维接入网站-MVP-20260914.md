# [P0] 学习编译层 MVP：把已有五维资产接入网站，先跑通一篇

## What：要交付什么

以现有 `agent-skills-api` 五维资产为唯一试点，完成一条可复现路径：

```text
内参文章 → 3 个概念 → 1 段分层阅读 → 3 道决策 → 5 个实验动作 → 费曼收尾
```

页面要能展示 `QST / CON / OPI / CAS / SOL` 的来源关系，但不把五类语义误排成五步。五维资产只作为章节材料来源：概念、阅读、决策、实验、费曼各自有明确出口。

## Why：为什么做

当前 Agent Loop 六章路线、正文流和来源链已经跑通；但严格五维拆解仍有 10 份，页面只暴露概念和费曼，`reading / decisions / experiments` 没有完整出口。需要先验证“学习编译层”在一个真实单元上的闭环，再决定全量扩展。

## Who / Where：边界

- 执行者：DeepSeek Harness。
- 决策者：产品负责人；先回报核对结果，收到明确 `OK` 后实施。
- 输入：现有仓库与 10 份严格五维 JSON。
- 不改：概念地图源数据、路线顺序、`.private/`、公网、Git 远端。
- 不做：知乎 API、运行时自由规划路线、58/76/918 的批量生成。

## Data contract

生成或传递的文章单元至少包含：

```json
{
  "slug": "...",
  "concepts": [],
  "reading": {},
  "decisions": [],
  "experiments": [],
  "feynman": {"demo": "", "rubric": []},
  "contentStatus": "generated-unreviewed"
}
```

每项保留来源 ID、原文定位和适用条件。决策题必须有 3 个选项且恰好 1 个正确答案；正确答案必须能回指 `OPI` 或 `SOL`。实验必须包含“做什么、观察什么、得出什么”。缺来源时显示缺口，不补写事实。LLM 产物不得自动变成 `owner-reviewed`。

## Page contract

1. 内参文章页新增五维入口，优先使用折叠区或分段卡，避免把概念图再次塞进学习页。
2. 读者先看当前文章的 3 个概念和 1 段分层阅读，再进入 3 道决策题。
3. 决策通过后显示 5 个实验动作；实验记录“做／观察／结论”。
4. 费曼收尾独立于阅读中的形成性费曼反馈。形成性反馈可以指出漏点并补讲，但不能直接解锁；收尾费曼才参与章节验收。
5. `/api/llm` 不可用时显示 `pending/manual`，不能伪造通过。

## 验收

- 一个试点单元五维内容全部可见，原文和来源 ID 保真。
- 10 份资产均通过结构体检；缺材料的单元不显示为 `ready`。
- 形成性费曼和收尾费曼状态分离；漏点能回指当前单元。
- 不新增知乎请求，不修改概念图源数据，不发布公网。
- 运行与改动匹配的现有测试，并新增一个针对五维页面出口的确定性测试。
- 提供桌面和窄屏截图各 1 张，截图必须是实际页面状态。
