## context
> Every skill you write is a permanent upgrade to your system. It never degrades. It never forgets. It runs at 3 AM while you sleep. And when the next model drops, every skill instantly gets better — the judgment in the latent steps improves while the deterministic steps stay perfectly reliable.
>
> That's how you get Yegge's 100x. Not a smarter model. Fat skills, thin harness, and the discipline to codify everything.
>
> The system compounds. Build it once. It runs forever.
作者给 OpenClaw 的原始指令：
> 你不许做一次性工作。如果我让你做一件**会再发生的事**，你必须：第一次手动在 3–10 个 item 上做完，给我看 output。我点头，就把它写成 skill file。如果该自动跑，就上 cron。**判定标准：如果同一件事我要让你做第二次，你就失败了。**
## 费曼一下
Garry Tan 提出的一条「为什么 skill-based 架构会复利」的机制。
**核心主张：**每写一个 skill，都是对系统的**永久升级**。
- **不退化**：skill 写好了就是写好了；
- **不遗忘**：文档躺在那里，下次调用还是原样；
- **半夜照跑**：cron 上去就会自动跑；
- **随模型升级自动变好**：下一代模型上线，latent 那层的判断自动变好，deterministic 那层照样可靠。
**为什么能复利：**这本质上是 thin harness, fat skills 架构的直接推论。只要你把判断写在 skill 里（latent 可增长）、把计算写在 deterministic 里（永远可靠），那么模型每次变强，都会免费衡乘你所有 skill 的能力。
**实践启示：**Garry Tan 给 OpenClaw 的那条原话 —— 「同一件事我要让你做第二次，你就失败了」——不是 prompt trick，是**复利架构的纪律**。
这也是 Steve Yegge 说的 100x 生产力的真正来源：**不是更聪明的模型，而是 fat skills + thin harness + 把一切 codify 的纪律**。
> The system compounds. Build it once. It runs forever.
