## context
> 它放在项目根目录，Claude Code 每次启动都会先读它，相当于你给新来的同事写的项目交接文档，区别是它每次都会从头认真读一遍而且严格执行。
写好的三件事：
- **短**：150 行以内，太长挤压对话空间
- **语气直接、命令式**：「所有注释用中文」比「团队偏好中文注释」有效得多
- **每条都能判断**：「函数超过 50 行必须拆分」而不是「代码质量要高」
四条最值钱的规则：先问清楚再动手、简单优先、只动该动的、做完要验证。
模板四块：项目背景 / 工作规范 / 禁止项 / **压缩时保留**——长会话被压缩时，决策的「理由」是第一个被丢的，写进去就不会前后矛盾。
## 费曼一下
每个项目根目录的「出厂规则」。它代替了你嘴上反复交代的背景：技术栈、人名、命名规则、禁止做的事。AI 每次开工先读一遍，所以这是项目里成本最低、回报最高的写作。
和 Memory 的区别：[CLAUDE.md](http://CLAUDE.md) 是项目级（这个仓库里的规则），Memory 是用户级（跨项目的个人偏好），两者互补。
