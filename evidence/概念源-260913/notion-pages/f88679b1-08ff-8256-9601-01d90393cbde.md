## context
> 每一次 MCP 或 CLI 工具调用，都要求 AI 智能体带上一个 `rationale` 参数，解释它为什么要发起这个请求。我们看不到聊天内容，但这个理由可以重建意图。
## 费曼一下
- 在隐私不允许 SaaS 厂商看用户与 Agent 的聊天记录的前提下，**让 Agent 自己写一句"我为什么这么调"**，是最便宜的意图采集方式。
- 这些理由聚合起来就是"用户意图日志"，作用：
	- 发现下一个该构建的功能（如 Ramp 反复看到"生成事故报告" → 上线 `build-incident-report`）。
	- 识别失败模式（一类 rationale 集中卡在某种场景）。
	- 替代过去由 UI 点击事件提供的产品信号。
- 对开发者友好的副作用：rationale 也能在调试 Agent 行为时充当低成本的可解释性。
## 与本文其他概念的关系
- 是**反馈循环**的核心机制之一，与"反馈工具""上下文种子"并列三驾马车。
- 解决的是**可观测性**问题：工具调用量看得到，但调用背后的意图看不到，rationale 就是把"为什么"补回来。
- 是 A2A 时代的产品决策原料——过去靠埋点，现在靠 rationale。
