## context
> Every step in your system is one or the other, and confusing them is the most common mistake in agent design.
>
> **Latent space** is where intelligence lives. The model reads, interprets, decides. Judgment. Synthesis. Pattern recognition.
>
> **Deterministic** is where trust lives. Same input, same output. Every time. SQL queries. Compiled code. Arithmetic.
直观例子：LLM 给 8 人排晚餐座位没问题；让它排 800 人就一定幻觉一张「看着合理但完全错」的座位图——组合优化是 deterministic 问题，不该被硬塞进 latent space。
## 费曼一下
agent 系统里每一步都必须落在其中一边。
- **Latent space（智能住的地方）**：读、解释、决策；判断、综合、识别模式。凡是需要语义、上下文、矛盾共存的判断，都该放在这里。例：判断一个创始人的 GitHub commit 与他在申请中说的东西到底差多远。
- **Deterministic（信任住的地方）**：同样输入、同样输出，每次。SQL、编译、算术、组合优化。凡是需要可重复、可审计、不能幻觉的工作，都该放在这里。例：给 6,000 个创始人分桌、算 NPS 得分、查 GitHub stats。
**为什么这件事重要：**把工作放错边，是 agent 设计里**最常见也最致命的错误**。烂系统总把组合优化填进 LLM（幻觉 800 人座位表）或者把判断问题扭成 SQL（查不出“says vs. actually building” 的 gap）。好系统**对这条线冷酷**。
实践启示：写 skill 时逐步问自己「这一步是 latent 还是 deterministic？」——这是 skill 设计的第一原则。
