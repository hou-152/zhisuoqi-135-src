## context
> Skill 本质就是一个文件夹，放在 .claude/skills/ 目录下，里面有个 [SKILL.md](http://SKILL.md) 写清楚什么时候用、要做什么。Claude Code 启动时只读 frontmatter，也就是描述触发条件的约 100 个字，真正调用时才加载完整内容，所以你装几十个 Skill 启动也不会变慢。
三种最常用类型：
- **工作流型**：整理周会、固定步骤打包
- **检查清单型**：上线前/发版前过一遍
- **领域专家型**：线上问题排查 SOP，把判断框架沉淀进去
两个写 Skill 的坑：
- description 要写**触发条件**，不要写功能介绍（这样 Claude Code 才知道什么时候调起它）
- 一个 Skill 只做一件事
Waza（`npx skills add tw93/Waza -g`）就是 8 个 Skill 的合集，对应一个好工程师该有的 8 个习惯：think、design、check、hunt、write、learn、read、health。
## 费曼一下
把「重复动作 + 判断框架」打包成可触发的小程序。description 决定它能不能被恰到好处地调起来；内容决定它做出来好不好。
它在 AI Coding 三层骨架里扮演「复用」层：[CLAUDE.md](http://CLAUDE.md) 解决一次性的项目背景，精确需求解决单次任务，Skill 解决「每次都要做的事」。
非技术人写 Skill 的优势：你最懂自己每天重复的判断和流程。把它们沉淀成 Skill，下次一句触发词就能跑——这本身就是一种 software for one。

## context
> A skill file is a reusable markdown document that teaches the model *how* to do something. Not what to do — the user supplies that. The skill supplies the process.
>
> Here's the key insight most people miss: **a skill file works like a method call.** It takes parameters. You invoke it with different arguments. The same procedure produces radically different capabilities depending on what you pass in.
例子：`/investigate` 七步流程，参数 `TARGET / QUESTION / DATASET`——指向安全科学家 + 210 万邮件，就是医学研究分析师；指向空壳公司 + FEC 申报，就是取证调查员。**同一个 skill、同一组步骤、同一份 markdown，invocation 决定世界。**
## 费曼一下
Garry Tan 把 skill 的本质提炼成一句更准的话：**a skill file works like a method call**。它接收参数，传不同参数能做出完全不同的能力。
这意味着两件事：
- skill 不是 prompt，是**软件设计**。markdown 是这套架构的编程语言，人类判断是它的 runtime。markdown 比死板的源代码更适合封装能力，因为它用模型自己思考的语言描述「过程、判断、上下文」。
- skill 是系统的**永久升级**。每写一个 skill，都给系统加了一层不退化、不遗忘、半夜照跑的能力；下一代模型一上线，所有 skill 自动变好——latent 那层升级，deterministic 那层照样可靠。判定标准：「同一件事我要让你做第二次，你就失败了」。
