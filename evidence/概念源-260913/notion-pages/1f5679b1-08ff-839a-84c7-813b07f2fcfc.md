## context
> 用户 → 用户的 AI 智能体 → 软件自己的 AI 智能体 → 数据库……两个大语言模型（LLM）一起协作，朝着同一个结果推进。
## 费曼一下
- 交互模式三段演化：
	- 旧：用户 → 界面 → 数据库（界面就是产品）。
	- 中：用户 → 用户 Agent → 数据库（Agent 直连，界面消失）。
	- 新：**用户 → 用户 Agent → 软件 Agent → 数据库**（双 Agent 协作）。
- "软件自家 Agent"承担的是过去由界面承担的"把关"职责：业务逻辑、规则校验、上下文补全、归类决策。
- 产品设计的对象因此不再是"一个孤立 Agent"，而是"一对协作者"——服务的还是同一个用户，只是中间多了两个 LLM。
## 与本文其他概念的关系
- 是**Headless 架构**的运行时形态：能力暴露出来后，最终被两个 Agent 一起咀嚼。
- 三原则正是 A2A 形态的设计指南：
	- **教会 Agent 成功** = 软件 Agent 给用户 Agent 准备说明书；
	- **反馈循环** = 软件 Agent 收集用户 Agent 的 rationale 与卡点；
	- **上下文缺口** = 双方 Agent 协商"谁手里有对方需要的信息"。
