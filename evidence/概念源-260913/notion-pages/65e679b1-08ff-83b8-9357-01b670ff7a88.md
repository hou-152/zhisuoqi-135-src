## context
> Diarization is the step that makes AI useful for real knowledge work. The model reads everything about a subject and writes a structured profile — a single page of judgment distilled from dozens or hundreds of documents.
>
> No SQL query produces this. No RAG pipeline produces this. The model has to actually read, hold contradictions in mind, notice what changed and when, and synthesize structured intelligence. It's the difference between a database lookup and an analyst's brief.

## 费曼一下
Diarization 是让 AI 真正能做知识工作的关键动作：
让模型读完一个对象的全部材料（申请、GitHub commit、顾问 transcript、社交信号），写出**一页结构化的 profile**——把几十上百份文档蒸馏成判断。
它不是什么：
- 不是 SQL lookup（查询出不了「说的」与「在做的」之间的 gap）；
- 不是 RAG（检索 + 拼接，拿不出跨文档的结构化判断）；
- 是「分析师 brief」——人类分析师读完资料后会交付的那种东西。
**为什么重要：**Diarization 是 knowledge agent 内部最核心的 latent 步骤。能抓到「says vs. actually building」这种只有把所有材料同时读完才看得出的 gap——这种洞察 embedding similarity 看不出，keyword 找不到。
**模板性使用：**Garry Tan 提出的两条可迁移 loop 都以 diarize 为枢纪：
- 输入 loop：retrieve → read → **diarize** → count → synthesize
- 改进 loop：survey → investigate → **diarize** → rewrite the skill
凡是需要「对象级 × 深读× 结构化判断」的任务，都可以把 diarization 內嵌进去。
