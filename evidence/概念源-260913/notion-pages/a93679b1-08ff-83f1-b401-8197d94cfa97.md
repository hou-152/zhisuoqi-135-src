## context
> 你应该思考：调用你家智能体的人，需要知道什么才能成功？然后主动把这些信息交给它。不要让它自己摸索。

## 费曼一下
- 旧世界：规范写进 API 文档，让人类开发者读完再写转换层。
- 新世界：**规范直接塞进工具描述**，让 Agent 在动手前就被强制"先读再写"。
- 最佳实践（Notion MCP）：在工具说明里把"先 fetch enhanced-markdown-spec"作为前置动作；这样不论是哪个 Agent 调用，都被迫先对齐格式规范。
- 反例（Slack MCP）：没把自家格式规范交给 Agent，结果用户花在改格式上的时间比手写还多——Agent 用错的成本由用户承担。
## 与本文其他概念的关系
- 是"为 Agent 设计产品"三原则的**事前**环节：在 Agent 动手前把规范、约束、格式喂进去。
- 与**反馈循环**互补：教会成功是事前供给，反馈循环是事中收集。
- 与**上下文缺口**配合：教会成功降低自家 Agent 的能力盲区，让对方 Agent 也少踩坑。
