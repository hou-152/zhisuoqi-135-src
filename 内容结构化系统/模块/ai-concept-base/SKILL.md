# ai-concept-base：AI 概念基本盘（五语义）

一个**自带数据**的 skill：538 个语义单元 ＋ 两条策展线，拿走整个目录就能用，不依赖任何外部路径。

## 数据在哪

| 文件 | 是什么 | 什么时候读 |
|---|---|---|
| `data/index.json` | 538 条轻量索引（id / 类型 / 标题 / 主题 / 关键词 / 摘要）—— 约 245 KB | **先读这个**做检索，别一上来读全文 |
| `data/units.json` | 538 个单元全文（含 frontmatter 关键字段、关系、正文）—— 约 1.2 MB | 命中索引后，只取需要的那几条 |
| `data/lines.json` | 两条策展线：Context Engineering 34 概念 / Harness Engineering 42 概念（含入口概念与分组） | 要做「一条线走完」的教学或选题时 |
| `data/manifest.json` | 数据规模与三个来源 | 需要交代数据从哪来时 |

## 怎么用

```sh
# 检索（默认查索引，输出 id / 类型 / 标题 / 摘要）
node scripts/query.mjs --q "上下文腐烂"
node scripts/query.mjs --type 方案单元 --theme "AI 如何持续行动" --limit 10
node scripts/query.mjs --q "harness" --json

# 装配一份「问题→概念→观点→案例→方案」草稿（只挑真实单元，不新增内容）
node scripts/assemble.mjs --qst QST-HAR-03
node scripts/assemble.mjs --q "上下文工程的本质" --out /tmp/draft.md
```

## 用之前必须知道的三件事

1. **这不是原始来源。** 单元的 `source_documents` 指向三个来源：飞书《Context Engineering 26+2》《Harness Engineering 28+2》，以及「Context × Harness 图鉴」的 76 张已审计概念卡。**对外引用要回到源文或图鉴站**，不要引这个库当一手证据。
2. **案例 76 条全部是假设场景**（字段 `case_type: 假设场景`），不是真实复盘。当决策题用可以，当事实用不行。
3. **`status` 只到「待核对」**：概念类来自上游已审计产物（`已核对（源：图鉴站已审计产物）`），观点与文章定位问题来自源文小标题的确定性解析（`待核对`）。**没有人工逐条核对过**，引用前抽查。

## 五类单元怎么对上产品

- **问题（141）** → 入口：一个问题开一条线（58 条文章定位 ＋ 76 条概念检验问题 ＋ 7 条分类问题）
- **概念（76）** → 3 概念：定义 ＋ 费曼 ＋ 边界 ＋ 迁移问题
- **观点（169）** → 费曼验收：讲完能不能复述出这一条
- **案例（76）** → 决策场：一条假设场景 ＋ 一段真实来源依据
- **方案（76）** → 实验台：每条 `action_steps` 都可改写成一次可观察的实验

## 边界

- 只读数据，不改上游；上游（图鉴站概念卡 / 两份飞书文档）更新后，重跑导出脚本即可刷新。
- 不联网、不调用模型：本模块的全部查询与装配都是本地确定性的。
